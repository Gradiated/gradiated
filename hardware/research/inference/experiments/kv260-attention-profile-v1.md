## Candidate decision

With the current cache ready at every request and returning each word on schedule, each key or value term uses one request, one response and one multiply-accumulate clock. Start by testing that model. A single outstanding request permits overlap of the next term’s request with the current accumulation. Without crossing key-dot-product or value-output boundaries the change predicts `62L − 32` fewer clocks at occupied length `L`. For the three archived natural requests this predicts 316,130, 564,840 and 1,252,230 fewer complete-request clocks. These are conditional schedule predictions. The working accumulation order, address/tag checks and cache port geometry must stay fixed.

The softmax exponential uses generic scalar arithmetic, except for inputs below its exact cutoff. The probability calculation also invokes the generic divider for zero-valued exponentials. Count the full exponential and divider costs and quantify how often such inputs occur before selecting a mechanism. Prefer the largest bounded avoidable cost with a clear exactness argument and a realistic route to the fixed clock. Verify the selected mechanism and anticipated saving independently before building. All exact results, reset behaviour, interface/acceptance behaviour and backpressure must remain correct. Record the selected intervention and its predicted control-to-candidate clock counts separately before running it.

After local equivalence and a clean routed 50 MHz build, use the standard [matched KV260 comparison](measurement-standard-v2.md) with the same three prompts, 36 timed requests, 18 warm-ups, and AB/BA/AB order.
