# Experiment 24 measurement fixture

This fixture retains the Experiment 23 mixed and homogeneous workload, native on-chip MMIO delivery, exact reference checks and INA260 integration. Both arms load the same selected FPGA firmware and native bundle. The board supervisor owns image installation, PL0 changes, locking, time limits and restoration. The fixture has no clock-setting or programming entry point.

## Prepare and verify offline

From the repository root, run `python3 -B hardware/research/inference/experiments/kv260-clock-frequency-v1/prepare_fixture.py . /path/to/new-packet`. The new directory contains the pinned workload and files, plus `measurement-plan.json`. It verifies the Exp23 source record and raw reply against the archive before deriving the host guard and active-window clock brackets. The packet binds the qualified Vivado profiles, exact firmware and DTBO. Run `python3 -B hardware/research/inference/experiments/kv260-clock-frequency-v1/test_frequency.py` from the repository root for synthetic full schedule and rejection tests.

The default packet uses the Experiment 23 image at 50,000,000 and 52,631,579 Hz. The original layout does not qualify for 62,500,000 Hz. A separate qualified layout can use `--implementation /path/to/offline-acceptance.json`. The receipt identifies `passed`, `board_programmed`, `protocol_sha256`, `same_image_for_all_passing_rates`, `qualified_nominal_rates_hz`, and `timing_profiles`. The profiles report `nominal_rate_hz`, `upper_qualified_rate_hz`, `admitted`, `setup_slack_ns`, `hold_slack_ns` and `pulse_width_slack_ns`. The receipt also names `live_program_overlay`, and `firmware` and `program_overlay` records with `filename`, `bytes` and `sha256`. The files are under `server/offline-package` and `server` next to the receipt. Use a fresh packet and 50 MHz arm with that distinct layout.

## Board supervisor interface

Load `measurement-plan.json` and set `clock_contract.pl0.control` and `.candidate` to the exact qualified clock fingerprints. Each has integer `configured_hz` and `parent_hz`, a `parent` name, `dividers` mapping each divider to its positive integer value, and `enabled: true`. The comparison also requires `clock_contract.unrelated_clocks`, the observed fixed fingerprint of other clock parents and rates. The board readback adapter returns `boot`, `image` (`name` and `sha256`), `pl0`, and `unrelated_clocks`. Preserve additional provider and firmware readback details in `raw`.

After verifying the packet and allocating its private staging directory, call `frequency_fixture.prepare_bundle(config)` once and put the returned `bytes` and `sha256` in `config.bundle_pin`. This creates `fixture-bundle-candidate` from the sealed board-native sources with an exact allowlist for the two rate profiles. Supply the optional `bundle_path` in the configuration if using a different destination. Preserve the derived bundle manifest.

With the clock and image already selected, call `frequency_fixture.measure(config, output, mode, pair, *, readback, smoke=False, homogeneous=None)`. Give it a new output directory for each block. Use the order and labels in `measurement.SESSIONS` and freeze `watchdog.json` in the evidence root with `request_timeout_ns` set to `5000000000`. `arm_timeout_s` is 120 for smokes or mixed blocks and `30 + 5*(1 + HOMOGENEOUS_REPLIES[case])` for a homogeneous block. The measured block boundaries stay the same in both arms. Whole-block clock captures bracket warm-up through settled idle, and separate captures bracket active replies outside the primary integral. A clock readback may influence the samples near an edge in the shifted ±50 ms sensitivity scenarios. The sampler period remains 50 ms.

## Offline score

Run `python3 -B /path/to/new-packet/score_frequency.py EVIDENCE FULL_CONFIG NEW_OUTPUT`. It checks every packet digest and exact output/work count, configured clock and firmware, chronology, thermal brackets, peripheral counters, and five-alignments rail eligibility. The output contains `score.json` with individual and paired observations and `measurement-findings.md` for the physical record. Preserve the original raw traces and readbacks regardless of outcome. A completed score is the measurement component of the record. Link the actual supervisor outcome, restoration and verified board evidence when registering the physical experiment.
