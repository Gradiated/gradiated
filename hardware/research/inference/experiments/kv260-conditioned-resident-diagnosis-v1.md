# KV260 resident timing diagnosis and repeated baseline

## Existing evidence

Across 30 detailed fresh-load requests, scored after the weights were ready, the median share of post-load generation time inside Python's step call was 97.64–98.79% across the three prompts. CPU argmax occupied 1.03–2.11%. The step call includes the sealed native function and Python score handling. Across the 72 existing resident requests, the generation loop accounted for 97.16–97.63% of verified request time. The previous 48-request block yielded 144.13–144.43 output bytes/s in its four 12-request segments. ## Board protocol

Use the sealed W16A16 model, board package and FPGA image and the same 50 MHz live state, three frozen prompts, greedy CPU selection, context clear, and all-score correctness checks as the earlier resident runs. The board uses one native session at a time and checks all 320 signed values in every frame before the next request. The Mac independently checks observed digests against the pinned exact traces. A failure saves the first mismatching frame and completed receipts.

Each of three same-boot sessions contains two three-request profiling arms in alternating order off/on, on/off, off/on. Warm up with six requests before each arm. Both arms score one request per prompt in the same order with the power logger disabled. Wrap the existing ctypes native call, Python step method, argmax, hash and exact-check functions only in the profiled arms. Record inclusive wall times and invocation counts. Subtract native time from the inclusive Python step to estimate the surrounding allocation/conversion/dispatch time under these hooks. The sealed native interval includes polling, FPGA work, moving the scores, and completion checks. Report all paired first-byte, verified-request and throughput differences against a descriptive ±2% screen. One request per prompt per arm gives a paired observation. The hooks add measured overhead and do not expose an exact compute/AXI partition.

After six more warm-up requests, run one uninterrupted block of 84 requests per session. Repeat a balanced 12-request order seven times, for 8,848 emitted bytes per block, with deep profiling disabled. Retain a compact digest and timing receipt per verified request. Digest formation is included in the verified boundary. This differs from the earlier block harness. Export happens after the block. Record throughput by block and each 12-request segment. Compare first and last segments within each block and report variation across blocks. A minute of continuous requests and boundary temperature snapshots describe the conditions achieved, without establishing thermal equilibrium.

Use the qualified unprivileged INA260 logger at 20 Hz in the long blocks. Use the existing two-second matched idle windows, half-second guards and 75 ms maximum integration gap. Keep identical verified context in the two idle windows. Admission and final verification use the board monotonic clock shared with the sampler. Sample for 75 seconds under an 84-second worker cap. Hold the existing outer timeouts and ownership checks, with a 900-second supervisor cap and 885-second inner deadline. The Mac verifies each phase before admitting the next one. Use original-model BOS before the experiment and after health-gated restoration.

Read exact AMS processed temperatures and current CPU policy/frequency at boundaries. Capture supervisor VmRSS, its lifetime VmHWM, and system MemAvailable at the long-block boundaries. Treat these as host process and system observations. The process includes Python and reference/evidence allocations, and the board's lifetime peak does not reveal inference-only peak. Keep all temperature reads outside timed power and inference windows.

The schedule has 54 warm-ups, 18 profiling requests and 252 long-block requests. Offline replay of all 12 gate exports produced about 0.76 MB, or about 66 seconds at 115,200 baud before transfer overhead. The three sampling windows total 225 seconds. Preserve the raw power samples and coverage decisions, boundaries, timing and verification receipts. Integrate only admitted blocks, report joules per verified completion and emitted byte over VCC_SOM, and retain separate matched-idle-adjusted estimates and alignment sensitivity. The earlier logger comparison screens observer effects for the same power sampling path and code. These runs provide block observations within one boot and one model. All interpretation stays within those boundaries.
