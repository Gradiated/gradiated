## Question, mechanism and scope

The [feed-forward diagnostic](../results/ff-profile-rtl-20261116T211748Z/findings.md) found 12,672 cycles per processed position in the exponential's three divisions by 45,426, or 36.9% of feed-forward time. Gate/up work mostly overlaps scalar arithmetic. Can skipping provably zero leading quotient digits reduce complete inference time and module energy while preserving exact behaviour?

Use the existing two-bit restoring division recurrence and unchanged final rounding/sign logic. For a numerator magnitude n, start with remainder P = n >> k only when P < 45,426, quotient zero and the remaining k low bits left-aligned in the existing numerator register. Continuing long division gives the same exact quotient and remainder. k is 6, 8 or 32 for the three respective EXP call sites, giving 3, 4 or 16 calculation clocks instead of 32 each. Any input outside the shortcut guard uses the original full division. This is exact work elimination, not approximate arithmetic or stored model answers.

Bounds cover the supported command/table domain rather than only observed model values. The first non-shortcut EXP input magnitude is at most 2^20, so n >> 6 <= 16,384. The second input is remainder times 256, so n >> 8 <= 45,425. The interpolation magnitude is at most 2^31 times 45,425 for any legal table entries, so n >> 32 <= 22,712. Each prefix is smaller than the divisor. Preserve the original EXP invalid-input and zero shortcut branches, sign handling, quotient/remainder, ties-to-even rounding and errors. Verify signed64 extrema and guard fallback too.

Only the feed-forward scalar instance uses the specialised clone and three EXP call sites. All other ten generated RTL modules remain byte-identical, including the generic scalar module. Preserve sigmoid division, activation formula, weights/tables, numerical rules, cache, output selection, eight score lanes, host and 50 MHz target. Reciprocal multiplication and wider-radix designs were considered but are not part of this candidate. The retained recurrence avoids an unnecessarily wider arithmetic critical path.
