# Experiment 17 · Fetch the next group of score weights while scoring this group

[Experiment 16](../results/logits-ddr4-burst-20261119T121954Z-31256a/findings.md) moved the 20 KiB final-score matrix from block RAM to DDR4. This freed eight of the selected circuit's 39 block RAM tiles. The eight scoring lanes waited while a local buffer filled before starting each group of eight token scores. Can we use a second buffer to recover part of that time while keeping the eight tiles free?

## Matched circuits and expected effect

Compare the routed one-buffer logits-ddr4-burst-v1 (A) with logits-ddr4-prefetch-v1 (B). B may fill the next 512-byte group while the lanes use the current one. Only the final-score weights live in this DDR buffer. Keep input embeddings on-chip. Both circuits process 40 groups per scoring pass, use eight lanes and identical signed rounding, accumulate the original dot products in their original order, and run at 50 MHz. Keep the same frozen model, packed matrix, AXI port and burst size, temporary driver, host boundaries and three prompts. Both arms should issue 320 address requests, receive 2,560 64-bit beats and use 20,480 bytes per scoring pass. Carry no speculative read past the final group of a pass. The first group still has to arrive before it can be used.

Each on-chip scoring pass took 1,680 clocks before adding DDR fetches. Experiment 16 added about 6,553 clocks per pass on this board. At the same memory service cost, overlap can conceal only the computation/control time available alongside fetches. On Hello's 91 scored positions the optimistic ceiling is about 3 ms per reply. This is an analytical bound conditional on unchanged service time. DDR response waits can change between arms. We predict faster decode and completion, unchanged traffic and broadly similar first-token times. Test energy and actual resource use independently. Inspect both routed memory hierarchies and report whether B retains the eight-tile saving and what additional LUTs and flip-flops the second buffer costs.

## Qualification

First compare both implementations in exact RTL replay against the frozen cases, and check group, coordinate and signed lane order. Include delayed responses, output backpressure, alternating ownership, final group, next request, reset, malformed response and drain/recovery. On simulated traces count overlapping fetch and scoring phases directly. Establish the relationship between the host-observable exposed waits and total reader service in each build. Keep the timing conventions for the first group and final returned beat explicit. Preserve source manifests and any failed qualifications separately. Allow 25 minutes per complete RTL replay. Reuse the verified Experiment 16 control image with pinned sources, constraints and reports. Allow 42 minutes for a candidate route, three minutes for packaging and up to 20 minutes for resumable archive recovery. Check setup and hold closure, 50 MHz, the read-only HP0 route, bounded reads into the private mapped buffer and complete artifact hashes before physical use.
