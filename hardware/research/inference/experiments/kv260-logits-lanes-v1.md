# One, two and four lanes for final token scores

Compare the exact `logits-pipeline-v1` one-lane implementation with two and four multiply-and-accumulate lanes in the final 320-by-32 token-score projection. This comparison uses the frozen `chip-joke-text-20261109` W16A16 model, the same 50 MHz target, host, AU02 stream, cache and request protocol. The selected research baseline remains `scalar-div-v1`.

Each lane calculates a different output row, using one signed 16-bit multiply and 48-bit accumulator in the same coordinate order as the control. It reads one weight per clock from its own row-interleaved bank. A single activation read supplies all lanes. The banks hold the same 10,240 weights without a second copy and retain the same external load interface. Banking is part of the coupled change needed to feed the parallel lanes. Physical BRAM allocation can rise due to bank geometry.

Prime one set of operands, accumulate 32 coordinates, round and clip each result, then emit the group's two or four scores in ascending order at one result per handshake. The next group starts after the current group is drained. At continuous readiness, the expected budgets are 11,200, 5,760 and 3,040 clocks per retained projection respectively. At 50 MHz, the expected single-position reductions from the one-lane arm are 0.1088 and 0.1632 ms. Missing weight-read throughput, output stalls, placement or resource mapping may reduce the effect. Wall-clock and energy measurements require the board comparison.
