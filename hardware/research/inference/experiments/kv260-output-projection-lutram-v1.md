Change only `core/output_projection/weight_memory`, a 32 × 32 matrix of trained 16-bit weights. Its logical capacity is 2,048 bytes. The adopted routed checkpoint maps this array to one RAMB18E2. ## Intervention and prediction

Keep the ports, data, signed widths, rounding, controller and read and write addresses. The same existing READ edge captures each operand. Weight writes still occur only in idle with valid indices. Reset cancels a calculation and leaves the stored weights intact. The supported access schedule excludes collisions. The matrix, other arrays, clock, model, host runtime and benchmark remain fixed. Use Vivado's native inference and check what it actually implements. [AMD memory inference guide](https://docs.amd.com/r/2025.2-English/ug901-vivado-synthesis/Memory-Inference-Capabilities)

All seven full-model requests should produce identical first, last, prefix and completion counters, phase counts, exact scores and cache activity. A difference in resource use or timing slack is possible even with identical cycles. Wall latency and energy can stay within observed variation. Small differences in board measurements need their paired variation and sample-alignment context. The result remains informative if it finds no measurable speed or energy gain. Whole-design slack can also reflect placement and routing outside the selected array.
