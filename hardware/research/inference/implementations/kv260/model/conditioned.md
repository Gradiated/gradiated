# Real-text, deterministic joke transformer

Authorised 9 November 2026. The actual UTF-8 input must enter the network. No
text hash, seed, sampling, joke identifier, output lookup, retries, output masks,
or replacement text is permitted during inference. Greedy argmax considers all
320 logits. Same input intentionally repeats its output. Source model and user
joke edits are preserved. Targets are the original frozen 48-joke snapshot.

## Initial contract (superseded input encoding below)

Keep the 26,720-parameter geometry. Input is [BOS=256, actual UTF-8 bytes,
ANSWER=258]; generated bytes follow until EOS=257 or the context boundary. The
answer marker is the same for everyone and names no joke. Existing unused
vocabulary capacity accommodates it without growing tensors. Input limit is
96 bytes, with explicit rejection rather than silent truncation; 256 positions
leave room for the longest 141-byte target. No KV reset at the answer boundary.

Start from a copy of pinned FP32 weights. AdamW, learning rate .0003, decay .01,
clip 1, batch 16; supervise every answer byte and EOS, with zero loss on input.
Keep ordinary full-attention computation over input. Reproducible randomness is
used only to construct synthetic training data and shuffle batches, never in
generation. Worker checkpoints include optimizer state and exact hashes.

Freeze 3,072 synthetic training prefixes plus authored edges, 240 development
prefixes plus edges, and exactly 1,000 final prefixes before training. Splits are
text-disjoint and use different natural-language openings. Categories include
printable noise, text/noise mixtures, repeated characters, whitespace, Unicode,
known joke fragments and unrelated questions. These are controlled synthetic
situations, not evidence of open-domain language understanding. All jokes remain
training targets; novelty is in input strings. Final outputs are not used to tune.

Proposed final gate: >=950/1000 complete exact authored jokes (a conservative
coherence check), >=40 distinct authored jokes. Report all failures, most frequent
joke, distribution by category/length, and verbatim outputs. Manually inspect
nonexact outputs separately. No performance or energy claim; setup, fit, eval,
peak MLX memory are recorded. GPU utilization/power are not instrumented.

## Opportunity register and branch rules

1. Independent paired prefixes (initial arm): the existing network knows the
   jokes but has never learned the input/answer boundary. Hypothesis: ordinary
   supervised updates recover coherent generation with text present. Competing
   explanation: independent targets teach a broad distribution that collapses
   under greedy decoding. Falsifier: good coherence with low joke diversity.
2. Learnable input/target relation (conditional arm): if variety collapses, pair
   synthetic training inputs by a simple last-byte class, balanced as feasible,
   to teach content-dependent deterministic selection. This is a training-data
   design only; the deployed inference function receives no IDs and contains no
   class calculation. It demonstrates learned routing, not semantic understanding.
   Falsifier: unseen prefixes still collapse or contaminate whole jokes.
3. Fresh initialization or staged curriculum only if a measured failure of the
   warm start justifies it. Register the exact change before execution.

Stock control is original FP32 weights receiving the same real text/answer
format, greedy. Development is measured after bounded fitting chunks. At most
12,000 updates per initial lineage before reassessing its mechanism; use <=180s
absolute offline workers and <=125s soft fit chunks with state export. No cloud,
new dependency, downloads or board writes. Existing Mac sandbox denies network
and source/selected-weight writes. Check source and all selected payload hashes.

When the FP32 candidate passes development, freeze it, check independent NumPy
logits and cached/full execution, then run final evaluation once. Convert to
W16A16 separately, recalibrate from training/development only, check integer
ranges, full/cache equality and actual output quality. FPGA validity requires
separate deployment/equivalence checks; software success is not hardware proof.

### First measured branch and amendment

The original FP32 control gave 0/64 exact jokes in the new input format. The
independent-pair warm start reached 1/249 at 1,600 updates, 78 at 5,600, 128 at
9,600 and 152 at 12,000 (29 distinct; most frequent 20). Complete outputs are
retained; low training loss .047 did not imply robust free generation.

The next bounded lineage starts again from original FP32, uses suffix-related
training targets and regenerates all preceding noise characters on every use.
This changes two factors to test a practical mechanism, not an isolated estimate
of either effect: learn a simple deterministic relation while preventing noise
prefix memorisation. Holdout inputs are explicitly excluded from regeneration;
heldout outputs remain unopened. Corpus/targets/geometry/optimizer/rate unchanged.
The first lineage's failure is retained, not silently relabelled as success.


### Numerical diagnosis and answer-start weighting

Fresh-prefix suffix lineage at 12,000 updates: 72/249 exact, 17 distinct, worse
than the retained 152/249 independent checkpoint. Six real-prefix probes checked
all-position full/cached FP32 outputs (maximum difference <.00011), plus independent
NumPy endpoint logits (<.000027). This supports a learning failure, not a cache
implementation discrepancy. First-answer-byte NLL is 1.45–5.13 despite low average
teacher loss. Later teacher errors are worse with longer random prefixes.

Next amendment: retain the same suffix/fresh lineage, lower LR to .0001 and weight
the first 16 answer predictions by 8. Keep all later tokens/EOS supervised. Budget
extends this lineage to 32,000 total updates, evaluating after 4,000-update chunks;
original 12,000 checkpoint remains immutable. Test whether emphasizing the start
improves free generation. No sampling/IDs/constraints are added to inference.


### Weighted branch outcome; direct-prefix alternative

The weighted suffix lineage remained poor: best 97/249 exact at 24k, then 78/249
at 32k. Its optimizer restore retained the old .0003 learning-rate tensor despite
the requested .0001: candidate JSON's requested rate is not the effective rate
for these five chunks. Optimizer SafeTensors preserve the actual value. Corrected
future resume to explicitly set/check optimizer.learning_rate after state restore.
No claimed low-rate comparison can use those five chunks.

Next separate lineage: omit the ANSWER token entirely, use [BOS, actual text]
followed by joke bytes, fresh suffix-related training prefixes, first16 weight8,
LR .0003, original FP32 warm start. This gives the first predicted byte direct
access to the last input byte's embedding, instead of requiring the answer
marker to discover it through attention. No input hashing or inference routing.
Train up to32k updates with development checks; preserve both marker lineages.


### Separate input-symbol vocabulary (role48)

Direct byte-prefix branch reached only74/249 at32k,34distinct, with frequent
missing initial characters and corrupted endings. Retain it; no final was opened.
Hypothesis: one-layer byte attention confuses random input characters with the
same characters in the generated joke. Test a lossless separate input alphabet:
every UTF8 byte b becomes [260+b//48, 272+b%48]. This uses existing unused
embedding slots, preserves every byte and its order, and is invertible. It is
ordinary tokenisation; no hash, seed, selection ID, semantic router or answer bank
is part of inference. Generated text still uses byte tokens0..255, EOS257, with
unmasked argmax over all320 scores. No answer marker in this arm.

Two input tokens/byte reduce the explicit input limit to48bytes to reserve room
for every joke. Same26,720weights/shape, original FP32 warm start, suffix-related
training examples, fresh noise, first16 lossweight8, LR.0003, up to32k updates.
A new versioned corpus freezes the corresponding input lengths and1000final
inputs before fitting. Architecture/arithmetic remain unchanged; tokenisation
change and smaller input limit must be disclosed. No hardware validity assumed.


### Role separation result and hexadecimal control

Role48 reaches245/249 exact jokes at4,000updates,41distinct, all249EOS/validUTF8.
This is development evidence only. It is much stronger than byte-token branches.
Before selection, test a standard radix16 input representation, independent of
the number of jokes: each byte b becomes [272+(b>>4),288+(b&15)]. These 32 symbols
represent its two hexadecimal digits with distinct high/low positions. Every
input byte is reconstructable; no runtime calculation depends on joke count.
Same text cases, targets, original FP32 warm start and training parameters. The
model must learn from both digits rather than receiving one48-way digit. This
removes a dataset-specific input-alphabet choice and is easier to explain.
Keep48-byte input cap, unchanged network geometry and unmasked greedy output.
Train up to32k with development gates; evaluate final only after freezing winner.

### Exactly what enters and leaves the network

Input is `[256,272+(b0>>4),288+(b0&15),272+(b1>>4),288+(b1&15),…]`.
There is no answer marker, input hash, seed, response ID or stored-answer lookup.
The two input tokens encode each actual UTF-8 byte losslessly. They use 32 existing
vocabulary slots distinct from output bytes. The model predicts the next token;
the host takes argmax over all 320 logits, feeds that token back, and repeats until
EOS 257. No vocabulary masking, retries or output replacement. KV for all input
positions remains present. Each entry starts a new completion, not chat history.

Inputs are limited to 48 UTF-8 bytes and explicitly rejected if longer. Two tokens
per input byte leave room for the longest 141-byte joke within 256 positions.
Same input deliberately gives the same answer. Many endings give the same joke.
The suffix training rule assigns authored targets using the last UTF-8 byte modulo
48; this calculation appears only in training-data construction and is absent
from inference. The network learns a simple routing relationship. It is not
trained to understand questions, and passing all input bytes does not imply that
all of them materially influence the generated answer.

## Original-scale deployment format, 9 November 2026

The selected fixed candidate now retains every original FPGA exponent, including
down weights at 2^-16. This supersedes the initial conversion's scale-change
requirement above. FP32 training weights and the original BOS-only controls are
unchanged; the prior 2^-15 conversion remains pinned as previous_fixed.

Naively forcing 2^-16 clips one of 4,096 down weights from -.54386252 to -.5.
It retained 245/249 exact development jokes but failed the existing normalized
RMSE gate: .02673862 > .01. That rejected result is retained at runtime
outputs/tiny/20261109T183205069139 and numerical check20261109T183615084380.

The selected conversion uses a function-preserving SwiGLU channel balance before
rounding. Copy the FP32 up/down arrays; multiply up[51,:] by 9/8 and divide
down[:,51] by 9/8, in FP32. Since hidden=silu(gate)*up and down is linear,
the factors cancel in exact real arithmetic. Gate and all other parameters are
unchanged. Quantize these arrays with ties-to-even at up exponent -15 and down
exponent -16, requiring no out-of-range signed 16-bit values. Copy all other integer
weights, tables and activation exponents from the initial converted payload.
This is conversion, not retraining; the original FP32 checkpoint is untouched.
No additional FPGA multiplication, parameter, storage or inference operation is
introduced. The hardware still uses the original down SHIFT15.
