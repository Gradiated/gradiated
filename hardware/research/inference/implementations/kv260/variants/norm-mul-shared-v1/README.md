# One shared five-clock multiplier for three normalisation units

[Experiment 21](../../../../experiments/kv260-norm-mul-shared-v1.md) compares this variant with the dedicated five-clock normalisation multipliers from Experiment 20. Inference starts the three normalisation instances in sequence. Each instance retains its own input and gain storage, scalar command and sign state, sum, reciprocal-square-root and division arithmetic, tables, rounding, and output registers. The feed-forward multiplier is separate.

## Request and result lifetime

The transformer starts each unit in its own start state, then waits until the final normalisation coordinate is accepted before advancing. This acceptance also returns the producer to idle. No two normalisation units can therefore be producing arithmetic requests during the same transformer clock. A model fault holds the controller until reset. The same synchronous reset clears the three scalars and the shared controller.

Each scalar latches the two magnitudes and its own result sign when it starts a multiply. It requests the datapath on the following edge, when the dedicated version would launch its first partial products. The shared unit chooses one request by fixed priority while idle. A denied request remains pending with its original operands. The grant captures both the new owner and all sixteen unsigned 16 × 16 partial products on the same edge. The next three edges register rows, halves and the full 128-bit magnitude. On the fifth calculation edge the original caller applies the original sign, overflow rule and next state. The shared unit presents valid only to the retained owner and holds the result until that owner accepts it.

Reset masks grants and valid results immediately and clears the owner and scheduler state at the next edge, as well as cancelling the clients. The arithmetic registers can retain their bits across reset. The scheduler rewrites every partial value before it presents a fresh valid result. The multiplier preserves the dedicated scalar’s rejection for any magnitude above (2^{63} - 1), including the signed-minimum edge under the inherited overflow rule.

## Reproduction

`materialise_shared_norm_multiply.py` verifies the dedicated source manifest and delegates arithmetic to the pinned partial-product kernel already used in both earlier designs. It emits the same eleven source filenames as the control, with changes confined to `rmsnorm.sv` and `transformer.sv`. `replay_shared.py` runs the seven pinned Experiment 19 inputs against the dedicated Experiment 20 control and the shared variant, checking the Experiment 20 cycle forecast and pinning the Verilator 5.052 runtime. `test_shared.py` exercises the real shared scalar interface with simultaneous requesters, independently computed signed products, overflow, blocked outputs and reset. `seal_gate.py` separately compares the result with the sealed Experiment 20 numerical and timing traces, then emits the route admission manifest and the canonical nested per-case results.

Use a fresh output root and Python 3.10 or newer. Obtain the dedicated RTL and archived replay members from the [Experiment 20 run record](../../../../results/norm-mul-dsp-v1-rtl-20261119T175201Z/run.json). Run each script with `--help` for the required paths. The RTL archive preserves the full generated sources, fixtures, tool logs, result summaries and route admission receipt. One shared copy nominally frees 32 DSPs compared with three dedicated copies. Routed utilisation and timing must establish the actual cost of sharing.
