# KV260 DDR4 burst fixture build

Exp15 uses the verified Exp14 PS, clock, reset and native HP0 layout. The fixture replaces the generated RTL inputs, raises the AXI interface's maximum burst length to eight beats, and keeps a direct 64-bit AXI4 link on `clk_pl_0`. The PS receives either a one-beat read (`ARLEN=0`) or an eight-beat incrementing row read (`ARLEN=7`). The low 2 GiB aperture and independently enforced 64-byte-aligned weight buffer stay fixed across all four modes. The synthesis image contains the BRAM control.

Materialise the exact RTL with [materialise_projection_burst.py](../materialise_projection_burst.py). Pass its output, the verified Exp14 `build-input.tar.gz`, a fresh destination and an attempt ID to `prepare.py`. For the final build pass the local `kv260-ddr4-burst-dma-direct.dts` and the [verified AFI restoration source](../../output-projection-ddr4-v1/build/kv260-ddr4-afi-restore.dts) as `--dma` and `--restore`. The build input manifest pins every file and the frozen experiment protocol.

Extract the prepared input archive into the manifest's `remote_root` on the established Linux host. From that directory run `KV_OUTER_BUILD_UTC=$(( $(date +%s) + 2520 )) python3 -u run-all.py`. The two-thread phase deadlines leave three minutes in the 45-minute implementation budget for the remote archive, followed by five minutes for recovery.

Recover the Linux archive and receipt onto the Mac. Run `verify.py <archive> <receipt> <new-destination> <exp14-run-directory> <acceptance.json> --manifest-pin <prepared-source-manifest-sha256> --rtl-manifest <tested-rtl-source-manifest> --rtl-run <rtl-run.json>`. It checks the archive, build phases and 20 ns route, traces the native HP0 pin drivers and clock, checks the original BRAM path, compares the generated PS writes with Exp14, then independently verifies the converted bitstream and device-tree values.

The package includes the candidate program overlay and the burst-specific direct DMA overlay. The AFI/UIO interface and AFI restore overlay are byte-identical to Exp14. The DMA overlay uses the burst driver's compatible and the same verified direct address mapping marker and register window. Use the existing [PS readback helper](../../output-projection-ddr4-v1/build/readback.py) only after confirming the original width-zero baseline and direct nonsecure mapping on the relevant boot.
