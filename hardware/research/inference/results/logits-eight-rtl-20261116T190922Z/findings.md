# Eight-lane final scoring in simulation

The four-lane control exactly replayed the earlier result. Both circuits passed the seven matched model cases and the signed component checks at 16 and 32 output bits. All retained scores, generated byte IDs, termination checks and valid cache contents matched the frozen references. Only the final scoring phase changed.

| Natural prompt | Four-lane complete clocks | Eight-lane complete clocks | Change |
| --- | ---: | ---: | ---: |
| Hello | 7,922,865 | 7,799,105 | −1.56% |
| Six-byte prompt | 11,778,637 | 11,611,357 | −1.42% |
| 48-byte prompt | 20,625,187 | 20,482,387 | −0.69% |

Each scored position took 3,040 projection clocks with four lanes and 1,680 with eight. The saving of 1,360 clocks is 27.2 µs at 50 MHz. Both designs serialise 320 output scores per projection. The two widths imply useful on-chip weight rates of 336.8 and 609.5 MB/s from the simulated cycles and fixed clock. Board measurements cover observable speed and energy separately.

The first launch stopped before compilation because the new Python module name collided with a pinned legacy helper. The retry used a unique module name and the same generated RTL, protocol and fixtures. The archive preserves the launch note.
