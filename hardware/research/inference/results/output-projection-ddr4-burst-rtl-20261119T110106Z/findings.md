# Exact DDR4 burst fixture replay

BRAM, scalar DDR, four-weight beat DDR and row-burst DDR matched all seven frozen cases across 716 processed positions per mode. Every emitted score, generated byte, stop reason and two cache checkpoints matched. BRAM and scalar DDR retained the Experiment 14 phase and request cycle counts exactly.

| Mode | Address requests per projection | Response beats per projection | Extra FPGA clocks per projection |
| --- | ---: | ---: | ---: |
| BRAM | 0 | 0 | 0 |
| Scalar DDR | 1,024 | 1,024 | 4,608 |
| Beat DDR | 256 | 256 | 1,152 |
| Row DDR | 32 | 256 | 704 |

The simulated slave imposed zero or two address stall clocks, alternating by transaction, and zero through three response wait clocks, cycling by beat. The extra clocks matched two launch clocks per address, the measured address and response waits, and one clock per accepted nonfinal burst beat. Each mode attributed all extra complete-request cycles to the output projection. These clock totals describe the simulated handshake schedule.

The full model monitor checked each ordered coefficient against the independently decoded frozen matrix, as well as each command address, burst length, access qualifier and 4 KiB boundary. The directed oracle checked every signed operand, product, partial sum, tie, clipped row and saturation flag. Changing only one external coefficient in each DDR mode changed row 6 from −50 to −52 with the BRAM weights fixed.

Ten fault or cancellation cases covered non-OKAY and wrong-ID responses, premature and delayed RLAST, address and response timeouts, and full reset with a stalled address, before the first response, and mid-burst, plus reset after the complete first row is buffered. The fixture withheld safe release until the accepted transaction drained. It then reloaded the model, matched all 320 BOS logits in BRAM, and matched all 320 in row mode using a fresh first-row request.
