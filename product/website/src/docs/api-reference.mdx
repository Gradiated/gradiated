# API reference

<DocsLead>Gradiated accepts OpenAI and Anthropic compatible inference requests, and native SystemOne decision requests.</DocsLead>

## Inference endpoints

You can use `https://api.gradiated.com` as the base URL in all SDKs.

| Method | Path                   | Purpose                                             |
| ------ | ---------------------- | --------------------------------------------------- |
| `GET`  | `/v1/models`           | List accessible models.                             |
| `POST` | `/v1/chat/completions` | Send an OpenAI Chat Completions request.            |
| `POST` | `/v1/responses`        | Send an OpenAI Responses request.                   |
| `POST` | `/v1/messages`         | Send an Anthropic Messages request.                 |
| `POST` | `/v1/systemone`        | Ask linden-1 for choices, probabilities and scores. |

The model catalog is also available at `/models`. Use `/v1/messages/count_tokens` to count message input tokens.

For direct HTTP requests, send the API key as a bearer token:

```http
Authorization: Bearer grad_...
```

See the [SystemOne SDK guide](/docs/systemone-sdk/) for linden-1 examples and supported parameters.

## Training API

The training API (`grad-server`) is the same on Gradiated Cloud, `grad local up` and the Helm chart. Its contract is `spec/openapi.yaml`; the Python, TypeScript, Go and Rust SDKs and the CLI are generated from it. Self-hosted servers default to `http://localhost:8787`.

### Models and keys

| Method   | Path            | Purpose                                                                |
| -------- | --------------- | ---------------------------------------------------------------------- |
| `GET`    | `/v1/models`    | List trainable base models, with prices and calibrated learning rates. |
| `POST`   | `/v1/keys`      | Create a scoped workspace API key. The secret is returned once.        |
| `GET`    | `/v1/keys`      | List workspace API keys.                                               |
| `DELETE` | `/v1/keys/{id}` | Revoke a key.                                                          |

### Datasets and imports

| Method | Path                               | Purpose                                                                       |
| ------ | ---------------------------------- | ----------------------------------------------------------------------------- |
| `GET`  | `/v1/datasets`                     | List datasets, newest first.                                                  |
| `POST` | `/v1/datasets`                     | Create an empty dataset.                                                      |
| `GET`  | `/v1/datasets/{name}`              | Get a dataset.                                                                |
| `POST` | `/v1/datasets/{name}/records`      | Append records as a new dataset version (creates the dataset if needed).      |
| `GET`  | `/v1/datasets/{name}/records`      | Read the records of a dataset version.                                        |
| `POST` | `/v1/datasets/{name}/render`       | Preview chat-template rendering and loss masks (estimated token counts).      |
| `POST` | `/v1/uploads`                      | Get an upload URL for a trace file. `PUT` the bytes, then create an import.   |
| `POST` | `/v1/datasets/{name}/imports`      | Import an uploaded file or a Hugging Face dataset into a dataset (async job). |
| `GET`  | `/v1/imports` / `/v1/imports/{id}` | List import jobs or get one.                                                  |

### Runs, checkpoints and artifacts

| Method | Path                           | Purpose                                                                                        |
| ------ | ------------------------------ | ---------------------------------------------------------------------------------------------- |
| `POST` | `/v1/runs/plan`                | Dry run at $0: resolve recipe defaults, check the data and estimate tokens and cost.           |
| `POST` | `/v1/runs`                     | Create and queue a training run. The run pins the dataset version.                             |
| `GET`  | `/v1/runs` / `/v1/runs/{id}`   | List runs, newest first, or get one (status, `resolved_config`, `eval_report`, `artifact_id`). |
| `GET`  | `/v1/runs/{id}/metrics`        | Step metrics as JSON pages, or a live SSE stream with `Accept: text/event-stream`.             |
| `POST` | `/v1/runs/{id}/cancel`         | Cancel a run. A running attempt is stopped and billed.                                         |
| `POST` | `/v1/runs/{id}/resume`         | Resume a stopped, failed or cancelled run from its latest checkpoint.                          |
| `GET`  | `/v1/runs/{id}/checkpoints`    | List a run's unexpired checkpoints (best and final never expire).                              |
| `POST` | `/v1/checkpoints/{id}/promote` | Copy a checkpoint into a new immutable artifact.                                               |
| `GET`  | `/v1/artifacts`                | List artifacts, newest first (filter with `name`).                                             |
| `GET`  | `/v1/artifacts/{id}`           | Get an artifact by id, `name@version` or `name@latest`.                                        |
| `GET`  | `/v1/artifacts/{id}/download`  | Download the `.grad.tar.gz` bundle. Verify it against `X-Artifact-Sha256`.                     |

### Evaluations

| Method | Path                           | Purpose                                                                                   |
| ------ | ------------------------------ | ----------------------------------------------------------------------------------------- |
| `POST` | `/v1/evals/plan`               | Estimate tasks, model and judge calls, and cost.                                          |
| `POST` | `/v1/evals`                    | Queue an eval of one or more models on a pinned dataset version.                          |
| `GET`  | `/v1/evals` / `/v1/evals/{id}` | List evals or get one with its summary.                                                   |
| `GET`  | `/v1/evals/{id}/outputs`       | Page through model outputs (filter by `model`, or by `missing_scorer` for local scorers). |
| `POST` | `/v1/evals/{id}/scores`        | Post scores from local SDK scorers. The eval completes when none are missing.             |
| `GET`  | `/v1/evals/{id}/results`       | Per-task, per-model results.                                                              |
| `GET`  | `/v1/evals/{id}/failures`      | Failing tasks, for mining into a new dataset.                                             |
| `POST` | `/v1/evals/{id}/cancel`        | Cancel a queued, running or `awaiting_scores` eval.                                       |

Run status is `queued`, `running`, `completed`, `failed`, `cancelled` or `stopped_budget`. Eval status is `queued`, `running`, `awaiting_scores`, `completed`, `failed` or `cancelled`.

### Deployments, routing and feedback

Self-hosted servers answer deploy, rollback, route and embeddings with 501 `deploy_unavailable`: download the artifact and serve it on vLLM or SGLang instead.

| Method | Path                                         | Purpose                                                           |
| ------ | -------------------------------------------- | ----------------------------------------------------------------- |
| `POST` | `/v1/deployments`                            | Deploy an artifact under a stable model name (`your-org/<name>`). |
| `GET`  | `/v1/deployments` / `/v1/deployments/{name}` | List deployments, or get one with its feedback summary.           |
| `POST` | `/v1/deployments/{name}/rollback`            | Roll back to the previous artifact.                               |
| `POST` | `/v1/route`                                  | Ask a deployed router which model should answer.                  |
| `POST` | `/v1/embeddings`                             | Embed text with a deployed embedding artifact.                    |
| `POST` | `/v1/feedback`                               | Record deduplicated outcome scores and gold corrections.          |

`/v1/trainer-jobs/*` is the internal protocol between the server and its trainer workers. It needs a platform `trainer:worker` key and is not part of the SDKs.

### Idempotency

Every `POST` accepts an `Idempotency-Key` header of up to 255 visible ASCII characters. The SDKs send a UUIDv4 on each call and reuse it on every retry, so POSTs are retried safely; pass your own key to make a retry of your whole script safe too (`idempotency_key=` in Python, `--idempotency-key` in the CLI).

- The key is stored in the same transaction as the request's writes. A repeat with the same key and body replays the stored response with `Idempotent-Replayed: true`.
- The same key with a different body is rejected with 422 `idempotency_key_reused`.
- A repeat while the first request is still running waits up to 5 seconds for it, then gets 409 `idempotency_in_progress` with `Retry-After`.
- Responses are kept for 24 hours. 5xx and 429 responses are not stored.
- `POST /v1/keys` is never replayed, because its response holds the secret: a repeat gets 409 `idempotency_replay_unavailable`.
- Plan and render requests are read-only and store nothing.

```http
POST /v1/runs
Authorization: Bearer grad_...
Idempotency-Key: 5f0c8d1e-3b8a-4c39-9a4e-2f1f0b6f4a21
```

### Pagination

List endpoints take `limit` and `cursor` and return `{"data": [...], "next_cursor": ...}`. Pass `next_cursor` back as `cursor` for the next page; it is `null` on the last page. A `limit` above an endpoint's maximum is clamped, not rejected:

| Endpoint                      | Default | Maximum |
| ----------------------------- | ------- | ------- |
| Most lists                    | 50      | 200     |
| `/v1/datasets/{name}/records` | 100     | 1000    |
| `/v1/runs/{id}/metrics`       | 1000    | 5000    |

`/v1/runs/{id}/metrics` also returns `tail_cursor`, the position after the newest point so far. Pass it back as `cursor` to poll for points written later. The SSE stream sends one `metric` event per point (event id = `seq`) and a final `status` event with the finished run; reconnect with `Last-Event-ID` to resume.

### Errors

Errors are `application/problem+json` with `type`, `title`, `status`, `code`, `detail` and `request_id`. The same `request_id` is in the `x-request-id` response header; quote it when reporting a problem.

```json
{
  "type": "https://gradiated.com/problems/deploy_unavailable",
  "title": "Hosted serving is not available",
  "status": 501,
  "code": "deploy_unavailable",
  "detail": "Hosted serving is disabled on this self-hosted server (DEPLOY_MODE=disabled). Download the artifact with `grad artifacts download <id> --output ./adapter` and serve it with vLLM or SGLang (...).",
  "request_id": "req_6f1c..."
}
```

| Status | Example codes                                                                     |
| ------ | --------------------------------------------------------------------------------- |
| 400    | `malformed_request`                                                               |
| 401    | `unauthorized`                                                                    |
| 403    | `forbidden`                                                                       |
| 404    | `run_not_found`, `dataset_not_found`, `artifact_not_found`, `route_not_found`     |
| 409    | `idempotency_in_progress`, `idempotency_replay_unavailable`                       |
| 413    | `payload_too_large` (upload large files through `/v1/uploads`)                    |
| 422    | `validation_error`, `idempotency_key_reused`, `invalid_cursor`, `recipe_deferred` |
| 500    | `internal_error`                                                                  |
| 501    | `deploy_unavailable`, `inference_unavailable`                                     |
| 503    | `store_unavailable`, `billing_unavailable`                                        |

The SDKs raise a typed error per status (`AuthenticationError`, `PermissionDeniedError`, `NotFoundError`, `ConflictError`, `ValidationError`, `RateLimitError`, `DeployUnavailableError`, `InferenceUnavailableError`, `ServerError`) that carries `status`, `code` and `request_id`.

See the [Primitives reference](/docs/reference/primitives/) for the record and object schemas.
