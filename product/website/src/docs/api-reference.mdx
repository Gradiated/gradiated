# API reference

<DocsLead>Gradiated accepts OpenAI and Anthropic compatible inference requests, and native SystemOne decision requests.</DocsLead>

## Inference endpoints

You can use `https://api.gradiated.com` as the base URL in all SDKs.

| Method | Path                   | Purpose                                             |
| ------ | ---------------------- | --------------------------------------------------- |
| `GET`  | `/v1/models`           | List accessible models.                             |
| `POST` | `/v1/chat/completions` | Send an OpenAI Chat Completions request.            |
| `POST` | `/v1/responses`        | Send an OpenAI Responses request.                   |
| `POST` | `/v1/messages`         | Send an Anthropic Messages request.                 |
| `POST` | `/v1/systemone`        | Ask Linden-1 for choices, probabilities and scores. |

The model catalog is also available at `/models`. Use `/v1/messages/count_tokens` to count message input tokens.

For direct HTTP requests, send the API key as a bearer token:

```http
Authorization: Bearer grad_...
```

See the [SystemOne SDK guide](/docs/systemone-sdk/) for Linden-1 examples and supported parameters.

## Training API

Every endpoint, with its fields, an example request and response and the SDK call that sends it, is in the generated [Training API reference](/docs/reference/training-api/). The tables below summarise them. The training API (`grad-server`) is the same everywhere it runs: `grad local up`, the Helm chart and, soon, Gradiated Cloud. Its contract is `spec/openapi.yaml`, and the Python, TypeScript, Go and Rust SDK transports are generated from it. `grad-server` listens on port 8787 by default (`grad local up` serves it at `http://127.0.0.1:18787`) and serves the live spec at `/openapi.json`.

<DocsCallout label="Coming soon on Gradiated Cloud">`api.gradiated.com` doesn't serve the training API yet. Run it yourself with `grad local up` or the Helm chart; see [Self-hosting](/docs/training/self-hosting/).</DocsCallout>

Every `/v1/*` call needs `Authorization: Bearer <key>`. `GET /health/live` and `GET /health/ready` (database reachable) need no key.

| Method   | Path                | Scope       | Purpose                                                                                                  |
| -------- | ------------------- | ----------- | -------------------------------------------------------------------------------------------------------- |
| `GET`    | `/v1/base-models`   | any key     | List trainable base models with their adapters, recipes, prices and calibrated learning rates.           |
| `POST`   | `/v1/keys`          | `admin`     | Create a scoped workspace API key. The secret is returned once.                                          |
| `GET`    | `/v1/keys`          | `admin`     | List workspace API keys.                                                                                 |
| `DELETE` | `/v1/keys/{id}`     | `admin`     | Revoke a key.                                                                                            |
| `GET`    | `/v1/usage`         | `runs:read` | Billed usage, newest first: one row per billed increment of a run or eval attempt (see [Usage](#usage)). |

With `AUTH_MODE=cloud`, `/v1/keys` answers `501 keys_managed_by_cloud`: Gradiated Cloud keys are created and revoked in the console.

| `POST` | `/v1/datasets/{name}/imports`      | Import an uploaded file, a Hugging Face dataset or a built-in benchmark into a dataset (async job).                                                                                                                                                                                                                   |

Dataset reads need `datasets:read`, writes `datasets:write`. Scoring also needs `runs:write`, because it's a billed eval.

### Secrets and sources

| Method   | Path                               | Purpose                                                                                                                                                 |
| -------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST`   | `/v1/secrets`                      | Create or replace a workspace secret `{name, value}`. The value is encrypted and never returned.                                                        |
| `GET`    | `/v1/secrets`                      | List secret names and metadata.                                                                                                                         |
| `GET`    | `/v1/secrets/{name}`               | Get one secret's metadata (what `secrets.get` returns: a reference, not the value).                                                                     |
| `DELETE` | `/v1/secrets/{name}`               | Delete a secret (409 `secret_in_use` while a source uses it).                                                                                           |
| `POST`   | `/v1/datasets/{name}/sources`      | Connect a provider `{provider: {kind, host, secret, project, filters}, schedule}` to a dataset.                                                         |
| `GET`    | `/v1/sources` / `/v1/sources/{id}` | List sources (`?dataset=`) or get one with its status, last error and latest sync.                                                                      |
| `PATCH`  | `/v1/sources/{id}`                 | Change `filters`, `schedule`, `sample_rate`, `max_records_per_sync`, `max_records_per_day` or `version_interval`, from the next sync (`sources:write`). |
| `POST`   | `/v1/sources/{id}/sync`            | Sync now `{full}`; returns the import job, or the one already running. A manual sync commits a dataset version at once.                                 |
| `DELETE` | `/v1/sources/{id}`                 | Remove a source. Its dataset and versions stay.                                                                                                         |

A source feeds exactly one dataset; a dataset can have several sources, and deleting the dataset deletes them. A source starts at most one sync a minute: a manual sync within 60 seconds of the last one returns that sync with `Retry-After`. Schedules are five-field UTC cron; a scheduled sync commits a dataset version at most every `version_interval` seconds (default 900; 0 commits every sync). A failed sync sets `last_error` and backs the schedule off (twice its interval per consecutive failure, at most an hour); after 10 failures in a row the source's `status` becomes `paused`. A manual sync, or a new value for its secret, resumes it.

### Runs, checkpoints and artifacts

| Method   | Path                              | Purpose                                                                                                                                                                         |
| -------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST`   | `/v1/runs/plan`                   | Dry run at $0: resolve recipe defaults, check the data and estimate tokens and cost.                                                                                            |
| `POST`   | `/v1/runs`                        | Create and queue a training run. The run pins the dataset version.                                                                                                              |
| `GET`    | `/v1/runs` / `/v1/runs/{id}`      | List runs, newest first, or get one (status, `resolved_config`, `eval_report`, `artifact_id`).                                                                                  |
| `GET`    | `/v1/runs/{id}/metrics`           | Step metrics as JSON pages, or a live SSE stream with `Accept: text/event-stream`.                                                                                              |
| `GET`    | `/v1/runs/{id}/events`            | Lifecycle events (phases, metrics, checkpoints, attempts, warnings) as JSON pages, or SSE with `Accept: text/event-stream` (the event name is its `type`; a final `completed`). |
| `POST`   | `/v1/runs/{id}/cancel`            | Cancel a run. A running attempt is stopped and billed.                                                                                                                          |
| `POST`   | `/v1/runs/{id}/resume`            | Resume a stopped, failed or cancelled run from its latest checkpoint.                                                                                                           |
| `GET`    | `/v1/runs/{id}/checkpoints`       | List a run's unexpired checkpoints (best and final never expire).                                                                                                               |
| `POST`   | `/v1/checkpoints/{id}/promote`    | Copy a checkpoint into a new immutable artifact (`artifacts:write`).                                                                                                            |
| `GET`    | `/v1/artifacts`                   | List artifacts, newest first (filter with `name`).                                                                                                                              |
| `GET`    | `/v1/artifacts/{id}`              | Get an artifact by id, `name@version` or `name@latest`.                                                                                                                         |
| `DELETE` | `/v1/artifacts/{id}`              | Delete a released artifact and its bundle (204; `409 artifact_pinned` while a holder pins it).                                                                                  |
| `GET`    | `/v1/artifacts/{id}/download`     | Download the `.grad.tar.gz` bundle. Verify it against `X-Artifact-Sha256`.                                                                                                      |
| `GET`    | `/v1/artifacts/{id}/download-url` | A presigned GET of the bundle, valid 15 minutes: `{url, expires_at, sha256, size_bytes, filename}`. Browsers download from storage directly.                                    |
| `POST`   | `/v1/artifact-imports`            | Register uploaded files or a Hugging Face repo as an artifact (async import job, 202).                                                                                          |
| `GET`    | `/v1/artifact-imports/{id}`       | Get an artifact import (`queued`, `running`, `completed` or `failed`, with `artifact_id` once done).                                                                            |

Run status is `queued`, `running`, `completed`, `failed`, `cancelled`, `stopped_budget` (hit its `max_cost_usd`; resume with a higher cap) or `stopped_balance` (the Cloud workspace ran out of balance; resume after a top-up with the same cap). A queued run also carries `queue_position` and `queue_message` (why it waits), and every run has `min_gpu_memory_gb`, the GPU memory its plan needs.

An artifact import takes `{source, base_model, format?, name?}`. `source` is `{kind: "upload", upload_id}` (a tar of the files from `POST /v1/uploads`) or `{kind: "hf", repo, revision?, secret?}` (a branch, tag or commit, pinned on import; `secret` names a workspace secret holding a Hugging Face token). `format` defaults to `peft_lora`; `name` is required for uploads and defaults to the repo's name for Hub imports. A worker checks the files against the format and the base model; if they don't match, the import fails with `error_code: invalid_artifact` and an `error` naming the file. Every artifact's `provenance` says where it came from: `source` is `run` (with `run_id`), `upload` (with `uploader`) or `import` (with `uri`, `hf://owner/name@<commit>`).

### Evaluations

| Method | Path                           | Purpose                                                                                   |
| ------ | ------------------------------ | ----------------------------------------------------------------------------------------- |
| `POST` | `/v1/evals/plan`               | Estimate tasks, model and judge calls, and cost.                                          |
| `POST` | `/v1/evals`                    | Queue an eval of one or more models on a pinned dataset version.                          |
| `GET`  | `/v1/evals` / `/v1/evals/{id}` | List evals or get one with its summary.                                                   |
| `GET`  | `/v1/evals/{id}/outputs`       | Page through model outputs (filter by `model`, or by `missing_scorer` for local scorers). |
| `POST` | `/v1/evals/{id}/scores`        | Post scores from local SDK scorers. The eval completes when none are missing.             |
| `GET`  | `/v1/evals/{id}/results`       | Per-task, per-model results.                                                              |
| `GET`  | `/v1/evals/{id}/failures`      | Failing tasks, for mining into a new dataset.                                             |
| `POST` | `/v1/evals/{id}/cancel`        | Cancel a queued, running or `awaiting_scores` eval.                                       |

While a model call waits for capacity, `waiting_reason` says why: `capacity_unavailable` (the model's serving pool is starting), `rate_limited` or `inference_unavailable` (the endpoint is down); the eval keeps its place and fails only after `GRAD_EVAL_CAPACITY_WAIT_SECONDS` (12 minutes by default) per call.

### Serving

<DocsCallout label="Coming soon on Gradiated Cloud">Publishing artifacts as model versions isn't live yet. Today, download the artifact and serve it on vLLM or SGLang; see [Serve it yourself](/docs/training/deploying/#serve-it-yourself).</DocsCallout>

The training API keeps no serving state. Publishing an artifact as a model version is Gradiated Cloud's Models API, not this one (see [Deploying](/docs/training/deploying/)); self-hosted, download the artifact and serve it on vLLM or SGLang. grad has no routing, embedding or feedback API either. Call a published model through the inference endpoints above, and keep production outcomes in your observability tool (or the Gradiated gateway); a [source](/docs/training/trajectories/#send-feedback-from-production) syncs them into a dataset.

`/v1/trainer-jobs/*` is the internal protocol between the server and its workers, not part of the SDKs. Workers authenticate with a worker token (a static key, a Kubernetes service-account token or a lease token minted by an orchestrator), never a workspace key; see [Worker authentication](/docs/training/self-hosting/#worker-authentication).

### Usage

`GET /v1/usage` (`grad usage list`, `client.usage.list()`) lists the workspace's billing ledger, newest first. A run or eval attempt is billed in increments while it runs: every million tokens or five minutes, at each checkpoint and when it ends. A worker killed outright is billed up to its last progress report. Filter with `from`, `to`, `run_id` (the run's training plus the evals it started), `eval_id` and `kind`.

| Field                           | Meaning                                                                                                                                                                                                    |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `kind`                          | What the tokens paid for: `training`, `eval` (including a run's checkpoint evals), `scoring` (`dataset.score()`), `labeling` (a router run's labeling eval) or `teacher` (distillation's teacher answers). |
| `ref_id`, `ref_name`, `attempt` | The run or eval, its name, and the attempt the tokens belong to.                                                                                                                                           |
| `run_id`                        | The run billed: the run itself, or the run whose labeling, teacher or checkpoint eval this is.                                                                                                             |
| `tokens_from`, `tokens_through` | The attempt's token range this row covers; `tokens` is the difference.                                                                                                                                     |
| `cost_usd`, `price_version`     | The charge, and the version of the catalog price it was computed with.                                                                                                                                     |
| `billed_by`                     | `grad`, or `gateway`: on Gradiated Cloud, eval model and judge tokens are billed by the inference gateway with your inference usage, so they're listed here but not charged twice.                         |
| `idempotency_key`               | `run-usage:{id}:{attempt}:{tokens_through}` (`eval-usage:` for evals); unique.                                                                                                                             |
| `created_at`                    | When the increment was billed.                                                                                                                                                                             |

`GET /v1/usage/summary` (`grad usage`, `client.usage.summary()`) totals a period: `from` and `to` take `YYYY-MM-DD` or an ISO 8601 timestamp, in UTC. `from` is inclusive; a date `to` covers that whole day and a timestamp `to` is exclusive. The default is the current UTC month, and `from` at or after `to` is `422 invalid_period`. It returns the resolved `from` and `to`, `cost_usd`, `tokens` and `records`, `by_kind[]` (costliest first), and `top_runs[]` and `top_evals[]` (up to 5 each, with `id`, `name`, `kind`, `cost_usd` and `tokens`). With `group_by` (`day`, `week` from Monday, `month`, `model`, `recipe` or `kind`), `groups[]` has one `{key, cost_usd, tokens, records}` per group, oldest first for time groups and costliest first otherwise; `key` is null for usage with no recipe.

### API key scopes

`POST /v1/keys` takes `{name, scopes}`. A `:write` scope includes its `:read`, and `admin` includes every workspace scope.

| Scope                               | Grants                                                                                                                                                     |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `admin`                             | Everything in the workspace, including key management.                                                                                                     |
| `datasets:read`, `datasets:write`   | Datasets, records, render, uploads and imports.                                                                                                            |
| `runs:read`, `runs:write`           | Runs, checkpoints, evals, dataset scoring and usage.                                                                                                       |
| `artifacts:read`, `artifacts:write` | Reading and downloading artifacts; promoting checkpoints, uploading, importing and deleting artifacts.                                                     |
| `artifacts:pin`                     | Pinning and unpinning artifacts. Only `admin` implies it; the pin endpoints are internal (Gradiated Cloud's publishing calls them) and aren't in the SDKs. |
| `secrets:read`, `secrets:write`     | Secret metadata, and naming a secret in a source, import or run logger; setting and deleting secrets. Values are never readable.                           |
| `sources:read`, `sources:write`     | Sources and syncs.                                                                                                                                         |

`trainer:worker` is a platform scope for workers. `admin` never implies it, and `/v1/keys` can't mint it; self-hosted servers configure [worker authentication](/docs/training/self-hosting/#worker-authentication) instead.

On Gradiated Cloud, a key or console session gets the scopes of its member's role. `admin` can do everything. `member` can push and read datasets, create runs and evals, read, download, upload and promote artifacts, and read sources; secrets, source changes and publishing are admin-only.

### Idempotency

Every create accepts an `Idempotency-Key` header of up to 255 visible ASCII characters: datasets, record pushes, imports, artifact imports, sources, runs, evals and keys. The SDKs send a UUIDv4 on each call and reuse it on every retry, so POSTs are retried safely; pass your own key to make a rerun of your whole script safe too (Python `idempotency_key=`, TypeScript `{ idempotencyKey }`, Go `RunParams.IdempotencyKey` / `EvalParams.IdempotencyKey`, Rust `create(&req, Some(key))`, CLI `--idempotency-key`).

- The key is stored on the resource the request creates, in the same transaction. A retry with the same key and body returns that resource in its current state, with `Idempotent-Replayed: true`.
- The same key with a different body is 422 `idempotency_key_reused`; a malformed key is 422 `idempotency_key_invalid`.
- `POST /v1/keys` can't replay, because the secret is shown only once: a repeat gets 409 `idempotency_replay_unavailable`.
- Every other POST is idempotent by nature (cancel, resume, scores, sync) or read-only (plan, render).

```http
POST /v1/runs
Authorization: Bearer grad_...
Idempotency-Key: 5f0c8d1e-3b8a-4c39-9a4e-2f1f0b6f4a21
```

### Pagination

List endpoints take `limit` and `cursor` and return `{"data": [...], "next_cursor": ...}`. Pass `next_cursor` back as `cursor` for the next page; it is `null` on the last page. A `limit` above an endpoint's maximum is clamped, not rejected:

| Endpoint                                        | Default | Maximum |
| ----------------------------------------------- | ------- | ------- |
| Most lists                                      | 50      | 200     |
| `/v1/datasets/{name}/records`                   | 100     | 1000    |
| `/v1/runs/{id}/metrics`, `/v1/runs/{id}/events` | 1000    | 5000    |

`/v1/runs/{id}/metrics` also returns `tail_cursor`, the position after the newest point so far. Pass it back as `cursor` to poll for points written later. The SSE stream sends one `metric` event per point (event id = `seq`) and a final `status` event with the finished run; reconnect with `Last-Event-ID` to resume.

| 501    | `inference_unavailable` (no inference endpoint configured for evals), `keys_managed_by_cloud` (`/v1/keys` with `AUTH_MODE=cloud`), `secrets_unavailable` (no `GRAD_SECRETS_KEY`), `source_unavailable` (the `gradiated` source: Cloud-only, and coming soon there).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| 502    | `inference_error` (the inference or judge endpoint failed), `source_upstream_error`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 503    | `database_unavailable` and `storage_unavailable` (object storage unreachable; both with `Retry-After: 1`), `billing_unavailable` (Cloud: billing can't be reached, or the price list hasn't refreshed for 24 hours), `auth_unavailable` (Cloud: the control plane can't be reached and the key isn't cached; retry), `source_upstream_unavailable`. `GET /health/ready` answers `store_unavailable`. `shutting_down` (`/health/ready` on a draining replica); `inference_unavailable` when the endpoint is down for a moment (raised as `InferenceUnavailableError` too).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

The SDKs retry twice (0.5 s, doubling up to 8 s, with jitter) on 408, 429, 500, 502, 503 and 504, and on a 409 that carries `Retry-After`, for every GET, PUT and DELETE and every public POST (one `Idempotency-Key` across the retries). They never retry `429 queue_limit`, and a `Retry-After` over 60 s raises at once (Python `err.retry_after`, TypeScript `err.retryAfterMs`). They raise a typed error that carries `status`, `code`, `message` and `request_id`:

| --------------------------- | --------------------------------------- | --------------------------------------- | --------------------------------------------- | ------------------------------------- |

| 401                         | `AuthenticationError`                   | `AuthenticationError`                   | `*grad.AuthenticationError`                   | `Error::Authentication`               |

| 409                         | `ConflictError`                         | `ConflictError`                         | `*grad.ConflictError`                         | `Error::Conflict`                     |
| 413                         | `PayloadTooLargeError`                  | `APIError`                              | `*grad.APIError`                              | `Error::Validation`                   |
| 422                         | `ValidationError`                       | `ValidationError`                       | `*grad.ValidationError`                       | `Error::Validation`                   |
| 429                         | `RateLimitError`                        | `RateLimitError`                        | `*grad.RateLimitError`                        | `Error::RateLimit`                    |

`InferenceUnavailableError` is a kind of `FeatureUnavailableError`, so catching the latter covers every 501 (in Rust, match both `Error::InferenceUnavailable` and `Error::FeatureUnavailable`). Rust has one `grad::Error` enum: `Error::Api` is only the fallback for statuses without a variant, so read any API error with `err.api()`, `err.status()` and `err.code()`. Every SDK raises `QueueLimitError` (`Error::QueueLimit`) for `429 queue_limit` and never retries it. Before 0.2.0-alpha.5, TypeScript and Go raised a `ServerError` for other 501s, which read as "try again later".

`wait()` raises `RunFailedError`, `EvalFailedError` or `ImportFailedError` with the final object when a job ends unsuccessfully, and `WaitTimeoutError` when it gives up (after 24 hours by default). See the [Primitives reference](/docs/reference/primitives/#errors) for the rest.
