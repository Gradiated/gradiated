# Use Gradiated with Codex

<p className="docs-lead">
  Use a separate Codex profile for Gradiated. Your normal Codex provider and
  model stay unchanged.
</p>

## Set up automatically

Run the Gradiated wizard:

```sh
npx -y @gradiated/wizard --agent codex
```

The wizard detects Codex. It gets or validates your Gradiated API key. It
fetches the model catalog. It then adds a Gradiated provider and a separate
`gradiated` profile.

The wizard stores the key in `~/.gradiated/credentials.json`. It does not put
the key in the Codex configuration. It does not change your default Codex
profile.

Start Codex with the Gradiated profile:

```sh
codex --profile gradiated
```

## Set up manually

### Before you start

You need:

- An active Gradiated API key.
- A model ID from `GET https://api.gradiated.com/openai/v1/models`.
- Codex installed on your machine.

Set your key in the environment where you run Codex:

```sh
export GRADIATED_API_KEY="grad_..."
```

### Add the provider

Add this block to `~/.codex/config.toml`:

```toml
[model_providers.gradiated]
name = "Gradiated"
base_url = "https://api.gradiated.com/v1"
env_key = "GRADIATED_API_KEY"
wire_api = "responses"
```

Keep provider settings in the user-level file. Do not put them in a project
`.codex/config.toml` file.

### Add the profile

Create `~/.codex/gradiated.config.toml`:

```toml
model_provider = "gradiated"
model = "YOUR_MODEL_ID"
```

Replace `YOUR_MODEL_ID` with an ID from the Gradiated model catalog.

Start Codex with this profile:

```sh
codex --profile gradiated
```

Use `-m YOUR_MODEL_ID` with the profile to select another Gradiated model for
one run.

## Troubleshooting

- Check that `GRADIATED_API_KEY` is set in the shell that starts Codex.
- Check that the provider base URL is `https://api.gradiated.com/v1`.
- Check that the model ID matches the Gradiated catalog.
- Use `codex exec --profile gradiated --strict-config` to find configuration errors.
- Check that the workspace has billing capacity.
