# Use Gradiated with OpenCode

<p className="docs-lead">
  OpenCode can use Gradiated as a custom OpenAI-compatible provider.
</p>

## Set up automatically

Run the Gradiated wizard:

```sh
npx -y @gradiated/wizard --agent opencode
```

The wizard detects OpenCode. It gets or validates your Gradiated API key. It
fetches the model catalog. It then merges the Gradiated provider into your
OpenCode user configuration.

The wizard preserves your existing default model. It writes a backup before
it changes an existing configuration file.

Start OpenCode after the wizard finishes:

```sh
opencode
```

Run `/models` to select a Gradiated model.

## Set up manually

### Before you start

You need:

- An active Gradiated API key.
- A model ID from `GET /v1/models`. The gateway matches it without regard to letter case.
- OpenCode installed on your machine.

Set your key in the environment where you run OpenCode:

```sh
export GRADIATED_API_KEY="grad_..."
```

### Add Gradiated to `opencode.json`

Add this provider to your OpenCode config. Keep the file in your project or in your user config. Do not put the API key in the file.

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "gradiated": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Gradiated",
      "options": {
        "baseURL": "https://api.gradiated.com/openai/v1",
        "apiKey": "{env:GRADIATED_API_KEY}"
      },
      "models": {
        "YOUR_MODEL_ID": {
          "name": "Your model name"
        }
      }
    }
  }
}
```

Replace `YOUR_MODEL_ID` with an ID from the Gradiated model catalog. Model matching is case-insensitive.

The `@ai-sdk/openai-compatible` adapter targets `/v1/chat/completions`, which is the protocol Gradiated currently exposes.

### Select the model

Start OpenCode and run:

```text
/models
```

Choose the Gradiated provider. Then choose your model.

Run a small test task first:

```text
Explain the main function in this repository in three short bullet points.
```

### Add model limits when needed

OpenCode can use model limits to manage context and output. Add them when the model catalog provides these values:

```json
{
  "models": {
    "YOUR_MODEL_ID": {
      "name": "Your model name",
      "limit": {
        "context": 128000,
        "output": 4096
      }
    }
  }
}
```

Use the values for the selected model. Do not copy limits from another model.

## Troubleshooting

- Check that `GRADIATED_API_KEY` is set in the same shell that starts OpenCode.
- Check that `baseURL` is `https://api.gradiated.com/openai/v1`.
- Check that the model ID matches the catalog response.
- Check that the workspace has billing capacity.
- Run `opencode auth list` if OpenCode reports a provider authentication error.

## Uninstall

Remove Gradiated from OpenCode (and any other agent it is configured for) with:

```sh
npx -y @gradiated/wizard uninstall
```

The wizard shows everything it found and lets you pick what to remove. It
deletes the provider block and the stored credential, keeps a timestamped
backup of each changed file, and never touches your other providers or your
default model unless it was a `gradiated/*` one.

OpenCode's [provider documentation](https://opencode.ai/docs/providers/) covers custom provider settings and the `/models` command.
