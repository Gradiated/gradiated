# Artifacts

<DocsLead>Every training run saves a versioned `.grad` artifact with your trained weights and evaluation results.</DocsLead>

An **`Artifact`** subclasses `Model` and always points to **one** fixed version of a trained model (`support-router@2026-11-26-1`). Keeping saved artifacts separate from live [`Endpoint`](/docs/training/endpoints/)s means you can test a new version offline and roll back production in one command without touching weights.

| | **Artifact** | **[Endpoint](/docs/training/endpoints/)** |
| --- | --- | --- |
| **How many models?** | Always **1** fixed model version | **1 or more** artifacts |
| **Changes over time?** | Never; every new run creates a new `name@version` | Yes; shadow, canary, promote, or roll back in place |
| **Main uses** | Offline evals, batch scoring (`infer_batch`), RL sampling (`sample`), merging checkpoints | Live production traffic (`infer` / `route`), traffic splits, fallbacks, feedback capture |

## Inspect and test an artifact

Load any saved artifact with `client.artifacts.get(...)` (or use `run.artifact` straight from a finished run). Check its held-out `eval_report` or score a batch of examples offline before deploying:

```python
from grad import Grad, Record

client = Grad()
art = client.artifacts.get("coding-effort@2026-11-25-1")

print(art.eval_report)

preds = art.infer_batch([Record(messages=m) for m in eval_messages])
print(preds[0].logits)
```

Because `Artifact` subclasses `Model`, you can pass any trained artifact anywhere a `Model` is expected:

- **Warm-start a next stage:** `DPORecipe(model=sft.artifact, ...)` or `GRPORecipe(model=sft.artifact, ...)`.
- **Use as a verifier:** `Judge(name="sql_ok", model=verifier_artifact)` or `strategies.Cascade(verifier=verifier_artifact, ...)`.
- **Use as a distillation teacher:** `DistillRecipe(model=Model("Qwen/Qwen3-4B"), teacher=teacher_artifact)`.

## Deploy an artifact

Every `.grad` artifact stores its model type, source dataset, and default serving strategy in `manifest.json`. Deploy any run or pinned artifact to an [`Endpoint`](/docs/training/endpoints/) in one line:

## Merge artifacts without retraining

Combine two models trained from the same base (for example, a coding model and a reasoning model) into a single new `Artifact` with `client.artifacts.merge()`. Supported merge methods are `mergers.TIES`, `mergers.Linear`, `mergers.DARE`, and `mergers.SLERP`:

```python
from grad import Grad, mergers

client = Grad()
coder = client.artifacts.get("coder@v4")
reasoner = client.artifacts.get("reasoner@v2")

merged = client.artifacts.merge(
    name="assistant-merged",
    artifacts=[(coder, 0.6), (reasoner, 0.4)],
    merger=mergers.TIES(density=0.5),
)
```

## Download and portability

Every `.grad` artifact is a portable bundle (`manifest.json`, weight files such as ONNX or Safetensors, and `eval_report.json`). Download any artifact via `GET /v1/artifacts/{id}/download` or run it on your own infrastructure with [Self-hosting](/docs/training/self-hosting/).
