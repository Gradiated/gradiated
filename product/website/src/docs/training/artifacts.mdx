# Artifacts

<DocsLead>
  Every training run saves a versioned `.grad` artifact with your trained
  weights and evaluation results.
</DocsLead>

An **`Artifact`** is a saved, versioned model produced by a training run (`fast-diff-merge@2026-11-26-1`). Artifacts are never overwritten: every new run writes a new version with its weights (`adapter_config.json` and `adapter_model.safetensors` for LoRA, or full Safetensors weights) alongside its held-out `eval_report.json`.

## Inspect and test an artifact

Load any saved artifact with `client.artifacts.get(...)` (or use `run.artifact` straight from a finished run) and check its held-out `eval_report` before deploying. To compare it with other models on your own examples, pass it to an [evaluation](/docs/training/evaluations/):

```python
from grad import Grad

client = Grad()
art = client.artifacts.get("fast-diff-merge@2026-11-26-1")

print(art.base_model, art.recipe_kind)
print(art.eval_report)
```

You can pass a trained `Artifact` in place of a model name:

- **Continue training:** `DPORecipe(model=sft.artifact, ...)` or `SFTRecipe(model=sft.artifact, ...)` (from SFT and DPO LoRA artifacts).
- **Evaluate it:** `client.evals.create(models=[art, "qwen/qwen3-8b"], dataset=..., rubric=...)`.
- **Use as a judge:** `Judge(name="sql_ok", model=art, prompt="Is this SQL correct?")`.

## Which checkpoint becomes the artifact

Managed runs save checkpoints automatically as they train and evaluate each one on the held-out split. `run.artifact` is the checkpoint with the best eval score. To pick a different one yourself, list the checkpoints and promote it:

```python
from grad import Grad

client = Grad()
run = client.runs.get("run_01J9Z2")

for ckpt in run.checkpoints():
    print(ckpt.step, ckpt.eval_score, ckpt.expires_at)

art = run.checkpoints()[-1].promote(name="fast-diff-merge")  # save a checkpoint as a versioned Artifact
```

The best and final checkpoints never expire; other checkpoints are kept for 30 days unless you promote them. Each checkpoint remembers the settings it was trained with (base model, chat template, learning rate), so evaluations and deploys reuse them automatically. If a run stops early, continue it from its latest checkpoint with `client.runs.resume("run_01J9Z2")`. Checkpoint frequency, retention and selection settings are in the [reference](/docs/reference/training-parameters/#checkpoints-and-evaluation).

## Deploy on Gradiated Cloud or download weights

Every artifact can either be hosted directly on Gradiated Cloud (callable via the standard OpenAI / Anthropic / SystemOne SDKs) or downloaded as standard weights to run on your own vLLM or SGLang servers:

<DocsCodeTabs>
  <DocsCodeTab label="Gradiated Cloud">

```python
from grad import Grad

client = Grad()

# Publish under your-org/fast-diff-merge.
# From a finished run, `run.deploy()` does the same.
client.artifacts.get("fast-diff-merge@2026-11-26-1").deploy()
```

  </DocsCodeTab>
  <DocsCodeTab label="Self-host (vLLM / SGLang)">

```bash
# Download standard HuggingFace PEFT LoRA weights (or merged weights)
grad artifacts download fast-diff-merge@2026-11-26-1 --output ./fast-diff-merge

# Load straight into vLLM or SGLang:
vllm serve Qwen/Qwen3-8B --enable-lora --lora-modules fast-diff-merge=./fast-diff-merge
```

  </DocsCodeTab>
  <DocsCodeTab label="CLI">

```bash
grad artifacts inspect fast-diff-merge@2026-11-26-1 --json
grad deploy fast-diff-merge@2026-11-26-1
```

  </DocsCodeTab>
</DocsCodeTabs>

See [Deploying](/docs/training/deploying/) for updates, rollbacks, calling deployed models with the OpenAI / Anthropic / SystemOne SDKs, and self-hosting details.
