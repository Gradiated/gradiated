# Custom loops

<DocsLead>Write your own RL, preference, distillation, or representation training loop in Python using the exact same typed adapters, losses, and optimizers that power Gradiated's recipes.</DocsLead>

Custom loops give you direct access to the primitives behind Gradiated's [recipes](/docs/training/recipes/). Your loop runs on any CPU machine (your laptop, CI, or an orchestrator) and drives remote `Trainer` and `Artifact` endpoints over HTTP.

Install the Python SDK with the optional `torch` extra when writing client-side `CustomLoss` subclasses:

```bash
pip install "grad-sdk[torch]"
```

## Mental model

- **`Trainer`** owns mutable weights and optimizer state on the server. Open it in a `with client.trainers.create(model=..., adapter=...) as trainer:` block so the remote trainer session closes cleanly on exit or error. Training is billed strictly **per million tokens processed** (forward/backward and sampling) plus storage for saved weights and checkpoints — never idle GPU time.
- **`trainer.snapshot()`** returns an immutable, ephemeral [**`Artifact`**](/docs/training/endpoints/) pointing at the current weights. Call `sample()`, `score_logprobs()`, `infer_batch()`, or `embed()` on it while training continues.
- **`trainer.export(name=...)`** writes a durable `.grad` **`Artifact`** ready to deploy on an [**`Endpoint`**](/docs/training/endpoints/).

## Universal 1:1 token alignment

Most training APIs force you to shift `input[:-1]` against `targets[1:]` and pad prompts manually — a single off-by-one mistake silently trains on the wrong tokens. In `grad`, every per-token array on a `Datum` (`loss_mask`, `sampling_logprobs`, `ref_logprobs`, `advantages`, and `out.logprobs`) has the **exact same length `T` as `tokens`**:

<DocsTokenAlignment />

`Artifact.sample()`, `Artifact.score_logprobs()`, `Artifact.to_datum()`, [`Trajectory.append_env_tokens()`](/docs/reference/primitives/), and [`Trajectory.to_datum()`](/docs/reference/primitives/) all preserve this invariant automatically.

### Chat templates and assistant-only masking

For multi-turn chat or tool-use SFT, let the server render the model's exact chat template and attach `loss_mask` (`0.0` on system, user, and tool turns; `1.0` on assistant turns) in one call via `base.to_datum()`:

```python
base = client.models.get("Qwen/Qwen3-8B")

datum = base.to_datum(

        {"role": "assistant", "content": "SELECT count(*) FROM users WHERE active_at >= current_date - 1;"},

    tools=tool_schemas,
)
```

## Example 1: Multi-turn GRPO loop

This loop runs rollouts in a [stateful environment](/docs/training/environments/), normalizes rewards per prompt group via `grad.group_datums()` (skipping zero-variance groups automatically), updates LoRA weights with `losses.GRPO`, and exports a merged artifact. See the [RL for agents guide](/docs/training/recipes/rl-agents/) for swapping in DAPO, Dr. GRPO (`norm="mean"`), RLOO (`norm="rloo"`), async CISPO, or sequence-level GSPO.

```python
import grad
from grad import Grad, Model, adapters, losses, optim

client = Grad()

with client.trainers.create(
    model=Model("Qwen/Qwen3-8B"),
    adapter=adapters.LoRA(rank=32),
) as trainer:
    for step, task_batch in enumerate(batches):
        snap = trainer.snapshot()
        groups = env.rollout_groups(
            artifact=snap,
            tasks=task_batch,
            group_size=8,
            max_turns=6,
            max_new_tokens=512,
            max_concurrency=8,
        )

        # Group-normalize rewards and skip zero-variance groups (norm="std" | "mean" | "rloo")
        datums = grad.group_datums(groups, norm="std", skip_zero_var=True)

        # Queue both calls before waiting to pipeline execution across one RTT.
        fb = trainer.forward_backward(datums, loss=losses.GRPO(clip_low=0.2, clip_high=0.28))
        opt = trainer.optim_step(optim.AdamW(lr=2e-5, grad_clip=1.0))

        metrics = fb.result()
        opt.result()
        print(f"step={step} loss={metrics.loss:.4f} grad_norm={metrics.metrics['grad_norm']:.3f}")

    artifact = trainer.export(name="code-agent-grpo", merge_adapter=True)
    print(artifact.id)
```

<DocsCallout label="Built-in RL numerics diagnostics" tone="tip">
On every `losses.GRPO`, `losses.CISPO`, or `losses.ImportanceSampling` step, `fb.result().metrics` reports `kl_sample_train` and `sample_train_max_diff` — comparing the sampler's exact `sampling_logprobs` against the trainer's recomputed logprobs so you spot off-policy staleness or tokenizer mismatches immediately.
</DocsCallout>

Passing an empty `datums` list (when every group in a batch has identical rewards) is a safe no-op.

## Example 2: Custom objectives via `losses.CustomLoss`

You do not need a separate API method or a server-side enum to test a new objective. Subclass `losses.CustomLoss` (declaring which `outputs` you need and implementing `compute(self, datums, out)`), and pass it to the **exact same `trainer.forward_backward(datums, loss=...)`** — or inject it into any `Recipe`!

Under the hood, `Trainer` fetches only the declared differentiable outputs from `/forward`, pre-populates aligned PyTorch views (`out.masks` with `mask[0] == 0.0`, `out.sampling_logprobs`, `out.ref_logprobs`, `out.advantages`, `out.turn_ids`, and auto-batched `out.teacher_topk_logprobs`), runs `compute()` locally, and sends exact gradients back to `/backward-surrogate`. No untrusted user code runs on GPU workers, and gradients match native PyTorch `.backward()` bit-for-bit.

Here is shuffle-safe, reference-free SimPO using `grad.by_group()` and `grad.masked_mean()`:

```python
import torch
import torch.nn.functional as F
import grad
from grad import Grad, adapters, losses, optim

class SimPOLoss(losses.CustomLoss):
    outputs = ("logprobs",)

    def __init__(self, beta: float = 2.0, gamma: float = 0.5):
        self.beta = beta
        self.gamma = gamma

    def compute(self, datums, out) -> torch.Tensor:
        terms = []
        for g in grad.by_group(datums, out):
            c, r = g["chosen"], g["rejected"]
            margin = grad.masked_mean(c.logprobs, c.mask) - grad.masked_mean(r.logprobs, r.mask)
            terms.append(-F.logsigmoid(self.beta * margin - self.gamma))
        return torch.stack(terms).mean()

client = Grad()
base = client.models.get("Qwen/Qwen3-8B")

preference_pairs = [
    base.to_datum(
        messages=[
            {"role": "user", "content": "Explain tail latency in one sentence."},
            {"role": "assistant", "content": "Tail latency is the response time of the slowest few percent of requests."},
        ],
        group_id="p0",
        role="chosen",
    ),
    base.to_datum(
        messages=[
            {"role": "user", "content": "Explain tail latency in one sentence."},
            {"role": "assistant", "content": "Latency is when computers wait a long time for packets to arrive."},
        ],
        group_id="p0",
        role="rejected",
    ),
]

with client.trainers.create(model=base, adapter=adapters.LoRA(rank=32)) as trainer:
    fb = trainer.forward_backward(preference_pairs, loss=SimPOLoss(beta=2.0, gamma=0.5))
    trainer.optim_step(optim.AdamW(lr=5e-5)).result()
    print(fb.result().loss)
```

### Compact top-k distillation with `gather_indices`

Never pull full 152k-vocabulary logits over the wire for custom distillation. Ask the teacher for `top_k=32` opaque `TensorRef`s and declare `outputs = ("topk_logprobs",)` on your `CustomLoss` — passing `gather_indices=t_refs` returns only the matching `(T_resp, 32)` student logprobs and auto-batch-fetches `out.teacher_topk_logprobs` in a single RPC (for arbitrary intermediate layer `TensorRef`s, use `client.tensors.fetch_batch(refs)`):

```python
teacher = client.models.get("Qwen/Qwen3-32B")

t_refs = teacher.score_logprobs(
    prefixes,
    response_tokens=responses,
    top_k=32,
).topk_refs

fb = trainer.forward_backward(datums, loss=SkewKLLoss(alpha=0.1), gather_indices=t_refs)
```

For multi-turn trajectories with no single prompt/response boundary, pass the `Trajectory` list directly to `score_logprobs`:

```python
ref_lps = ref_artifact.score_logprobs(trajectories).aligned_logprobs
datums = [t.to_datum(advantage=a, ref_logprobs=r) for t, a, r in zip(trajectories, advs, ref_lps)]
```

### Pause, resume, and stage transitions

- **Stage transitions (`SFT → DPO`, `SFT → GRPO`):** pass the previous stage's `Artifact` as `model=` to start with those weights and a fresh optimizer.
- **Pause and resume mid-run:** save optimizer moments and step count with `trainer.save_state()`, and restore everything cleanly via `client.trainers.resume(ckpt)`:

```python
ckpt = trainer.save_state(name="code-agent-step-500")

# Resume the exact same run (weights + optimizer moments + step count):
with client.trainers.resume(ckpt) as resumed:
    ...

# Or start a fresh stage from exported weights (fresh optimizer):
sft_art = client.artifacts.get("code-agent@sft-v1")
with client.trainers.create(model=sft_art, adapter=adapters.LoRA(rank=32)) as grpo_trainer:
    ...
```

### Gradient accumulation, LR schedules, and held-out eval

Because `forward_backward()` accumulates gradients on the trainer until `optim_step()` runs, multi-microbatch accumulation and per-step cosine schedules take four lines:

```python
import math

def cosine_lr(step: int, total_steps: int, max_lr: float = 2e-4, min_lr: float = 2e-5) -> float:
    return min_lr + 0.5 * (max_lr - min_lr) * (1.0 + math.cos(math.pi * step / total_steps))

# Accumulate 4 microbatches before one optimizer update
futs = [trainer.forward_backward(mb, loss=losses.CrossEntropy()) for mb in microbatches]
trainer.optim_step(optim.AdamW(lr=cosine_lr(step, total_steps), grad_clip=1.0)).result()
mean_loss = sum(f.result().loss for f in futs) / len(futs)

# Run held-out eval without retaining autograd graphs on the GPU
eval_out = trainer.forward(val_datums, outputs=("logprobs",), retain_graph=False)
```

### High-concurrency async rollouts (`AsyncGrad`)

When driving hundreds of concurrent tool-calling or browser rollouts in `asyncio`, use `AsyncGrad` so rollout coroutines overlap with training steps without thread-pool overhead:

```python
import asyncio
import grad
from grad import AsyncGrad, Model, adapters, losses, optim

async def train_async(batches):
    async with AsyncGrad() as client:
        async with client.trainers.create(model=Model("Qwen/Qwen3-8B"), adapter=adapters.LoRA(rank=32)) as trainer:
            for task_batch in batches:
                snap = await trainer.snapshot()
                groups = await asyncio.gather(
                    *(run_async_group(snap, task) for task in task_batch)
                )
                datums = grad.group_datums(groups, norm="std")

                fb = await trainer.forward_backward(datums, loss=losses.GRPO())
                opt = await trainer.optim_step(optim.AdamW(lr=2e-5, grad_clip=1.0))
                metrics, _ = await asyncio.gather(fb.result(), opt.result())
                print(metrics.loss)
```

### Multimodal (VLM and audio) inputs

Pass image or audio `MediaRef`s directly to `base.to_datum()` — the server handles model-specific vision/audio preprocessing and special token expansion so you never need a client-side image processor:

```python

img = MediaRef(kind="image", ref="s3://my-bucket/screens/checkout_step2.png")
```

## Example 3: Multi-stage heads, differential LRs, and weight merges

- **Freeze Stage-1 heads in Stage 2:** set `trainable=False` on `heads.Linear(...)`.
- **Differential learning rates (e.g. LoRA+):** pass `param_groups=[optim.ParamGroup(...)]` to `optim.AdamW`.
- **Continual learning anchor (L2-SP / EWC):** pass `weight_anchor=optim.WeightAnchor(...)`.
- **Zero-train-token weight merging:** combine checkpoints with `client.artifacts.merge()`.

```python
from grad import Grad, adapters, heads, optim

stage1 = client.artifacts.get("reward-model@stage1")

with client.trainers.create(
    model=stage1,
    adapter=adapters.FrozenHead(),
    heads={
        "attrs": heads.Linear(dim=5, trainable=False),
        "gate": heads.Linear(dim=5, trainable=True),
    },
) as trainer:
    trainer.forward_backward(datums, loss=GatingBTLoss()).result()
    trainer.optim_step(
        optim.AdamW(
            param_groups=[optim.ParamGroup(match="extra_heads.gate", lr=5e-3)],
            weight_anchor=optim.WeightAnchor(artifact=stage1, strength=0.01),
        )
    ).result()

coder = client.artifacts.get("coder@v4")
reasoner = client.artifacts.get("reasoner@v2")

merged = client.artifacts.merge(
    name="assistant-merged",
    artifacts=[coder, reasoner],
    weights=[0.6, 0.4],
    method="ties",
    density=0.5,
)
```

## Closed-form and convex fits (`fit_batch`)

Routers, linear probes, and representation steering vectors do not need SGD. Extract cached embeddings once with `Model.embed()` and solve in a single `fit_batch()` call with a typed `Solver`:

```python
from grad import Datum, DatumTargets, Grad, ModelInput, adapters, solvers

client = Grad()
encoder = client.models.get("BAAI/bge-small-en-v1.5")

embeddings = encoder.embed(inputs, pool="mean").embeddings
embedding_datums = [
    Datum(
        ModelInput(embedding=emb.tolist()),
        DatumTargets(scalar=label),
        metadata={"action_id": model_id},
    )
    for emb, label, model_id in zip(embeddings, labels, model_ids)
]

with client.trainers.create(model=encoder, adapter=adapters.FrozenHead()) as trainer:
    trainer.fit_batch(embedding_datums, solver=solvers.DualHeadKernelLBFGS(l2=0.1))
    router_artifact = trainer.export(name="support-router")
```

## Reference tables

### Built-in `losses.*` classes

| Class | Use it for |
| --- | --- |
| `losses.CrossEntropy(heads=...)` | Next-token SFT respecting `loss_mask`; optionally pass `heads={"k1": HeadCE(shift=2, weight=0.8), ...}` for server-side Medusa / multi-token prediction without sending vocab logits over HTTP. |
| `losses.BCEWithLogits()` | Binary or multi-label head classification. |
| `losses.OrdinalBCE()` | Ordered tier classification (`low < medium < high`). |
| `losses.L2Logistic()` | Regularized logistic heads. |
| `losses.DPO(beta=0.1)` | Paired preference optimization (`group_id` + `chosen` / `rejected`). |
| `losses.ImportanceSampling(kl_beta=0.0)` | Unclipped importance-weighted policy gradient for on-policy or lightly off-policy RL. |
| `losses.GRPO(clip_low=0.2, clip_high=0.28, kl_beta=0.0)` | Clipped policy-gradient RL with optional KL penalty. |
| `losses.CISPO(clip_low=0.2, clip_high=0.28)` | Stop-gradient clipped importance sampling for off-policy or async rollouts. |
| `losses.ReverseKLDistill()` | Token-level reverse-KL distillation against `ref_logprobs`. |
| `losses.TopKKLDistill(top_k=32)` | Distillation against `teacher_topk` (`TensorRef` or multi-teacher weighted list). |
| `losses.InfoNCE(temp=0.05)` | Contrastive embedding training (`anchor` / `positive` / `negative`). |
| `losses.BCESparsePositions(head="prm")` | Token-level or step-level heads at explicit `positions` (PRMs, prompt compression). |
| `losses.CustomLoss` *(base class)* | Subclass to run any client-side PyTorch objective with exact surrogate gradients. |

### Built-in `adapters.*` dataclasses

| Class | What gets trained |
| --- | --- |
| `adapters.FrozenHead()` | Backbone frozen; trains only attached `heads`. |
| `adapters.LoRA(rank=32, alpha=64)` | Low-rank adapters + trainable `heads`. |
| `adapters.DoRA(rank=32, alpha=64)` | Weight-decomposed LoRA (magnitude + direction). |
| `adapters.QLoRA(rank=32)` | 4-bit NF4 quantized backbone + LoRA adapters. |
| `adapters.PrefixKV(num_tokens=256)` | Backbone frozen; trains only prepended KV prefix tokens (Cartridges). |
| `adapters.LoReFT(layers=[...], rank=4)` | Backbone frozen; trains orthogonal low-rank residual-stream interventions. |
| `adapters.Eagle3Draft(fusion_layers=[...])` | Frozen target trunk + multi-layer speculative draft fusion head. |
| `adapters.PartialUnfreeze(last_n_layers=1)` | Top `N` transformer layers + `ln_f` + trainable `heads`. |
| `adapters.Full()` | All backbone parameters + trainable `heads`. |
