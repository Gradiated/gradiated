# Deploying

<DocsLead>
  Host trained artifacts on Gradiated Cloud in one command, or download standard
  weights to run on your own vLLM or SGLang servers.
</DocsLead>

Every training run produces a versioned [`Artifact`](/docs/training/artifacts/) (such as `fast-diff-merge@2026-11-26-1`). From there, pick whichever serving path fits your stack:

<DocsDeployFlow />

## Option 1: Host on Gradiated Cloud

On Gradiated Cloud, you don't need to manage GPUs or a serving stack. You can call any saved artifact immediately by its pinned version, or deploy it behind a stable model name so you can update versions without redeploying your app.

### Deploy behind a stable model name

`run.deploy()` (or `grad deploy`) publishes your artifact under `your-org/<name>` on Gradiated's inference gateway. Your app calls the exact same [OpenAI SDK](/docs/openai-sdk/), [Anthropic SDK](/docs/anthropic-sdk/), or [SystemOne SDK](/docs/systemone-sdk/) you already use; you only change the `model` string. The endpoint uses the same pinned chat template and `thinking` setting the artifact was trained with, and reasoning models return their reasoning in `reasoning_content`, separate from `content`:

<DocsCodeTabs action={<DocsApiKeyAction />}>
  <DocsCodeTab label="Python">

```python
import os
from openai import OpenAI
from grad import Grad

# 1. Deploy your trained artifact
client = Grad()
artifact = client.artifacts.get("fast-diff-merge@2026-11-26-1")
artifact.deploy()

# 2. Call it with the standard OpenAI SDK (only `model` changes)
oai = OpenAI(
    base_url="https://api.gradiated.com/v1",
    api_key=os.environ["GRADIATED_API_KEY"],
)
res = oai.chat.completions.create(
    model="your-org/fast-diff-merge",
    messages=[{"role": "user", "content": "Merge these two diffs into one patch: ..."}],
)
print(res.choices[0].message.content)
```

  </DocsCodeTab>
  <DocsCodeTab label="TypeScript">

```ts
import OpenAI from "openai";
import { Grad } from "@gradiated/grad";

// 1. Deploy your trained artifact
const grad = new Grad();
const artifact = await grad.artifacts.get("fast-diff-merge@2026-11-26-1");
await artifact.deploy();

// 2. Call it with the standard OpenAI SDK (only `model` changes)
const oai = new OpenAI({
  baseURL: "https://api.gradiated.com/v1",
  apiKey: process.env.GRADIATED_API_KEY,
});
const res = await oai.chat.completions.create({
  model: "your-org/fast-diff-merge",
  messages: [
    { role: "user", content: "Merge these two diffs into one patch: ..." },
  ],
});
console.log(res.choices[0].message.content);
```

  </DocsCodeTab>
  <DocsCodeTab label="Go">

```go
artifact, _ := client.Artifacts.Get(ctx, "fast-diff-merge@2026-11-26-1")
_, _ = artifact.Deploy(ctx)
// Then pass "your-org/fast-diff-merge" as `model` in your OpenAI or Anthropic client.
```

  </DocsCodeTab>
  <DocsCodeTab label="CLI">

```bash
# First deploy (publishes your-org/fast-diff-merge)
grad deploy fast-diff-merge@2026-11-26-1

# Next retrain: deploy the new version, check status, or roll back in one command
grad deploy fast-diff-merge@2026-12-03-1
grad deployments status fast-diff-merge
grad deployments rollback fast-diff-merge
```

  </DocsCodeTab>
</DocsCodeTabs>

For [Decision models](/docs/training/recipes/decision-model/), pass `"your-org/<name>"` straight to `TypeSafeClient` (`/v1/systemone`). For [Embeddings](/docs/training/recipes/embeddings/), pass it to `openai.embeddings.create(model="your-org/<name>", ...)`. For [Model routers](/docs/training/recipes/router/), pass it to the OpenAI or Anthropic SDK, or call `client.route("support-router", ...)` if you dispatch to your own providers.

### Updates and rollback

Because every [`Artifact`](/docs/training/artifacts/) is a fixed version, rolling forward or rolling back on Gradiated Cloud is a single pointer update with no app redeploy:

<DocsTerminal
  title="Deployment status"
  command="grad deployments status fast-diff-merge"
>

```text
Model     your-org/fast-diff-merge
Active    art_9d41c7e2a05b3f8816e2c4d7
Previous  art_3f9c0a1b2c3d4e5f60718293
Status    active
Fallback  -
Explore   0
```

</DocsTerminal>

Deploying a new version qualifies the adapter on a serving replica first, then atomically switches `your-org/fast-diff-merge` to the new version. If anything looks wrong, `grad deployments rollback fast-diff-merge` (or `client.deployments.rollback("fast-diff-merge")`) points the name back at the previous artifact. To go back further, deploy any earlier version (`grad deploy fast-diff-merge@2026-11-26-1`).

### Feed production back into training

The Gradiated gateway records every request to your deployed model, along with its feedback, so you don't need a separate observability tool. Connect them to a dataset with the built-in `gradiated` [source](/docs/training/trajectories/#sync-from-observability-providers): each sync adds a new dataset version with the latest traces and scores, ready for your next run.

If you already log to Langfuse, LangSmith, Braintrust, Phoenix or PostHog, keep sending feedback there and sync it the same way. See [Send feedback from production](/docs/training/trajectories/#send-feedback-from-production).

## Option 2: Run on your own vLLM or SGLang

If you already run your own inference infrastructure (or self-host training in your VPC), download the trained artifact directly. Deploying is a Gradiated Cloud feature; a [self-hosted](/docs/training/self-hosting/) server answers `deploy` with `501 deploy_unavailable`. LoRA runs export standard HuggingFace PEFT weights (`adapter_config.json` and `adapter_model.safetensors`), and `merge_on_export=True` exports standalone merged Safetensors weights.

<DocsCodeTabs>
  <DocsCodeTab label="vLLM">

```bash
grad artifacts download fast-diff-merge@2026-11-26-1 --output ./fast-diff-merge

vllm serve Qwen/Qwen3-8B \
  --enable-lora \
  --lora-modules fast-diff-merge=./fast-diff-merge
```

  </DocsCodeTab>
  <DocsCodeTab label="SGLang">

```bash
grad artifacts download fast-diff-merge@2026-11-26-1 --output ./fast-diff-merge

python -m sglang.launch_server \
  --model-path Qwen/Qwen3-8B \
  --lora-paths fast-diff-merge=./fast-diff-merge
```

  </DocsCodeTab>
</DocsCodeTabs>

Handle traffic splitting and rollbacks with whatever you already use in your stack (feature flags, Envoy/Nginx weights, or Argo Rollouts). Log requests and feedback to your observability tool and [sync them](/docs/training/trajectories/#sync-from-observability-providers) into a dataset to train your next version.
