# Endpoints

<DocsLead>Serve trained artifacts behind a stable endpoint name, roll out new versions safely, and log real-world outcomes.</DocsLead>

An **`Endpoint`** is a named production URL backed by one or more [`Artifact`](/docs/training/artifacts/)s. Your app always calls the same name (`support-router`, `coding-effort`, `fast-diff-merge`), while you shadow-test, canary, promote, or roll back artifacts behind it without redeploying your code.

## Deploy in one line (or configure explicitly)

Every `.grad` [`Artifact`](/docs/training/artifacts/) knows its model type, source dataset, and default serving settings. For most cases, `run.deploy()` (or `artifact.deploy()` / `grad deploy`) creates the endpoint on the first deploy and updates traffic splits after that:

<DocsCodeTabs>
  <DocsCodeTab label="Python">

```python
endpoint = run.deploy(canary=0.10)
```

  </DocsCodeTab>
  <DocsCodeTab label="TypeScript">

```ts
const endpoint = await run.deploy({ canary: 0.1 });
```

  </DocsCodeTab>
  <DocsCodeTab label="Go">

```go
endpoint, _ := run.Deploy(ctx, grad.DeployOpts{Canary: 0.10})
```

  </DocsCodeTab>
  <DocsCodeTab label="CLI">

```bash
# First deploy (creates `support-router` with artifact defaults)
grad deploy support-router@latest

# Subsequent deploys: shadow -> 10% canary -> 100% active (or instant rollback)
grad deploy support-router@2026-11-26-1 --shadow
grad deploy support-router@2026-11-26-1 --canary 0.10
grad endpoints status support-router --watch
grad deploy support-router@2026-11-26-1 --active
```

  </DocsCodeTab>
</DocsCodeTabs>

When you want to set a custom fallback model, quality limit, or multi-model setup, pass your [`Artifact`](/docs/training/artifacts/), [`Dataset`](/docs/training/trajectories/), `Model`, and `Strategy` to `client.endpoints.create()`:

<DocsCodeTabs action={<DocsApiKeyAction />}>
  <DocsCodeTab label="Python">

```python
from grad import Grad, Model, strategies

client = Grad()
artifact = client.artifacts.get("support-router@2026-11-25-1")
capture = client.datasets.get("support-prod")

router = client.endpoints.create(
    slug="support-router",
    artifact=artifact,
    capture_dataset=capture,
    strategy=strategies.SLALagrangian(
        fallback=Model("claude-opus-4-7"),
        max_quality_drop=0.02,
    ),
)

decision = router.route(messages=messages, tools=tools)
reply = call_your_llm(decision.model, messages, tools)
```

  </DocsCodeTab>
  <DocsCodeTab label="TypeScript">

```ts
import { Grad, Model, strategies } from "@gradiated/grad";

const grad = new Grad();
const artifact = await grad.artifacts.get("support-router@2026-11-25-1");
const capture = await grad.datasets.get("support-prod");

const router = await grad.endpoints.create({
  slug: "support-router",
  artifact,
  captureDataset: capture,
  strategy: strategies.slaLagrangian({
    fallback: new Model("claude-opus-4-7"),
    maxQualityDrop: 0.02,
  }),
});

const decision = await router.route({ messages, tools });
const reply = await callYourLLM(decision.model, messages, tools);
```

  </DocsCodeTab>
  <DocsCodeTab label="Go">

```go

```

If an endpoint times out or hits its safety limit, it automatically falls back to your configured backup model so requests keep working. See [errors, limits, and retries](/docs/errors/) for status codes and retries.

## Record feedback

Every endpoint call returns an `inference_id` and saves a [`Trajectory`](/docs/training/trajectories/) to `capture_dataset`. Call `.record_feedback(...)` right on the response if you know the outcome immediately, or call `client.feedback.record(inference_id=...)` later from a background job once a test finishes or a support ticket closes:

<DocsCodeTabs>
  <DocsCodeTab label="Python">

```python
# Inline right after inference:
merged.record_feedback(
    idempotency_key=f"pr-{pr_number}-check-1",
    score=1.0 if tests_passed else 0.0,
    expected_output={"merged_code": human_fix} if human_fix else None,
    metrics={"cost_usd": 0.0012, "latency_ms": 480},
)

# Or later from an async webhook worker with only the stored inference_id:
# client.feedback.record(inference_id=saved_inference_id, score=1.0)
```

  </DocsCodeTab>
  <DocsCodeTab label="TypeScript">

```ts
await merged.recordFeedback({
  idempotencyKey: `pr-${prNumber}-check-1`,
  score: testsPassed ? 1.0 : 0.0,
  expectedOutput: humanFix ? { merged_code: humanFix } : undefined,
  metrics: { cost_usd: 0.0012, latency_ms: 480 },
});

// Or later from an async webhook worker with only the stored inferenceId:
// await grad.feedback.record({ inferenceId: savedInferenceId, score: 1.0 });
```

  </DocsCodeTab>
  <DocsCodeTab label="Go">

```go
_ = merged.RecordFeedback(ctx, grad.Feedback{
	IdempotencyKey: fmt.Sprintf("pr-%d-check-1", prNumber),
	Score:          score,
	Metrics:        map[string]float64{"cost_usd": 0.0012, "latency_ms": 480},
})
```

  </DocsCodeTab>
  <DocsCodeTab label="cURL">

```bash
curl https://api.gradiated.com/v1/feedback \
  -H "Authorization: Bearer $GRADIATED_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "events": [{
      "inference_id": "inf_01J9Y",
      "idempotency_key": "pr-481-check-1",
      "score": 1.0,
      "metrics": {"cost_usd": 0.0012, "latency_ms": 480}
    }]
  }'
```

  </DocsCodeTab>
</DocsCodeTabs>

Duplicate submissions with the same `idempotency_key` are ignored safely. Feedback updates live canary metrics right away and attaches to the saved `Trajectory` for your next training run.

## Shadow, canary, and rollback

Because every [`Artifact`](/docs/training/artifacts/) is a fixed version, promoting a new model or rolling back to an old one is a single command with no redeploy:

```bash
# 1. Shadow: run the new artifact silently alongside active traffic (0% user impact)
grad deploy support-router@2026-11-26-1 --shadow

# 2. Canary: shift 10% of requests and watch live quality and cost deltas
grad deploy support-router@2026-11-26-1 --canary 0.10
grad endpoints status support-router --watch

# 3. Promote to 100%, or roll back to any earlier version in one command
grad deploy support-router@2026-11-26-1 --active
grad deploy support-router@2026-11-25-1 --active
```

## Serving strategies

A `Strategy` controls how an endpoint picks models, checks outputs, and falls back when something looks wrong. Pick a built-in strategy from `strategies.*` or subclass `Strategy` to write your own:

<DocsEndpointDiagram />

| Strategy class | Artifacts | What it does | Guide |
| --- | --- | --- | --- |
| `strategies.Direct()` | 1 | Calls the active artifact directly. | [Model distillation](/docs/training/recipes/distillation/) |
| `strategies.SLALagrangian(...)` | 1 | Routes to the cheapest model that meets your quality target, monitors live quality against your fallback, and switches back to the fallback if quality drops too far. | [Model router](/docs/training/recipes/router/) |
| `strategies.ConfidenceFallback(...)` | 1 | Returns a safe fallback label or model whenever decision-model confidence is below your threshold. | [Decision models](/docs/training/recipes/decision-model/) |
| `strategies.SyntaxFallback(...)` | 1–2 | Checks generated output against a JSON schema or code parser and retries on a fallback model if it is invalid. | [Supervised fine-tuning (SFT)](/docs/training/recipes/sft/) |
| `strategies.Cascade(...)` | 2–3 | Generates a fast draft, scores it with a [reward model](/docs/training/recipes/reward-models/), and escalates to a stronger model only when the score is low. | [RL for agents](/docs/training/recipes/rl-agents/) |
| `strategies.BestOfN(...)` / `MajorityVote(...)` | 1–2 | Generates `N` answers and returns the majority answer or the highest-scoring one. | [Reward models](/docs/training/recipes/reward-models/) |
| `strategies.BudgetForcing(...)` | 1 | Caps or extends how many reasoning tokens a model uses at inference time. | [Custom loops](/docs/training/custom-loops/) |

### Multi-artifact example: cascade

```python
from grad import Model, strategies

sql_agent = client.artifacts.get("sql-8b@v3")
verifier = client.artifacts.get("sql-verifier@v2")

client.endpoints.create(
    slug="sql-assistant",
    artifact=sql_agent,
    strategy=strategies.Cascade(
        verifier=verifier,
        frontier=Model("Qwen/Qwen3-32B"),
        threshold=0.75,
    ),
)
```

## Routing directly through the inference gateway

On Gradiated Cloud, you don't need a separate API call to route requests. Pass `"model": "<org>/<endpoint-slug>"` straight to `/v1/chat/completions`, `/v1/responses`, or `/v1/messages` in the [OpenAI SDK](/docs/openai-sdk/) or [Anthropic SDK](/docs/anthropic-sdk/). Gradiated runs your router inside the gateway, forwards to the chosen model, and returns `x-gradiated-inference-id`, `x-gradiated-action`, and `x-gradiated-artifact` headers so you can still log feedback.
