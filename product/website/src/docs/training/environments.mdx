# Environments

<DocsLead>Run your agent against your own tools, databases, or containers during reinforcement learning.</DocsLead>

Environments run **on your own machines** (a laptop or Kubernetes) and talk to Gradiated's [`Artifact`](/docs/training/artifacts/) and [`Trainer`](/docs/training/custom-loops/) APIs over HTTP. Your containers, seed data, and internal credentials stay inside your network.

## `Task`, `Environment`, and `Rubric`

| Concept | What it does | How they fit together |
| --- | --- | --- |
| **`Task`** | One problem to solve: `id`, starting `messages` and `tools`, `seed` data (commit SHA, DB fixture, or Harbor task path), optional `expected` answer, and `timeout_s`. Build one from a log with `Task.from_trajectory(t)`. | You pass many `Task`s to a run. |
| **`Environment[H]`** | Runs a `Task` in an isolated sandbox (`setup`), executes the agent's tool calls (`step`), runs your [`Rubric`](/docs/training/rubrics/) before cleanup (`evaluate`), and tears down the sandbox (`teardown`). | One `Environment` runs thousands of `Task`s. |
| **[`Rubric`](/docs/training/rubrics/)** | Grades how well the agent did using `Scorer`s, `Judge`s, `StatefulScorer`s, or `GroupScorer`s and writes results into `trajectory.scores`. | Passed into the `Environment` (or paired with per-task test scripts like Harbor's `tests/test.sh`). |

<DocsCallout label="Starting from production logs?" tone="tip">
You don't need to build a simulator from scratch to use RL. See [Traces to environments](/docs/training/recipes/traces-to-environments/) to turn an existing [`Dataset`](/docs/training/trajectories/) into simple tasks, mock tool sandboxes, or Harbor containers.
</DocsCallout>

## Built-in adapters (`environments.*`)

If your tasks already use a standard format or tool server, plug them straight in with a built-in adapter instead of writing boilerplate:

### Harbor / Terminal-Bench (`environments.Harbor`)

Load Harbor task folders (`instruction.md`, `task.toml`, `environment/Dockerfile`, `tests/test.sh`, and optional `solution/solve.sh`) straight into `Task` objects. `environments.Harbor` starts a fresh container for each attempt, keeps `tests/` hidden until `evaluate()` runs so the model cannot cheat, reads test scores into `trajectory.scores`, and lets you sanity-check every reference solution before paying for training:

```python
from grad import environments

tasks = environments.Harbor.load_tasks("./harbor-tasks/")
env = environments.Harbor(rubric=extra_rubric)  # combines tests/test.sh + optional Rubric

# Smoke-test every task's solution/solve.sh oracle (and verify initial state fails)
verified = env.verify_oracles(tasks, require_initial_fail=True)

groups = env.rollout_groups(
    artifact=trainer.snapshot(),
    tasks=verified[:16],
    group_size=8,
    max_turns=12,
    max_concurrency=8,
)
```

### Other built-in adapters

| Adapter | Use it for |
| --- | --- |
| **`environments.Harbor`** | Harbor / Terminal-Bench task folders (`task.toml`, `instruction.md`, `environment/Dockerfile`, `tests/test.sh`, `solution/solve.sh`). |
| **`environments.MCP`** | Expose tools from any Model Context Protocol server directly to the model; `step()` calls MCP `call_tool` and keeps tool responses excluded from training loss. |
| **`environments.DockerCompose`** | Multi-container stacks (Postgres, Redis, API) with a warm pool and fast template-database resets. |
| **`environments.from_gym(make_env)`** | Wrap any Gymnasium environment (`reset` → `setup`, `step` → `step`, `close` → `teardown`). |

## Writing a custom `Environment`

When an agent changes live state (writing to Postgres, calling an internal API, or editing files), each parallel run needs its own isolated sandbox and reliable cleanup. `Environment` runs four methods in order so your [`Rubric`](/docs/training/rubrics/) checks live state **before** anything is torn down:

<DocsEnvLifecycle />

1. **`setup(task, rollout_id)`:** start or borrow an isolated sandbox and seed its initial state.
2. **`step(handle, action)`:** run the agent's tool call against `handle` and return `Observation(text=..., done=...)`.
3. **`evaluate(handle, trajectory)`:** score the run **while containers are still up** so `StatefulScorer` checks can query Postgres, Redis, or your API.
4. **`teardown(handle)`:** stop containers or reset the database. `rollout_groups()` always runs `teardown` in a `finally:` block, even on a timeout or crash.

```python
import subprocess
from dataclasses import dataclass
from grad import Environment, Observation, Rubric, Task

@dataclass
class ComposeHandle:
    project: str
    base_url: str
    db_url: str

class AppComposeEnv(Environment[ComposeHandle]):
    def __init__(self, compose_file: str, rubric: Rubric):
        super().__init__(rubric)
        self.compose_file = compose_file

    def setup(self, task: Task, rollout_id: str) -> ComposeHandle:
        project = f"grad_{rollout_id}"
        subprocess.run(
            ["docker", "compose", "-p", project, "-f", self.compose_file, "up", "-d", "--wait"],
            check=True,
        )
        subprocess.run(
            ["./scripts/seed.sh", project, task.seed["fixture_id"]],
            check=True,
        )
        api_port = get_mapped_port(project, "api", 8080)
        db_port = get_mapped_port(project, "postgres", 5432)
        return ComposeHandle(
            project=project,
            base_url=f"http://127.0.0.1:{api_port}",
            db_url=f"postgres://postgres:postgres@127.0.0.1:{db_port}/app",
        )

    def step(self, handle: ComposeHandle, action) -> Observation:
        tool_call = parse_tool_call(action.text)
        if tool_call is None:
            return Observation(done=True)

        obs_text = execute_tool_against_api(handle.base_url, tool_call)
        return Observation(text=obs_text, done=False)

    def evaluate(self, handle: ComposeHandle, trajectory) -> dict[str, float]:
        # Runs BEFORE teardown so StatefulScorer terms can query `handle.db_url`.
        self.rubric.score(trajectory, state=handle)
        return trajectory.scores

    def teardown(self, handle: ComposeHandle) -> None:
        subprocess.run(
            ["docker", "compose", "-p", handle.project, "-f", self.compose_file, "down", "-v", "--remove-orphans"],
            check=False,
        )
```

<DocsCallout label="Tool outputs stay read-only" tone="tip">
Just return plain text from `step()` with `Observation(text=...)`. Gradiated feeds it back to the model as context for the next turn while automatically excluding it from training updates, with no local tokenizer or manual masking needed.
</DocsCallout>

### Faster resets with a warm pool

Cold-starting `docker compose up` per rollout works for small runs, but a warm pool is 10–50x faster during RL:

- Boot `N` stacks once (matching `max_concurrency`) and lease a slot in `setup()`.
- Restore Postgres from a pre-seeded template database (`DROP DATABASE app; CREATE DATABASE app TEMPLATE seed_v1;`) and flush Redis, typically in under 50 ms.
- Return the slot to the pool in `teardown()`.

## Plug in an existing OpenAI-based agent

Already have an agent built on the OpenAI SDK, LangGraph, or your own loop? Wrap `trainer.snapshot()` with `snap.openai_client()`. Every chat completion runs against the current training weights and records a `Trajectory` automatically, with no rewrite needed:

```python
snap = trainer.snapshot()

with snap.openai_client() as (openai_client, recorder):
    result = await my_existing_agent.run(task, client=openai_client)

traj = recorder.to_trajectory(scores={"reward": grade(result, task)}).with_targets(advantage=adv)
```

## Running rollouts

Run `env.rollout_groups()` against any base model (`"qwen/qwen3-8b"`) for offline evals, or against an [`Artifact`](/docs/training/artifacts/) (such as `trainer.snapshot()`) inside an online RL loop.

```python
groups = env.rollout_groups(
    artifact=trainer.snapshot(),
    tasks=task_batch,
    group_size=8,
    max_turns=6,
    max_new_tokens=512,
    max_concurrency=8,
    timeout_s=60,
)
```

Every run handles three things automatically:

- **Tool outputs stay read-only:** tool responses and retrieved docs are excluded from training updates so the model only learns from its own tokens.
- **Concurrency limits:** `max_concurrency` caps how many sandboxes run at once so you don't run out of CPU or RAM.
- **Timeout cleanup:** runs that hit `timeout_s` are cancelled, get a score of `0.0`, and still run `teardown()`.
