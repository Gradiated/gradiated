# Environments

<DocsLead>Run multi-turn RL rollouts against Harbor benchmarks, MCP servers, Docker Compose stacks, or your existing OpenAI-compatible agent harness — right on your own infrastructure.</DocsLead>

Environments run **outside the GPU training cluster**, on your own CPU machines, Kubernetes cluster, or sandbox pool, and call Gradiated [`Model` / `Artifact`](/docs/training/artifacts/) and [`Trainer`](/docs/training/custom-loops/) endpoints over HTTP. Your containers, seed scripts, and internal credentials never leave your network.

## `Task`, `Environment`, and `Rubric`

| Entity | Responsibility | Relationship |
| --- | --- | --- |
| **`Task`** | One immutable problem instance: `id`, initial `messages`/`tools`, environment `seed` (repo SHA, DB fixture, or Harbor task path), optional `expected` reference, and `timeout_s`. Convert from a trace via `Task.from_trajectory(t)`. | Many `Task`s per run. |
| **`Environment[H]`** | The execution harness that turns any `Task` into an isolated handle `H` (`setup`), runs agent tool calls (`step`), invokes your [`Rubric`](/docs/training/rubrics/) before cleanup (`evaluate`), and destroys resources (`teardown`). | 1 `Environment` executes thousands of `Task`s. |
| **[`Rubric`](/docs/training/rubrics/)** | Weighted grading logic combining deterministic `Scorer`s, `Judge`s, `StatefulScorer`s, and `GroupScorer`s into `trajectory.scores`. | Passed into the `Environment` (and/or combined with per-task test scripts like Harbor's `tests/test.sh`). |

<DocsCallout label="Starting from production traces?" tone="tip">
You do not need a hand-built simulator to start RL. See [Building an environment from traces](/docs/training/traces-to-environments/) to turn a [`Dataset`](/docs/training/trajectories/) of traces into single-turn `Task`s, local mock/replay tool sandboxes, or verified Harbor benchmarks.
</DocsCallout>

## Standard formats and adapters (`environments.*`)

You rarely need to write container or protocol plumbing from scratch. Standard task formats and tool harnesses plug straight into `Environment` via built-in adapters:

### Harbor / Terminal-Bench (`environments.Harbor`)

Load standard Harbor task directories (`instruction.md`, `task.toml`, `environment/Dockerfile`, `tests/test.sh`, and optional `solution/solve.sh`) directly into typed `Task` objects. `environments.Harbor` boots the container per rollout, isolates `tests/` until `evaluate()` runs (so the agent can never inspect test files during rollouts), parses verifier rewards into `trajectory.scores`, and lets you verify every task's oracle solution before spending training tokens:

```python
from grad import environments

tasks = environments.Harbor.load_tasks("./harbor-tasks/")
env = environments.Harbor(rubric=extra_rubric)  # combines tests/test.sh + optional Rubric

# Smoke-test every task's solution/solve.sh oracle (and verify initial state fails)
verified = env.verify_oracles(tasks, require_initial_fail=True)

groups = env.rollout_groups(
    artifact=trainer.snapshot(),
    tasks=verified[:16],
    group_size=8,
    max_turns=12,
    max_concurrency=8,
)
```

### Other built-in adapters

| Adapter | Use it for |
| --- | --- |
| **`environments.Harbor`** | Standard Harbor / Terminal-Bench task directories (`task.toml`, `instruction.md`, `environment/Dockerfile`, `tests/test.sh`, `solution/solve.sh`). |
| **`environments.MCP`** | Expose any Model Context Protocol server's tools directly to the policy; `step()` invokes MCP `call_tool` and keeps tool responses read-only automatically. |
| **`environments.DockerCompose`** | Multi-service stacks (Postgres, Redis, API) with warm-pool slot leasing and fast template-database resets. |
| **`environments.from_gym(make_env)`** | Wrap any Gymnasium environment (`reset` → `setup`, `step` → `step`, `close` → `teardown`). |

## Writing a custom stateful `Environment`

When an agent modifies live state (inserting rows in Postgres, calling an internal API, or editing files), each parallel rollout needs isolation and guaranteed cleanup. `Environment` runs four hooks in strict order so your [`Rubric`](/docs/training/rubrics/) inspects live container state **before** cleanup:

<DocsEnvLifecycle />

1. `setup(task, rollout_id)` — start or lease an isolated environment and run your seed script.
2. `step(handle, action)` — run the agent's tool call against `handle` and return `Observation(text=..., done=...)`.
3. `evaluate(handle, trajectory)` — score the trajectory **while the environment is still running** so `StatefulScorer` terms can query Postgres, Redis, or your API.
4. `teardown(handle)` — stop containers or reset the database. `rollout_groups()` always runs `teardown` in a `finally:` block, even on timeout or error.

```python
import subprocess
from dataclasses import dataclass
from grad import Environment, Observation, Rubric, Task

@dataclass
class ComposeHandle:
    project: str
    base_url: str
    db_url: str

class AppComposeEnv(Environment[ComposeHandle]):
    def __init__(self, compose_file: str, rubric: Rubric):
        super().__init__(rubric)
        self.compose_file = compose_file

    def setup(self, task: Task, rollout_id: str) -> ComposeHandle:
        project = f"grad_{rollout_id}"
        subprocess.run(
            ["docker", "compose", "-p", project, "-f", self.compose_file, "up", "-d", "--wait"],
            check=True,
        )
        subprocess.run(
            ["./scripts/seed.sh", project, task.seed["fixture_id"]],
            check=True,
        )
        api_port = get_mapped_port(project, "api", 8080)
        db_port = get_mapped_port(project, "postgres", 5432)
        return ComposeHandle(
            project=project,
            base_url=f"http://127.0.0.1:{api_port}",
            db_url=f"postgres://postgres:postgres@127.0.0.1:{db_port}/app",
        )

    def step(self, handle: ComposeHandle, action) -> Observation:
        tool_call = parse_tool_call(action.text)
        if tool_call is None:
            return Observation(done=True)

        obs_text = execute_tool_against_api(handle.base_url, tool_call)
        return Observation(text=obs_text, done=False)

    def evaluate(self, handle: ComposeHandle, trajectory) -> dict[str, float]:
        # Runs BEFORE teardown so StatefulScorer terms can query `handle.db_url`.
        self.rubric.score(trajectory, state=handle)
        return trajectory.scores

    def teardown(self, handle: ComposeHandle) -> None:
        subprocess.run(
            ["docker", "compose", "-p", handle.project, "-f", self.compose_file, "down", "-v", "--remove-orphans"],
            check=False,
        )
```

<DocsCallout label="Tool outputs stay read-only" tone="tip">
Just return plain text from `step()` with `Observation(text=...)`. Gradiated feeds it back to the model as context for the next turn while automatically excluding it from training updates — no local tokenizer or manual masking needed.
</DocsCallout>

### Faster resets with a warm pool

Cold-starting `docker compose up` per rollout works for small runs, but a warm pool is 10–50x faster during RL:

- Boot `N` stacks once (matching `max_concurrency`) and lease a slot in `setup()`.
- Restore Postgres from a pre-seeded template database (`DROP DATABASE app; CREATE DATABASE app TEMPLATE seed_v1;`) and flush Redis, typically in under 50 ms.
- Return the slot to the pool in `teardown()`.

## Plug in an existing OpenAI-based agent

Already have an agent built on the OpenAI SDK, LangGraph, or an existing coding-agent harness? Wrap any live `trainer.snapshot()` with `snap.openai_client()` — every chat completion runs against the snapshot and automatically records an exact `Trajectory` with zero agent rewrite:

```python
snap = trainer.snapshot()

with snap.openai_client() as (openai_client, recorder):
    result = await my_existing_agent.run(task, client=openai_client)

traj = recorder.to_trajectory(scores={"reward": grade(result, task)}).with_targets(advantage=adv)
```

## Running rollouts

Run `env.rollout_groups()` against any `Model` or [`Artifact`](/docs/training/artifacts/): a base model (`client.models.get(...)`) for offline evals, or `trainer.snapshot()` inside an online RL loop.

```python
groups = env.rollout_groups(
    artifact=trainer.snapshot(),
    tasks=task_batch,
    group_size=8,
    max_turns=6,
    max_new_tokens=512,
    max_concurrency=8,
    timeout_s=60,
)
```

Every rollout enforces three guarantees automatically:

- **Read-only tool outputs:** tool responses and retrieved documents are automatically excluded from training updates so gradients apply only to tokens generated by the model.
- **Bounded concurrency:** `max_concurrency` caps active stacks so large rollout groups do not exhaust CPU or memory.
- **Timeout cleanup:** rollouts exceeding `timeout_s` are cancelled, assigned `reward = 0.0`, and still run `teardown()`.
