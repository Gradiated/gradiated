# Training overview

<DocsLead>Train routers, classifiers, reward models, and fine-tuned or RL-tuned LLMs from traces or live environments. Start in three lines, and drop down into full PyTorch loops whenever you need to.</DocsLead>

<DocsCodeTabs action={<DocsApiKeyAction />}>
  <DocsCodeTab label="CLI">

```bash
grad import ./support_traces.jsonl --dataset support-prod
grad train --dataset support-prod --name support-router --wait
grad deploy support-router@latest --canary 0.10
```

  </DocsCodeTab>
  <DocsCodeTab label="Python">

```python
from grad import Grad

client = Grad()
client.trajectories.import_file("./support_traces.jsonl", dataset="support-prod").wait()

run = client.runs.create(dataset="support-prod", name="support-router").wait()
endpoint = run.deploy(canary=0.10)
```

  </DocsCodeTab>
  <DocsCodeTab label="TypeScript">

```ts
import { Grad } from "@gradiated/grad";

const grad = new Grad();
await grad.trajectories.importFile("./support_traces.jsonl", { dataset: "support-prod" }).wait();

const run = await grad.runs.create({ dataset: "support-prod", name: "support-router" }).wait();
const endpoint = await run.deploy({ canary: 0.1 });
```

  </DocsCodeTab>
</DocsCodeTabs>

Already sending inference requests through Gradiated with the `x-gradiated-task` header? Skip `import` — your dataset is populated automatically, so you go straight to `grad train` and `grad deploy`.

The CLI and SDKs read `GRADIATED_API_KEY` automatically (create one in the [quickstart](/docs/quickstart/)) and target `https://api.gradiated.com`. To run locally instead, start the open-source server with Docker Compose:

```bash
grad local up
export GRAD_BASE_URL=http://localhost:8787
```

`grad local up` starts the API server on `:8787`, Postgres, Valkey, and a CPU trainer worker — enough for routers, classifiers, and trace syncing. Pass `--gpu` on a CUDA machine for LLM fine-tuning and RL, and run `grad local down` to stop the stack.

## Call your endpoint and close the loop

`run.deploy()` (and `grad deploy`) reads the artifact's manifest to configure its default serving strategy, fallback model, and capture dataset. Call the endpoint in your app and send outcomes back so live traffic feeds the next training run:

<DocsCodeTabs>
  <DocsCodeTab label="CLI">

```bash
# Watch live canary quality, offload %, and cost savings
grad endpoints status support-router --watch

# Promote to 100% when metrics hold, or roll back in one command
grad deploy support-router@2026-11-25-1 --active
```

  </DocsCodeTab>
  <DocsCodeTab label="Python">

```python
decision = client.router("support-router").route(messages=messages, tools=tools)
reply = call_your_llm(decision.model, messages, tools)

client.feedback.record(
    inference_id=decision.inference_id,
    score=1.0 if user_resolved else 0.0,
    metrics={"cost_usd": reply.cost_usd, "latency_ms": reply.latency_ms},
)
```

## Progressive control (Level 0 → 1 → 2)

Start at Level 0. Move down a level only when you need control the level above does not expose.

| Level | How it works | When to use it |
| --- | --- | --- |
| [**Level 0 — Automatic**](/docs/training/recipes/) | Pass a dataset and name. Gradiated inspects the data, selects a recipe and compute target, trains, and runs a held-out evaluation. | You have traces or labeled examples and want a measured baseline fast. |
| [**Level 1 — Managed recipes**](/docs/training/recipes/) | Pick a recipe ([router](/docs/training/recipes/router/), [classifier](/docs/training/recipes/classifier/), [sft](/docs/training/recipes/sft-dpo/), [dpo](/docs/training/recipes/sft-dpo/), [grpo](/docs/training/recipes/rl-agents/), [distill](/docs/training/recipes/distillation/), [cartridge](/docs/training/recipes/distillation/)) with typed top-level config or checked-in YAML. | You want explicit, reproducible runs in Git or CI without maintaining a training loop. |
| [**Level 2 — Custom loops**](/docs/training/custom-loops/) | Drive `Trainer`, `Artifact`, `Environment`, and `Rubric` directly in Python with built-in losses or client-side PyTorch losses. | You need custom losses, stateful Docker Compose environments, reward models, or custom RL curricula. |

Every Level 0 run exports its exact resolved Level 1 YAML (`grad runs inspect <run_id> --yaml`), so graduating from automatic training to checked-in config takes one command.

## The five primitives

Every concept in `grad` maps to one of five non-overlapping primitives:

| Primitive | What it is | Main operations |
| --- | --- | --- |
| [**Trajectory**](/docs/training/trajectories/) *(in a Dataset)* | A recorded interaction: production traces, labeled `(input, expected_output)` pairs, multimodal inputs, or multi-turn RL rollouts. | `import`, `push`, `sync`, `to_datum()` |
| [**Environment & Rubric**](/docs/training/environments/) | An optional test harness (Docker Compose stack, sandbox, tool server) and scoring functions that grade trajectories. | `setup()`, `step()`, `evaluate()`, `teardown()` |
| [**Trainer**](/docs/training/custom-loops/) *(driven by a [Recipe](/docs/training/recipes/))* | The CPU or GPU worker that updates model weights and writes checkpoints. | `runs.create()`, `fit_batch()`, `forward_backward()`, `optim_step()`, `snapshot()`, `export()` |
| [**Artifact**](/docs/training/endpoints/) *(a `.grad` bundle)* | Always one immutable, versioned model: a base model, a trained checkpoint, or an ephemeral RL snapshot. | `infer()`, `infer_batch()`, `sample()`, `score_logprobs()`, `embed()`, `merge()` |
| [**Endpoint**](/docs/training/endpoints/) | A named production serving slot over one or more artifacts, with canary splits, guardrails, and automatic trajectory capture. | `deploy()`, `create()`, `infer()`, `feedback()`, `promote()`, `status()` |

## Using with coding agents

The `grad` CLI and docs are built for autonomous agent loops as well as human developers:

- **Machine-readable docs:** every page is served as plain Markdown at `<url>.md`, indexed in [`/llms.txt`](/llms.txt) and `/llms-full.txt`.
- **Structured CLI output:** pass `--json` to any `grad` command for a single JSON envelope on stdout and deterministic exit codes.
- **Zero-cost pre-flight checks:** run `grad train ... --dry-run --json` (or `client.runs.plan(...)`) to validate dataset coverage, preview the resolved recipe, and estimate compute before spending GPU time.

```bash
# Safe autonomous loop: pre-flight check -> train -> inspect eval -> canary deploy
grad train --dataset support-prod --name support-router --dry-run --json
grad train --dataset support-prod --name support-router --wait --json
grad deploy support-router@latest --canary 0.10 --json
```

## Local vs. Gradiated Cloud

The HTTP API, `.grad` artifact format, recipes, and SDKs are identical locally and on Gradiated Cloud.

| Component | Local (`grad local up`) | Gradiated Cloud |
| --- | --- | --- |
| Base URL | `http://localhost:8787` | `https://api.gradiated.com` |
| Training worker | Local CPU container (`--gpu` for CUDA) | Managed CPU and GPU pools |
| Storage | Local volume or MinIO | Encrypted S3 |
| Serving | Local ONNX runtime + optional local LLM container | Hosted runtime + zero-hop gateway routing |
