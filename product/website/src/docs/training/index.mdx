# Training overview

<DocsLead>Train routers, classifiers, reward models, and fine-tuned or RL-tuned LLMs from traces or live environments. Start in three lines, and drop down into full PyTorch loops whenever you need to.</DocsLead>

  <DocsCodeTab label="Python">

```python

client = Grad()
client.trajectories.import_file("./support_traces.jsonl", dataset="support-prod").wait()

run = client.runs.create(dataset="support-prod", name="support-router", recipe="router").wait()
endpoint = run.deploy(canary=0.10)
```

## Call your endpoint and close the loop

`run.deploy()` (and `grad deploy`) reads the artifact's manifest to configure its default serving strategy, fallback model, and capture dataset. Call the endpoint in your app and record outcomes so live traffic feeds the next training run:

<DocsCodeTabs>
  <DocsCodeTab label="Python">

```python
decision = client.router("support-router").route(messages=messages, tools=tools)
reply = call_your_llm(decision.model, messages, tools)

client.feedback.record(
    inference_id=decision.inference_id,
    score=1.0 if user_resolved else 0.0,
    metrics={"cost_usd": reply.cost_usd, "latency_ms": reply.latency_ms},
)
```

  </DocsCodeTab>
  <DocsCodeTab label="TypeScript">

```ts
const decision = await grad.router("support-router").route({ messages, tools });
const reply = await callYourLLM(decision.model, messages, tools);

await grad.feedback.record({
  inferenceId: decision.inferenceId,
  score: userResolved ? 1.0 : 0.0,
  metrics: { cost_usd: reply.costUsd, latency_ms: reply.latencyMs },
});
```

  </DocsCodeTab>
  <DocsCodeTab label="Go">

```go

	Messages: messages,
```

## Two ways to train

Start with a managed recipe and its built-in defaults. Drop down to custom loops only when you need control a recipe does not expose.

| Mode | How it works | When to use it |
| --- | --- | --- |
| [**Managed recipes**](/docs/training/recipes/) | Pick a recipe ([router](/docs/training/recipes/router/), [classifier](/docs/training/recipes/classifier/), [sft](/docs/training/recipes/sft-dpo/), [dpo](/docs/training/recipes/sft-dpo/), [grpo](/docs/training/recipes/rl-agents/), [distill](/docs/training/recipes/distillation/), [cartridge](/docs/training/recipes/distillation/)). Start with defaults in one call, then pass typed fields or checked-in YAML to tune base model, adapter, loss, optimizer, split, or filters. | You want fast, reproducible training and held-out evals without maintaining a training loop. |
| [**Custom loops**](/docs/training/custom-loops/) | Drive `Trainer`, `Artifact`, `Environment`, and `Rubric` directly in Python with built-in losses or client-side PyTorch losses. | You need custom losses, stateful Docker Compose environments, reward models, or custom RL curricula. |

Any managed run can export its full resolved defaults as YAML (`grad runs inspect <run_id> --yaml > recipe.yaml`), so moving from defaults to version-controlled config takes one command.

<DocsCallout label="Rule of thumb" tone="tip">
Start at the cheapest layer that proves value: a CPU router or classifier on existing traces takes seconds and often cuts frontier spend by 50%+. Move to GPU SFT, distillation, or RL once you have a measured baseline and a clean held-out eval.
</DocsCallout>

## Using with coding agents

Every docs page includes **Copy page** (raw Markdown) and **Copy prompt** (a ready-to-paste coding-agent prompt) in the top right, and every page is served as plain Markdown at `<url>.md`, indexed in [`/llms.txt`](/llms.txt) and `/llms-full.txt`.

The CLI is designed for non-interactive agent loops: pass `--json` to any `grad` command for a single JSON envelope on stdout, and run `--dry-run --json` (or `client.runs.plan(...)`) to validate dataset coverage and estimate compute before spending GPU time.

### Starter prompts to paste into Claude Code, Codex, or Cursor

<DocsCodeTabs>
  <DocsCodeTab label="Model router">

```text
Read https://gradiated.com/docs/training/recipes/router.md and integrate a Gradiated model router into this codebase:
1. Find where we call LLMs and inspect how we log or store completed requests and outcomes.
2. Push or import historical traces into a Gradiated dataset using GRADIATED_API_KEY from env.
3. Run `grad train --dataset <name> --name <router> --recipe router --dry-run --json` first and fix any data warnings.
4. Train the router, verify `eval_report.pareto_summary.quality_drop_ci95` stays inside 2%, and deploy with `grad deploy <router>@latest --canary 0.10`.
5. Wire `grad.router("<router>").route(...)` and `grad.feedback.record(...)` with idempotency keys.
```

  </DocsCodeTab>
  <DocsCodeTab label="Fine-tune (SFT & DPO)">

```text
Read https://gradiated.com/docs/training/recipes/sft-dpo.md and set up a fine-tuning pipeline for our task:
1. Export verified passing examples into a Gradiated dataset (`input.messages`, `expected_output`, `session_id`, and `scores`).
2. Create a checked-in `recipe.yaml` for `recipe: sft` with `split.strategy: by_session` and a score filter.
3. Validate with `grad train -f recipe.yaml --dry-run --json` before running on GPU.
4. Deploy behind a `syntax_fallback` endpoint and wire `feedback.record()` so human fixes are captured as `expected_output`.
```

  </DocsCodeTab>
  <DocsCodeTab label="RL agent (Docker Compose)">

```text
Read https://gradiated.com/docs/training/environments.md and https://gradiated.com/docs/training/recipes/rl-agents.md:
1. Subclass `grad.Environment` around our existing `docker-compose.yml` and seed script (`setup`, `step` returning `Observation(text=...)`, `evaluate` before `teardown`, and guaranteed `teardown`).
2. Write a `Rubric` with deterministic stateful assertions against the live container state.
3. Run a 2-task smoke test against a base `Artifact` (`max_concurrency=2`) to verify `loss_mask` masks tool outputs and containers clean up cleanly.
4. Wire a GRPO / async CISPO custom loop using `with client.trainers.create(...) as trainer:`.
```

  </DocsCodeTab>
  <DocsCodeTab label="Distill / Cartridge">

```text
Read https://gradiated.com/docs/training/recipes/distillation.md:
1. Identify our high-volume frontier prompts or repeated long system prompts.
2. Write a flat YAML recipe for on-policy `distill` (32B teacher -> 4B/8B student) or `cartridge` (`prefix_kv` over our static context).
3. Validate with `grad train -f recipe.yaml --dry-run --json`, run training, compare `eval_report` against the baseline, and deploy with `--shadow` first.
```
