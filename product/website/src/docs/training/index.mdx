  <DocsCodeTab label="Fine-tune a model (60s)">

```python
from grad import Grad
from grad.recipes import SFTRecipe

client = Grad()  # reads GRADIATED_PROFILE or GRADIATED_API_KEY

# Plain chat records (the OpenAI fine-tuning format). The last assistant turn is what the model learns.
dataset = client.datasets.push("sql-quickstart", [
    {"messages": [
        {"role": "user", "content": "Count active users from yesterday."},
        {"role": "assistant", "content": "SELECT count(*) FROM users WHERE active_at >= current_date - 1;"},
    ]},
    {"messages": [
        {"role": "user", "content": "Total revenue by plan this month."},
        {"role": "assistant", "content": "SELECT plan, sum(amount_usd) FROM invoices WHERE created_at >= date_trunc('month', current_date) GROUP BY plan;"},
    ]},
])

recipe = SFTRecipe(model="qwen/qwen3-8b")

# $0 preview: resolved defaults, warnings, tokens and cost
print(client.runs.plan(dataset=dataset, name="sql-helper", recipe=recipe))

run = client.runs.create(dataset=dataset, name="sql-helper", recipe=recipe, max_cost_usd=5).wait()
run.download("./sql-helper")  # LoRA weights for vLLM / SGLang
```

Two examples are enough to see the whole loop. The plan warns that they leave no eval split and too few steps to train a useful model. For a real run, pass a file or a Hugging Face dataset instead of a list: `client.datasets.push("sql", "./train.jsonl")` or `client.datasets.from_hf("HuggingFaceH4/ultrachat_200k", split="train_sft")`.

## Install and connect

`grad` is open source under the MIT license. Its packages are published with the first release: `grad-sdk` on PyPI and crates.io, `@gradiated/grad` on npm, `github.com/Gradiated/grad/sdks/go` on the Go module proxy, and the `grad` CLI as `grad-cli`. Until then, install from a checkout:

```bash
git clone https://github.com/Gradiated/grad
```

```bash
npm install ./grad/sdks/typescript
```

  </DocsCodeTab>

```bash
go get github.com/Gradiated/grad/sdks/go
```

  </DocsCodeTab>
  <DocsCodeTab label="Rust">

```bash
cargo add grad-sdk --path ./grad/sdks/rust
```

  </DocsCodeTab>
  <DocsCodeTab label="CLI">

```bash
cargo install --locked --path ./grad/cli
```

  </DocsCodeTab>
</DocsCodeTabs>

Then start a local stack (it needs Docker with the Compose plugin) and point the CLI and SDKs at it:

```bash
grad local up --build   # build the images from the checkout
export GRADIATED_PROFILE=local
grad models list
```

`grad local up` saves its URL and keys in the `local` profile of `~/.config/gradiated/config.json`, and `GRADIATED_PROFILE=local` selects it in the CLI and every SDK. See [Self-hosting](/docs/training/self-hosting/) for the local stack's options, GPUs and the Kubernetes Helm chart.

For any other server, run `grad login` (it saves the key in the `default` profile) or set `GRADIATED_BASE_URL` and `GRADIATED_API_KEY`. Without either, the SDKs connect to `https://api.gradiated.com`. You can also pass both directly:

### Versioning and deprecations

The SDKs follow semantic versioning, so upgrading within a major version shouldn't break your code:

- **Patch releases only fix bugs.**
- **Renamed APIs keep their old name for at least two minor releases**, with a `DeprecationWarning` that names the replacement. Removed CLI commands print what replaced them.
- **Release notes always have New, Deprecated and Breaking sections**, with a migration example for every breaking change.
- **Changes to how `"auto"` defaults resolve are versioned**, so an existing run config keeps training the same way.

Base model retirement follows its own notice policy; see [Model retirement](/docs/training/models/#model-retirement).

## Use your trained model

Download the artifact and serve it with the inference stack you already run. A LoRA loads into vLLM or SGLang on its base model, and your app calls it through any OpenAI-compatible client:

```bash
grad artifacts download sql-helper@latest --output ./sql-helper
vllm serve Qwen/Qwen3-8B --enable-lora --max-lora-rank 32 --lora-modules sql-helper=./sql-helper
```

```python
from openai import OpenAI

oai = OpenAI(base_url="http://localhost:8000/v1", api_key="unused")
reply = oai.chat.completions.create(
    model="sql-helper",
    messages=[{"role": "user", "content": "Count active users from yesterday."}],
)
print(reply.choices[0].message.content)
```

Routers, decision models, cartridges, reward models and embedding models export their own bundles; [Deploying](/docs/training/deploying/#serve-it-yourself) shows how to load each one.

To improve the next version, log outcomes (thumbs up, tests passed, a human fix) to the observability tool you already trace requests with. A [source](/docs/training/trajectories/#send-feedback-from-production) syncs the traces and their latest scores into a new dataset version.

<DocsCallout label="Coming soon on Gradiated Cloud">

  one-command rollback and trace capture built in. Until then, serve it
  yourself as above.
</DocsCallout>

## Two ways to train

Start with a built-in `Recipe` and its defaults. Learning rate, batch size and schedule are calibrated for each base model, and the dry run prints every resolved value. When you need more control, override a single piece (like the loss function or dataset split).

| Mode                                             | How it works                                                                                                                                                                   | When to use it                                                                                                                                           |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [**Recipes**](/docs/training/recipes/)           | Pick a recipe (`SFTRecipe`, `DPORecipe`, `RouterRecipe`, `DecisionModelRecipe`, `CartridgeRecipe`, `EmbeddingRecipe`, `DistillRecipe`, `RewardModelRecipe`), or run from YAML. | Almost always. You get calibrated defaults, held-out evaluations, automatic checkpoints, and can swap individual pieces without writing a training loop. |
| [**Custom loops**](/docs/training/custom-loops/) | Coming soon: call `Trainer` directly in Python with built-in losses or your own PyTorch `CustomLoss`.                                                                          | You are building a new algorithm: a custom research loop, multi-trainer setup, replay buffer, or rollout logic a recipe can't express.                   |

[RL agents](/docs/training/recipes/rl-agents/) are coming soon. [Distillation](/docs/training/recipes/distillation/) and [reward models](/docs/training/recipes/reward-models/) are recipes too. To train in stages, wait for the first run and pass its artifact to the next recipe: `DPORecipe(model=sft.artifact)`.

You can export the full resolved config of any run as YAML (`grad runs inspect <run_id> --yaml > recipe.yaml`) to check it into Git.

<DocsCallout label="Metered per token" tone="tip">
  Runs are metered per million tokens processed, never per GPU-hour, and
  `runs.plan()` prices a run for $0 before it starts (`grad usage` lists what
  each one cost). Start with the simplest option that proves value: a router or
  decision model trains quickly, then move up to fine-tuning once you have a
  baseline.
</DocsCallout>

## Using with coding agents

Every docs page includes a **Copy** menu (**Copy page** as raw Markdown or **Copy prompt** for coding agents) in the top right, and every page is served as plain Markdown at `<url>.md`, indexed in [`/llms.txt`](/llms.txt) and `/llms-full.txt`.

The CLI is designed for non-interactive agent loops: pass `--json` to any `grad` command for a single JSON envelope on stdout, and run `--dry-run --json` (or `client.runs.plan(...)`) to validate dataset coverage and estimate tokens and cost before starting a run.

### Starter prompts to paste into Claude Code, Codex, or Cursor

<DocsCodeTabs>
  <DocsCodeTab label="Model router">

```text
Read https://gradiated.com/docs/training/recipes/router.md and integrate a Gradiated model router into this codebase:
1. Find where we call LLMs and inspect how we log or store completed requests and outcomes.
2. Push or import historical traces into a Gradiated dataset using GRADIATED_API_KEY from env.
3. Run `grad train --dataset <name> --name <router> --recipe router --dry-run --json` first and fix any data warnings.
4. Train the router, verify `eval_report.pareto_summary.quality_drop_ci95` stays inside 2%, and download it with `grad artifacts download <router>@latest`.
5. Load the router bundle in our serving path (see https://gradiated.com/docs/training/deploying.md), send outcomes to our observability tool, and connect it with `grad sources add` so the next sync picks them up.
```

  </DocsCodeTab>
  <DocsCodeTab label="Fine-tune (SFT & DPO)">

```text
Read https://gradiated.com/docs/training/recipes/sft.md (and https://gradiated.com/docs/training/recipes/dpo.md) and set up a fine-tuning pipeline for our task:
1. Export verified passing examples as plain chat records (`{"messages": [...]}`, last assistant turn is the target) and push them with `client.datasets.push(name, records_or_jsonl_path)`.
2. Configure `SFTRecipe(model="qwen/qwen3-8b")` with its defaults. For a DPO stage, wait for the SFT run (`sft = client.runs.create(...).wait()`) and train `DPORecipe(model=sft.artifact)` on preference pairs. Don't hand-set `lr`; the default `lr="auto"` is calibrated per model.
3. Run `grad render <dataset> --model qwen/qwen3-8b --limit 3` to check the chat template and loss mask, then `client.runs.plan(...)` or `grad train -f recipe.yaml --dry-run --json` and fix every warning.
4. Start the run with `max_cost_usd=` set, download the LoRA with `run.download(path)` for vLLM/SGLang, and send human fixes to our observability tool as corrections so the next sync picks them up.
```

  </DocsCodeTab>
  <DocsCodeTab label="Cartridge">

```text
Read https://gradiated.com/docs/training/recipes/cartridges.md:
1. Identify the long system prompts or reference documents we repeat on every request.
2. Configure `CartridgeRecipe(context=Context.from_file("./context.md"))` to compress that static context into a trained prefix.
3. Validate with `client.runs.plan(...)` or `grad train -f recipe.yaml --dry-run --json`, run training, compare `eval_report` against the baseline, and download the cartridge with `grad artifacts download`.
```
