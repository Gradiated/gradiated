# LangSmith

<DocsLead>
  Sync LangSmith runs and their feedback, including corrections, into a dataset.
</DocsLead>

## What syncs

Each root run of a trace becomes one record, with its inputs and outputs as `messages`. Feedback on the run becomes `scores` (by feedback `key`), and a feedback `correction` becomes `expected_output`, so SFT can train on the fixed answer.

| LangSmith                       | grad record                            |
| ------------------------------- | -------------------------------------- |
| Run ID                          | `id` (the merge key for late feedback) |
| Run inputs / outputs            | `messages`                             |
| Feedback (`key` → `score`)      | `scores`                               |
| Feedback `correction`           | `expected_output`                      |
| Thread / session ID             | `session_id`                           |
| Run `metadata` (model, version) | `metadata`                             |
| Run `tags`                      | `metadata.tags`                        |

## Tag runs with the model and version

```python
from langsmith import traceable
from langsmith.run_helpers import get_current_run_tree

@traceable(name="answer", metadata={"model": "your-org/support-sft", "version": "v42"}, tags=["prod"])
def answer(question: str) -> tuple[str, str]:
    reply = ...  # call the model
    return reply, str(get_current_run_tree().id)
```

## Send feedback from production

Use `create_feedback` with the run ID. Pass `correction` when someone fixes the answer:

```python
from langsmith import Client

ls = Client()
ls.create_feedback(run_id, key="resolved", score=1)

# A reviewer rewrote the answer:
ls.create_feedback(
    run_id,
    key="resolved",
    score=0,
    correction={"outputs": {"answer": "Open Billing > Invoices and click Download."}},
)
```

Feedback logged later is picked up by the next sync (see [How syncing works](#how-syncing-works)).

## Connect it to grad

Store the key once as a workspace secret (it reads the value from stdin and never returns it), then add a source to a dataset. The schedule is a cron expression; leave it out to sync only when you ask.

<DocsCodeTabs>
  <DocsCodeTab label="CLI">

```bash
grad secrets set langsmith-prod

grad sources add langsmith \
  --dataset support-prod \
  --host https://api.smith.langchain.com \
  --secret langsmith-prod \
  --schedule "*/30 * * * *"

grad sources list
grad sources sync src_01J9X
```

## How syncing works

Each sync is incremental: it pulls traces added since the last sync, plus scores and corrections added to traces it already has, so feedback that arrives days later still counts. Records are matched by the provider's trace ID and the latest score wins.

Every sync creates a new dataset version. Old versions never change, so a run keeps the exact data it pinned. If you edit old scores or change the mapping, `grad sources sync src_01J9X --full` (or `source.sync(full=True)`) rebuilds the dataset from the provider as a new version.

A one-off `grad import` of an exported file is a snapshot: it never gets later feedback. Use a source for the feedback loop.

## Choose what to train on

Records keep the provider's scores in `scores` and its model and version tags in `metadata`, so you can pick a slice before training. Read the synced version, keep what you want, and push it as its own dataset:

```python
from grad import Grad

client = Grad()
good = [
    r for r in client.datasets.records("support-prod")
    if (r.get("scores") or {}).get("resolved", 0) >= 1.0
    and (r.get("metadata") or {}).get("version") == "v42"
]
client.datasets.push("support-prod-v42-good", good)
```

A [router](/docs/training/recipes/router/) can use the raw dataset as is: it learns from every score, good and bad.

## Keys and hosts

- **Key:** a personal access token or a service key with read access to the workspace. Tracing keys (`lsv2_tr_...`) can only write traces, so they can't be used for syncing.
- **Hosts:** `https://api.smith.langchain.com` (US), `https://eu.api.smith.langchain.com` (EU), or your self-hosted LangSmith API URL.
