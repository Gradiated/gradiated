# Supported training models

<DocsLead>
  See which base models you can fine-tune, what each size is best at, and how
  token-based training billing works.
</DocsLead>

Pass any model ID as a plain lowercase string (such as `"qwen/qwen3-8b"`) to a [`Recipe`](/docs/training/recipes/). You can also pass an SFT or DPO [`Artifact`](/docs/training/artifacts/) to `SFTRecipe` or `DPORecipe` to continue training from an earlier stage (for example, `SFT -> DPO`).

## Trainable base models

These tables mirror the live catalog. `grad models list` is the source of truth, so check it if anything here looks out of date.

| Model ID          | Best for                                                           | Adapters        | Notes                                                                    |
| ----------------- | ------------------------------------------------------------------ | --------------- | ------------------------------------------------------------------------ |
| `qwen/qwen3-0.6b` | Model routers, fast classifiers, latency-critical SFT              | LoRA            | Default backbone for `RouterRecipe`; sub-15 ms routing.                  |
| `qwen/qwen3-1.7b` | Lightweight extraction, formatting, high-volume structured outputs | LoRA            | Good balance of speed and instruction following.                         |
| `qwen/qwen3-4b`   | Fast assistants, narrow coding and SQL helpers                     | LoRA, Cartridge | Smallest model that supports Cartridges.                                 |
| `qwen/qwen3-8b`   | General SFT, DPO and Cartridges                                    | LoRA, Cartridge | Default for every recipe except routers, decision models and embeddings. |
| `qwen/qwen3-14b`  | Harder reasoning, multi-step tool use, domain synthesis            | LoRA, Cartridge | Strong step up when 8B plateaus on complex logic.                        |
| `qwen/qwen3-32b`  | High-accuracy SFT and DPO, complex coding agents                   | LoRA, Cartridge | Largest base model in the catalog.                                       |

All Qwen3 models are hybrid thinking models. Recipes render their chat template with `thinking="auto"` by default; see [Chat templates and loss masks](/docs/training/tuning-troubleshooting/#chat-templates-and-loss-masks).

Multimodal (image + text) fine-tuning and DeepSeek MoE training are coming soon.

### Recipe-managed backbones

Some recipes pick their own backbone, so you don't pass these as `model=` to `SFTRecipe` or `DPORecipe`:

| Model ID                 | Used by               | Notes                                                                            |
| ------------------------ | --------------------- | -------------------------------------------------------------------------------- |
| `gradiated/linden-1`     | `DecisionModelRecipe` | SystemOne decision models (`Choice`, `Noul`, `Score`) served at `/v1/systemone`. |
| `baai/bge-small-en-v1.5` | `EmbeddingRecipe`     | Domain search and RAG embeddings; full fine-tuning; sub-10 ms inference.         |

### Querying the live catalog

Check the exact list of trainable models and their context limits at any time via the CLI or API:

```bash
grad models list
grad models list --recipe sft
```

Or fetch `GET https://api.gradiated.com/v1/models`: each entry lists its `recipes`, `adapters`, `max_context_tokens` and `price_per_million_tokens_usd`. See [Models and pricing](/docs/models-pricing/) for the live catalog table and serving rates.

## Model retirement

Base models get replaced as better open models ship. When we retire one, you get at least 90 days' notice, and nothing you trained stops working without warning:

- **Notice:** the retirement date and a named replacement are announced in the changelog and by email.
- **New runs:** you can start runs on a retiring model until its retirement date. After that, `runs.plan()` rejects the model.
- **Your artifacts:** trained weights stay downloadable as PEFT adapters for as long as you keep them, so you can always serve them yourself with vLLM or SGLang.
- **Your deployments:** hosted deployments of artifacts on a retiring base keep serving until the retirement date. Retrain on the replacement with the same recipe and data, then [deploy the new artifact](/docs/training/deploying/).
- **Recipe defaults:** when you leave out `model=`, the run uses the current default, and the dry run says which one. Export the config with `grad runs inspect <run> --yaml` to pin the exact model.

## Judge and comparison models

[`Judge`](/docs/training/rubrics/) and [`Evaluations`](/docs/training/evaluations/) can call any frontier or open model in the catalog (such as `"{{SONNET_MODEL}}"`, `"{{OPUS_MODEL}}"`, `"{{GPT_MODEL}}"`, or `"qwen/qwen3-32b"`), or a chat model `Artifact` you fine-tuned yourself.

## How training billing works

Training on Gradiated Cloud uses the same token-metered model as inference:

- **Training & sampling tokens:** billed **per million tokens processed** across forward/backward passes, teacher sampling and logprob scoring, so you don't pay for idle GPU time.
- **Weight & checkpoint storage:** billed for saved `.grad` artifacts and checkpoints retained in your workspace.
- **Zero-cost pre-flight estimate:** run `grad train --dry-run` or `client.runs.plan(...)` before launching any managed recipe to see `estimated_tokens` and `estimated_cost_usd` at `$0`.
- **Spend cap:** pass `max_cost_usd=` on any run; it stops cleanly with status `stopped_budget` and saves a checkpoint when the cap is reached.
- **Checkpoint retention:** the best and final checkpoints of every run never expire; other checkpoints expire after 30 days unless you promote them.

```bash
grad train --dataset support-sft --name support-sft --recipe sft --dry-run
grad train --dataset support-sft --name support-sft --recipe sft --wait
```

For current per-token rates and service tiers, see [Models and pricing](/docs/models-pricing/).
