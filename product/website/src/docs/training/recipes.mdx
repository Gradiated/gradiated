# Recipes

<DocsLead>Pick a recipe, check the cost with a dry run, and train with sensible defaults.</DocsLead>

A **recipe** is a Python class that wires up a common training workflow (`RouterRecipe`, `DecisionModelRecipe`, `SFTRecipe`, `DPORecipe`, `GRPORecipe`, `DistillRecipe`, `CartridgeRecipe`, `RewardModelRecipe`, `EmbeddingRecipe`). When a run finishes, it saves a versioned `.grad` [`Artifact`](/docs/training/artifacts/) along with its held-out evaluation report.

<DocsRecipeChooser />

## Built-in recipes

| Recipe class | Guide | Expected dataset fields |
| --- | --- | --- |
| `RouterRecipe` | [Model router](/docs/training/recipes/router/) | Prompts (`input.messages`) + a `Judge` or existing `scores` (optional `metrics.cost_usd`) |
| `DecisionModelRecipe` | [Decision models](/docs/training/recipes/decision-model/) | SystemOne `state` + `questions` (`choice`, `noul`, `score`) and `expected_output` |
| `SFTRecipe` | [Supervised fine-tuning (SFT)](/docs/training/recipes/sft/) | `input` + `expected_output` (or filtered high-score `output`) |
| `DPORecipe` | [Preference tuning (DPO)](/docs/training/recipes/dpo/) | Paired `group_id` trajectories with `role: chosen \| rejected` |
| `GRPORecipe` | [RL for agents](/docs/training/recipes/rl-agents/) | Prompts + a [`Rubric`](/docs/training/rubrics/) (`Judge` / `validators.*`) or [`Environment`](/docs/training/environments/) |
| `DistillRecipe` | [Model distillation](/docs/training/recipes/distillation/) | Prompts or traces + `teacher` model |
| `CartridgeRecipe` | [Context Cartridges](/docs/training/recipes/cartridges/) | Static corpus (`Context`) + QA prompts (`num_tokens`) |
| `RewardModelRecipe` | [Reward models](/docs/training/recipes/reward-models/) | Paired `group_id` trajectories with `role: chosen \| rejected` |
| `EmbeddingRecipe` | [Embeddings](/docs/training/recipes/embeddings/) | Query groups with `role: anchor \| positive \| negative` |

## Start with recipe defaults

Every recipe comes with working defaults for the base model, train/eval split, and optimizer. You pay per million tokens trained plus storage for saved weights, never for idle GPUs. Pass your dataset, output name, and recipe, and use `--dry-run` (or `runs.plan()`) to check data coverage and estimated cost before launching.

<DocsCodeTabs action={<DocsApiKeyAction />}>
  <DocsCodeTab label="Python">

```python
from grad import Grad
from grad.recipes import RouterRecipe

client = Grad()
dataset = client.datasets.get("support-prod")

# Optional pre-flight check before starting training ($0)
plan = client.runs.plan(dataset=dataset, name="support-router", recipe=RouterRecipe())
print(plan.resolved_recipe, plan.warnings, plan.estimated_tokens, plan.estimated_cost_usd)

run = client.runs.create(
    dataset=dataset,
    name="support-router",
    recipe=RouterRecipe(),
).wait(
    on_metric=lambda m: print(f"step={m.step} loss={m.loss:.4f}"),
)

print(run.artifact.id)
print(run.eval_report)
```

### Inspect resolved defaults

Export the full resolved config of any run as YAML to see every default — model, split strategy, filters, and hyperparameters — and check it into Git:


## Customize any piece

Leave out any argument to keep the recipe's default, or override just the pieces you care about (`model`, `adapter`, `loss`, `optimizer`, `split`, `rubric`). Filter your data directly on the `Dataset` with `dataset.filter(...)`:

<DocsCodeTabs>
  <DocsCodeTab label="Router">

```python
from grad import Grad, Judge
from grad.recipes import RouterRecipe

client = Grad()
dataset = client.datasets.get("support-prod")

recipe = RouterRecipe(
    model="Qwen/Qwen3-0.6B",
    models=["Qwen/Qwen3-8B", "{{OPUS_MODEL}}"],
    score=Judge(
        name="resolved",
        model="{{SONNET_MODEL}}",
        prompt="Did the assistant solve the user's issue accurately?",
    ),
    max_quality_drop=0.02,
)

run = client.runs.create(dataset=dataset, name="support-router", recipe=recipe).wait()
```

  </DocsCodeTab>
  <DocsCodeTab label="Decision model">

```python

from grad.recipes import DecisionModelRecipe

dataset = client.datasets.get("ticket-triage")

    split=splits.BySession(eval_fraction=0.15),

```

  </DocsCodeTab>
  <DocsCodeTab label="SFT">

```python
from grad import Grad, Judge, adapters, optim, splits
from grad.recipes import SFTRecipe

client = Grad()
judge = Judge(
    name="clean_merge",
    model="{{SONNET_MODEL}}",
    prompt="Did the assistant apply the edit accurately without breaking surrounding code?",
)
dataset = client.datasets.get("diff-merge-prod").score(judge).wait().filter(
    lambda t: t.scores["clean_merge"] >= 0.8,
)

recipe = SFTRecipe(
    model="Qwen/Qwen3-8B",
    adapter=adapters.LoRA(rank=32),
    optimizer=optim.AdamW(lr=2e-4),
    split=splits.BySession(eval_fraction=0.10),
)

run = client.runs.create(dataset=dataset, name="fast-diff-merge", recipe=recipe).wait()
```

### Swap one component instead of rewriting the loop

You don't need to write a full training loop just to try a different loss function or split strategy. Pass your own `losses.CustomLoss`, `AdvantageEstimator`, or `Splitter` straight into the recipe:

```python
# Swap built-in losses.DPO() for your own SimPOLoss subclass inside DPORecipe:
recipe = DPORecipe(
    model="Qwen/Qwen3-8B",
    adapter=adapters.LoRA(rank=32),
    loss=SimPOLoss(beta=2.0, gamma=0.5),
    optimizer=optim.AdamW(lr=3e-5),
)
```

### Run recipes from YAML

Every recipe composed of built-in specs serializes 1:1 to a flat YAML file (`recipe.to_yaml()`) you can check into Git and run from CI:

```yaml
# recipe.yaml
dataset:
  name: diff-merge-prod
  filter:
    min_score:
      tests_passed: 1.0
name: fast-diff-merge
recipe: sft
model: Qwen/Qwen3-8B
adapter:
  kind: lora
  rank: 32
optimizer:
  kind: adamw
  lr: 2e-4
split:
  strategy: by_session
  eval_fraction: 0.10
```

```bash
grad train -f recipe.yaml --dry-run
grad train -f recipe.yaml --wait
```

## Chaining stages (`SFT → DPO` / `SFT → GRPO`)

Every recipe takes a `Model` (a base model or a trained `Artifact`) and produces a new `Artifact`. `run.artifact` can be passed straight into a second run before the first finishes: use `.then(...)` for a simple chain, pass `model=sft.artifact` if you want to branch, or call `.wait()` in between to check metrics before continuing:

<DocsCodeTabs>
  <DocsCodeTab label="Chained (.then)">

```python
from grad import Grad, Judge, Rubric, Scorer, adapters, optim, validators
from grad.recipes import GRPORecipe, SFTRecipe

client = Grad()
gold_ds = client.datasets.get("diff-merge-gold")
tasks_ds = client.datasets.get("diff-merge-tasks")

merge_rubric = Rubric([
    Scorer("valid_ts", weight=0.4, fn=validators.TypeScriptAST()),
    Judge(
        name="exact_merge",
        model="{{SONNET_MODEL}}",
        prompt="Verify the merged file applies the edit cleanly without breaking surrounding code.",
        weight=0.6,
    ),
])

# GRPO starts automatically when SFT finishes and cancels if SFT fails.
run = (
    client.runs.create(
        dataset=gold_ds,
        name="fast-diff-merge",
        recipe=SFTRecipe(model="Qwen/Qwen3-8B", adapter=adapters.LoRA(rank=32), optimizer=optim.AdamW(lr=2e-4)),
    )
    .then(
        dataset=tasks_ds,
        recipe=GRPORecipe(
            adapter=adapters.LoRA(rank=32),
            rubric=merge_rubric,
            optimizer=optim.AdamW(lr=2e-5),
        ),
    )
    .wait()
)
```

  </DocsCodeTab>
  <DocsCodeTab label="Pass run.artifact (or inspect in between)">

```python
gold_ds = client.datasets.get("diff-merge-gold")
tasks_ds = client.datasets.get("diff-merge-tasks")

# Omit .wait() here so GRPO queues behind SFT, or call .wait() to inspect sft.eval_report first.
sft = client.runs.create(
    dataset=gold_ds,
    name="fast-diff-merge",
    recipe=SFTRecipe(model="Qwen/Qwen3-8B", adapter=adapters.LoRA(rank=32)),
)

rl = client.runs.create(
    dataset=tasks_ds,
    name="fast-diff-merge",
    recipe=GRPORecipe(
        model=sft.artifact,
        rubric=merge_rubric,
    ),
).wait()
```

  </DocsCodeTab>
</DocsCodeTabs>

## Live metrics and evaluation

Stream step-by-step telemetry (`step`, `loss`, `grad_norm`, `lr`, `tokens_per_sec`, `eval_metrics`) while a run is active, or inspect the saved `eval_report.json` afterward:

<DocsCodeTabs>
  <DocsCodeTab label="Python">

```python
for metric in run.metrics(follow=True):
    print(metric.step, metric.loss, metric.eval_metrics)
```

  </DocsCodeTab>
  <DocsCodeTab label="TypeScript">

```ts
for await (const metric of run.metrics({ follow: true })) {
  console.log(metric.step, metric.loss, metric.evalMetrics);
}
```

  </DocsCodeTab>
  <DocsCodeTab label="CLI">

```bash
grad runs logs run_01J9X --follow
grad artifacts inspect fast-diff-merge@2026-11-25-2 --json
```

  </DocsCodeTab>
</DocsCodeTabs>

Router artifacts include a held-out cost-vs-quality Pareto curve and 95% bootstrap confidence intervals against your fallback model.

## When to write a custom loop

Stick with a `Recipe` (even with a custom loss or splitter) as long as a standard train/eval flow works. Switch to [custom loops](/docs/training/custom-loops/) when you need:

- Multiple trainers updating together in one loop (like a separate actor and critic).
- Custom rollout setups like async replay buffers, tree search, or multi-agent self-play.
- Manual control over batching, mid-run `trainer.snapshot()` calls, or Docker Compose environments.
