# Context Cartridges

<DocsLead>Compress 30k–100k tokens of repeated system prompts, API documentation, or repository manuals into a compact trainable KV-cache prefix you pay to encode once and hot-swap per tenant.</DocsLead>

When every request prepends the same long static corpus (internal runbooks, compliance rules, product docs, or codebase manuals), re-processing that context on every turn inflates prefill latency and cost.

## How a Cartridge works

A Cartridge replaces a huge static system prompt with a tiny **precomputed attention memory** (KV cache) that stays frozen-base-compatible:

1. **`context`** is the static document(s) you want to compress (`Context.from_file(...)`, `Context.from_uri("s3://...")`, or `Context.from_text(...)`).
2. **`dataset`** is a set of 500–2,000 representative questions or tasks grounded in that corpus (`input.messages` — no gold answers required).
3. **`num_tokens`** is the compressed Cartridge size (for example, `256` virtual KV-cache tokens standing in for a 50,000-token manual — backed by `adapters.PrefixKV(num_tokens=256)` under the hood while keeping the base model weights frozen).

During training, the full model reads `context` + each question to produce target predictions, while the Cartridge trains to match those predictions **without** `context` in the prompt. At serving time, one frozen base model can hot-swap different Cartridges per tenant or repository on every request.

## Train a Cartridge (`CartridgeRecipe`)

`CartridgeRecipe` defaults `teacher=model` (override `teacher=` only if you want to distill from a larger model) and trains an `adapters.PrefixKV(num_tokens=...)` prefix automatically:

<DocsCodeTabs action={<DocsApiKeyAction />}>
  <DocsCodeTab label="Python">

```python
from grad import Context, Grad, Model, losses, optim
from grad.recipes import CartridgeRecipe

client = Grad()
dataset = client.datasets.get("api-docs-qa-prompts")

recipe = CartridgeRecipe(
    model=Model("Qwen/Qwen3-8B"),
    context=Context.from_file("./api-docs-bundle.md"),  # or Context.from_uri("s3://...") / Context.from_text(...)
    num_tokens=256,
    loss=losses.TopKKLDistill(top_k=20),
    optimizer=optim.AdamW(lr=2e-2),
)

run = client.runs.create(dataset=dataset, name="api-docs-cartridge", recipe=recipe).wait()

print(run.artifact.id, run.eval_report)
```

```ts
import { Context, Grad, Model, losses, optim, recipes } from "@gradiated/grad";

const grad = new Grad();
const dataset = await grad.datasets.get("api-docs-qa-prompts");

const run = await grad.runs
  .create({
    dataset,
    name: "api-docs-cartridge",
    recipe: recipes.cartridge({
      model: new Model("Qwen/Qwen3-8B"),
      context: Context.fromFile("./api-docs-bundle.md"),
      numTokens: 256,
      loss: losses.topKKLDistill({ topK: 20 }),
      optimizer: optim.adamW({ lr: 2e-2 }),
    }),
  })
  .wait();

console.log(run.artifact.id, run.evalReport);
```

## Deploy and serve

Cartridges export as standard `.grad` artifacts (`prefix_kv.safetensors` + `base_model_ref`) and deploy onto any [`Endpoint`](/docs/training/endpoints/) identically to a LoRA adapter. Requests hit the endpoint with only the user question — no giant system prompt required:

```python
endpoint = run.deploy()
```

### Key parameters

| Component | Guidance |
| --- | --- |
| `num_tokens` | Compressed KV-cache size (`128`–`256` for 10k–30k token manuals; `512`–`1024` for 100k+ token corpora). Uses `adapters.PrefixKV(num_tokens=...)` under the hood. |
| `optim.AdamW(lr=...)` | Prefix KV tensors need a much higher learning rate (`1e-2`–`2e-2`) than LoRA adapters. |
| `eval_report` | Compare KL divergence and task QA accuracy against the full-context model to pick the smallest `num_tokens` that holds quality. |

## Cartridge (`PrefixKV`) vs. prompt distillation into LoRA

If you only have **one** static prompt and want a single merged checkpoint with zero prefix-KV tensors at serving time, pass `context=` to [`DistillRecipe`](/docs/training/recipes/distillation/) with `adapters.LoRA(..., merge_on_export=True)`:

```python
from grad import Context, Model, adapters, losses
from grad.recipes import DistillRecipe, OnPolicy

recipe = DistillRecipe(
    model=Model("Qwen/Qwen3-8B"),
    teacher=Model("Qwen/Qwen3-8B"),
    context=Context.from_uri("s3://my-bucket/api-docs-bundle.md"),
    adapter=adapters.LoRA(rank=32, merge_on_export=True),
    rollout=OnPolicy(max_new_tokens=512),
    loss=losses.TopKKLDistill(top_k=32),
)

run = client.runs.create(dataset=dataset, name="api-docs-prompt-distilled", recipe=recipe).wait()
```

<DocsCallout label="When to pick CartridgeRecipe vs. LoRA prompt distillation" tone="tip">
Choose **`CartridgeRecipe` (`adapters.PrefixKV`)** when you serve many per-tenant, per-customer, or per-repository contexts against one shared frozen base model. Choose **prompt distillation (`DistillRecipe` + `adapters.LoRA`)** when you have one global system prompt and want a single merged model.
</DocsCallout>
