# Classifiers and decisions

<DocsLead>Train calibrated binary guardrails, multiclass triage models, and ordinal effort detectors that run in milliseconds and fall back automatically when uncertain.</DocsLead>

Use `ClassifierRecipe` whenever your model outputs a discrete label or ordered level rather than free-form text: thinking-effort detectors (`low / medium / high`), support ticket routing, PII/safety gates, or escalation triggers.

## What data you need

- **Minimum volume:** ~200 labeled [trajectories](/docs/training/trajectories/) per class for a frozen-encoder head; 1,000+ when fine-tuning the encoder with `adapters.LoRA` or `adapters.Full`.
- **Required fields:** `input.messages` (plus optional `input.features` for structured signals like user tier, token length, or retry count) and `expected_output.label` (string or integer class).

```python
from grad import Grad, Trajectory, TrajectoryInput

client = Grad()
dataset = client.datasets.create("coding-effort")

dataset.push([
    Trajectory(
        session_id="issue_104",
        input=TrajectoryInput(
            messages=[{"role": "user", "content": "Rename foo to bar in utils.ts"}],
            features={"file_count": 1, "diff_lines": 4},
        ),
        expected_output={"label": "low"},
    ),
    Trajectory(
        session_id="issue_105",
        input=TrajectoryInput(
            messages=[{"role": "user", "content": "Refactor auth middleware for multi-tenant OAuth"}],
            features={"file_count": 14, "diff_lines": 420},
        ),
        expected_output={"label": "high"},
    ),
])
```

## Train the classifier

Choose the `losses.*` class that matches your label structure:

- **`losses.CrossEntropy()`** for unordered categories (`billing`, `bug`, `feature_request`).
- **`losses.OrdinalBCE()`** for ordered tiers (`low < medium < high`), so confusing `low` with `high` costs more than confusing `low` with `medium`.
- **`losses.BCEWithLogits()`** for binary gates or multi-label tags.

### Calibration options

| Calibration class | What it does |
| --- | --- |
| `calibration.Temperature()` | Fits a single scalar temperature on the held-out split to minimize NLL so confidence scores reflect real accuracy. |
| `calibration.Conformal(alpha=0.10)` | Computes a split-conformal quantile threshold for a target coverage rate, guaranteeing bounded abstention error on exchangeable traffic. |

## Read the evaluation report

Inspect `run.eval_report` before shipping:

- **Per-class precision, recall, and F1:** Watch minority classes (for example, `high` effort or safety escalations) — overall accuracy hides class imbalance.
- **Confusion matrix:** For ordinal models, verify errors stay adjacent (`low ↔ medium`) rather than jumping extremes (`low ↔ high`).
- **Expected calibration error (ECE):** Lower ECE means `min_conf` thresholds behave predictably in production.

## Deploy with confidence fallback

Attach the artifact to an [endpoint](/docs/training/endpoints/) using `strategies.ConfidenceFallback`. Whenever top-class confidence falls below `min_conf`, the endpoint returns your safe fallback label (for example, `"high"` effort so complex prompts never get under-budgeted).

<DocsCodeTabs>
  <DocsCodeTab label="Python">

```python
from grad import Grad, strategies

client = Grad()
capture = client.datasets.get("coding-effort")

endpoint = client.endpoints.create(
    slug="coding-effort",
    artifact=run.artifact,
    capture_dataset=capture,
    strategy=strategies.ConfidenceFallback(
        min_conf=0.75,
        fallback="high",
    ),
)

effort = endpoint.infer(messages=messages)

if not tests_passed:
    effort.record_feedback(
        score=0.0,
        expected_output={"label": "high"},
    )
```

## Dynamic choices without a fixed head (`candidate_tokens`)

When your choice set changes per request (for example, ranking candidate tools or scoring zero-shot multiple-choice decisions with an LLM), score or train directly on the next-token probability distribution over those specific `candidate_tokens` in a single forward pass — without fetching full 152k-vocabulary logits:

```python
import torch
from grad import Grad, losses

client = Grad()
base = client.models.get("Qwen/Qwen3-8B")

# Score a dynamic per-request choice set in one forward pass
choice_ids = [base.tokenize(c)[-1] for c in ["A", "B", "C"]]
scored = base.score_logprobs(
    [base.tokenize(messages=prompt_messages)],
    candidate_tokens=choice_ids,
)
probs = torch.softmax(torch.tensor([scored.candidate_logprobs[0][t] for t in choice_ids]), dim=-1)

# Or fine-tune on soft target probabilities with a CustomLoss
class BrierLoss(losses.CustomLoss):
    outputs = ("topk_logprobs",)

    def compute(self, records, out) -> torch.Tensor:
        terms = []
        for lp, rec in zip(out.topk_logprobs, records):
            p = torch.softmax(lp[-1], dim=-1)
            target = torch.tensor(rec.metadata["target_probs"])
            terms.append(((p - target) ** 2).sum())
        return torch.stack(terms).mean()

fb = trainer.forward_backward(decision_records, loss=BrierLoss(), gather_indices=choice_ids)
```

<DocsCallout label="Fixed head vs. prompted choices" tone="tip">
Use `ClassifierRecipe` (dedicated head) when your labels are fixed across requests — it runs in under 10 ms at a fraction of LLM cost. Use `candidate_tokens` when choices vary per request or when zero-shot LLM world knowledge matters.
</DocsCallout>

## Going deeper with custom loops

Drop to [custom loops](/docs/training/custom-loops/) when you want:

- **Deep-ensemble uncertainty:** attach multiple seeded heads (`heads={"h0": heads.Linear(1), "h1": heads.Linear(1), "h2": heads.Linear(1)}`) and abstain on high variance via `artifact.infer_batch()`.
- **Few-shot contrastive classification (SetFit):** fine-tune the encoder with `losses.InfoNCE()` first, extract pooled embeddings with `artifact.embed(inputs, pool=pooling.Mean()).embeddings`, and fit the final head with `fit_batch(..., solver=solvers.DualHeadKernelLBFGS())`.
- **Token-level classification:** set `heads.Linear(dim=1, token_level=True)` for prompt compression or step-level process reward models.
