# Decision models

<DocsLead>Train your own fast decision model for categories, yes/no checks, or ordered ratings — with a fallback when it isn't sure.</DocsLead>

Use **`DecisionModelRecipe`** whenever you want a model to pick a label, return a yes/no probability, or rate an input on a scale instead of generating free-form text: effort levels (`low / medium / high`), support triage, safety checks, or routing flags.

If you already use [`gradiated/linden-1`](/docs/systemone-sdk/) through the SystemOne SDK and want a faster or more accurate model tuned specifically to your own traffic, this is how you train your own decision model.

## What data you need

- **Minimum volume:** ~200 labeled [trajectories](/docs/training/trajectories/) per label to start (1,000+ for harder or nuanced decisions).
- **Required fields:** `input.messages` (plus optional `input.features` like user tier, file count, or retry count) and `expected_output.label`.
- **Don't have labels yet?** Score an unlabeled dataset first with a [`Judge`](/docs/training/rubrics/) (using a frontier model or `gradiated/linden-1`), review a sample, and train on those labels.

```python
from grad import Grad, Trajectory, TrajectoryInput

client = Grad()
dataset = client.datasets.create("coding-effort")

dataset.push([
    Trajectory(
        session_id="issue_104",
        input=TrajectoryInput(
            messages=[{"role": "user", "content": "Rename foo to bar in utils.ts"}],
            features={"file_count": 1, "diff_lines": 4},
        ),
        expected_output={"label": "low"},
    ),
    Trajectory(
        session_id="issue_105",
        input=TrajectoryInput(
            messages=[{"role": "user", "content": "Refactor auth middleware for multi-tenant OAuth"}],
            features={"file_count": 14, "diff_lines": 420},
        ),
        expected_output={"label": "high"},
    ),
])
```

## Train the decision model

Choose the `losses.*` class that matches your label structure:

- **`losses.CrossEntropy()`** for unordered categories (`billing`, `bug`, `feature_request`).
- **`losses.OrdinalBCE()`** for ordered tiers (`low < medium < high`), so confusing `low` with `high` costs more than confusing `low` with `medium`.
- **`losses.BCEWithLogits()`** for yes/no checks or multi-label tags.

Choose your base `model`:

- **`Model("Qwen/Qwen3-0.6B")`** *(default)* — strong general starting point for text, code, and multi-turn conversations.
- **`Model("gradiated/linden-1")`** — great starting point if you already use [SystemOne](/docs/systemone-sdk/) and want to specialize `linden-1` on your own questions.
- **`Model("BAAI/bge-small-en-v1.5")`** — smallest option if you only need ultra-fast CPU inference on short text.

### Calibration options

- **`calibration.Temperature()`** *(default)* — adjusts confidence scores on the eval split so a `0.85` score really means ~85% accuracy.
- **`calibration.Conformal(alpha=0.10)`** — picks a confidence cutoff automatically so the model falls back whenever error would exceed `alpha`.

## Read the evaluation report

Check `run.eval_report` before shipping:

- **Per-label precision, recall, and F1:** check rare labels (like `high` effort or safety flags) — overall accuracy can look fine even when rare classes are missed.
- **Confusion matrix:** for ordered tiers, mistakes should stay next door (`low ↔ medium`), not jump from `low` to `high`.
- **Calibration error (`ece`):** lower means your `min_conf` threshold works more predictably in production.

## Deploy with a confidence fallback

Attach the [`Artifact`](/docs/training/artifacts/) to an [endpoint](/docs/training/endpoints/) using `strategies.ConfidenceFallback`. Whenever confidence is below `min_conf`, the endpoint returns your safe fallback label (like `"high"` effort so hard tasks don't get rushed).

<DocsCodeTabs>
  <DocsCodeTab label="Python">

```python
from grad import Grad, strategies

client = Grad()
capture = client.datasets.get("coding-effort")

endpoint = client.endpoints.create(
    slug="coding-effort",
    artifact=run.artifact,
    capture_dataset=capture,
    strategy=strategies.ConfidenceFallback(
        min_conf=0.75,
        fallback="high",
    ),
)

effort = endpoint.infer(messages=messages)

if not tests_passed:
    effort.record_feedback(
        score=0.0,
        expected_output={"label": "high"},
    )
```

```ts
import { Grad, strategies } from "@gradiated/grad";

const grad = new Grad();
const capture = await grad.datasets.get("coding-effort");

const endpoint = await grad.endpoints.create({
  slug: "coding-effort",
  artifact: run.artifact,
  captureDataset: capture,
  strategy: strategies.confidenceFallback({
    minConf: 0.75,
    fallback: "high",
  }),
});

const effort = await endpoint.infer<{
  label: "low" | "medium" | "high";
  confidence: number;
  fallbackUsed: boolean;
}>({ messages });

// Send back a correction when a "low" effort attempt fails tests
if (!testsPassed) {
  await effort.recordFeedback({
    score: 0.0,
    expectedOutput: { label: "high" },
  });
}
```
