# Model distillation

<DocsLead>Train a small, fast model to copy a larger one using your own prompts.</DocsLead>

If you just fine-tune a small model on saved outputs from a big model, it can go off the rails as soon as it starts writing its own slightly different wording. **`DistillRecipe`** with `rollout=OnPolicy(...)` fixes that: the small **student** generates answers to your prompts, and the larger **teacher** scores those exact tokens so the student learns to recover from its own mistakes.

## What data you need

- **Only prompts:** you don't need labeled answers — 1,000–5,000 real prompts in `input.messages` ([trajectories](/docs/training/trajectories/)) are enough.
- **A teacher model:** any larger `Model` (`"Qwen/Qwen3-32B"`) or a fine-tuned `.grad` [`Artifact`](/docs/training/artifacts/) you trained earlier.

## Train with `DistillRecipe`

<DocsCodeTabs action={<DocsApiKeyAction />}>
  <DocsCodeTab label="Python">

```python
from grad import Grad, adapters, losses, optim
from grad.recipes import DistillRecipe, OnPolicy

client = Grad()
dataset = client.datasets.get("support-prompts")

recipe = DistillRecipe(
    model="Qwen/Qwen3-4B",
    teacher="Qwen/Qwen3-32B",
    adapter=adapters.LoRA(rank=32),
    rollout=OnPolicy(max_new_tokens=512),
    loss=losses.TopKKLDistill(top_k=32),
    optimizer=optim.AdamW(lr=1e-4),
)

run = client.runs.create(dataset=dataset, name="support-4b-distilled", recipe=recipe).wait()

print(run.artifact.id, run.eval_report)
```

```ts
import { Grad, adapters, losses, optim, recipes } from "@gradiated/grad";

const grad = new Grad();
const dataset = await grad.datasets.get("support-prompts");

const run = await grad.runs
  .create({
    dataset,
    name: "support-4b-distilled",
    recipe: recipes.distill({
      model: "Qwen/Qwen3-4B",
      teacher: "Qwen/Qwen3-32B",
      adapter: adapters.lora({ rank: 32 }),
      rollout: recipes.onPolicy({ maxNewTokens: 512 }),
      loss: losses.topKKLDistill({ topK: 32 }),
      optimizer: optim.adamW({ lr: 1e-4 }),
    }),
  })
  .wait();

console.log(run.artifact.id, run.evalReport);
```

### Key parameters

- **`teacher`:** the stronger model you want to copy — any catalog `Model` (like `"Qwen/Qwen3-32B"`) or a larger `.grad` [`Artifact`](/docs/training/artifacts/) you already fine-tuned.
- **`rollout=OnPolicy(max_new_tokens=512)`:** generates answers from the student and grades them with the teacher so the student learns where it actually makes mistakes. Switch to `OffPolicy()` only if you already have fixed teacher completions you want to train on directly.
- **`losses.TopKKLDistill(top_k=32)`:** matches the teacher's top 32 next-token probabilities at every step (`top_k=16..32` captures almost all the signal cleanly).
- **`optim.AdamW(lr=...)`:** start around `1e-4` for LoRA distillation.

## When to use distillation vs. SFT vs. Cartridges

- **`DistillRecipe`** — you have a strong, slow model (like a 32B or frontier model) and want a small 4B–8B model to match it on your prompts, with no labeled answers required.
- **[`SFTRecipe`](/docs/training/recipes/sft/)** — you already have verified gold answers (or human-edited outputs) you want the model to copy directly.
- **[`CartridgeRecipe`](/docs/training/recipes/cartridges/)** — you don't want to change the model's general behavior; you just want to stop resending the same 30k–100k tokens of docs or system prompt on every request.

## Deploy and serve

Distilled checkpoints export as standard `.grad` [`Artifact`](/docs/training/artifacts/)s and deploy onto any [`Endpoint`](/docs/training/endpoints/) with `strategies.Direct()` (or `strategies.Cascade` paired with a [reward model](/docs/training/recipes/reward-models/)):

```python
endpoint = run.deploy(canary=0.10)
```
