# Preference tuning (DPO)

<DocsLead>Teach a model which answers you prefer by showing it pairs of good and bad examples.</DocsLead>

Use **`DPORecipe`** after [Supervised fine-tuning (SFT)](/docs/training/recipes/sft/) when your model already knows the right format but still makes recurring mistakes (like cutting off code, being too wordy, or picking the wrong tool arguments). Showing it **chosen** vs. **rejected** pairs steers it away from those patterns.

## What data you need

- **Minimum volume:** 300–1,000 preference pairs for narrow failure modes; 2,000+ for general style and quality alignment.
- **Format:** Store pairs sharing a `group_id` with `role: "chosen"` and `role: "rejected"` in a [`Dataset`](/docs/training/trajectories/). Pairs automatically stay together in the same train or eval split.

```json
[
  {
    "schema": "grad.trajectory/1",
    "group_id": "pair_19",
    "role": "chosen",
    "input": { "messages": [{ "role": "user", "content": "Merge this diff." }] },
    "output": { "turns": [{ "role": "assistant", "content": "clean merged code..." }] }
  },
  {
    "schema": "grad.trajectory/1",
    "group_id": "pair_19",
    "role": "rejected",
    "input": { "messages": [{ "role": "user", "content": "Merge this diff." }] },
    "output": { "turns": [{ "role": "assistant", "content": "truncated code with syntax error..." }] }
  }
]
```

## Train with `DPORecipe`

Pass an existing SFT [`Artifact`](/docs/training/artifacts/) directly as `model=`, or chain `SFTRecipe` into `DPORecipe` in one expression with `.then(...)` so Stage 2 starts automatically on the server when Stage 1 finishes:

<DocsCodeTabs action={<DocsApiKeyAction />}>
  <DocsCodeTab label="From an SFT artifact">

```python
from grad import Grad, adapters, losses, optim
from grad.recipes import DPORecipe

client = Grad()
sft_art = client.artifacts.get("fast-diff-merge@sft-v1")
prefs = client.datasets.get("diff-merge-preferences")

dpo = client.runs.create(
    dataset=prefs,
    name="fast-diff-merge",
    recipe=DPORecipe(
        model=sft_art,
        adapter=adapters.LoRA(rank=32),
        loss=losses.DPO(beta=0.1),
        optimizer=optim.AdamW(lr=5e-5),
    ),
).wait()

print(dpo.artifact.id, dpo.eval_report)
```

  <DocsCodeTab label="Chain SFT → DPO (.then)">

```python
from grad import Grad, Model, adapters, losses, optim, splits
from grad.recipes import DPORecipe, SFTRecipe

client = Grad()
sft_ds = client.datasets.get("diff-merge-prod").filter(
    lambda t: t.scores.get("tests_passed") == 1.0,
)
prefs_ds = client.datasets.get("diff-merge-preferences")

dpo = (
    client.runs.create(
        dataset=sft_ds,
        name="fast-diff-merge",
        recipe=SFTRecipe(
            model=Model("Qwen/Qwen3-8B"),
            adapter=adapters.LoRA(rank=32),
            optimizer=optim.AdamW(lr=2e-4),
            split=splits.BySession(eval_fraction=0.10),
        ),
    )
    .then(
        dataset=prefs_ds,
        recipe=DPORecipe(
            adapter=adapters.LoRA(rank=32),
            loss=losses.DPO(beta=0.1),
            optimizer=optim.AdamW(lr=5e-5),
        ),
    )
    .wait()
)
```

```ts
import { Grad, adapters, losses, optim, recipes } from "@gradiated/grad";

const grad = new Grad();
const sftArt = await grad.artifacts.get("fast-diff-merge@sft-v1");
const prefs = await grad.datasets.get("diff-merge-preferences");

const dpo = await grad.runs
  .create({
    dataset: prefs,
    name: "fast-diff-merge",
    recipe: recipes.dpo({
      model: sftArt,
      adapter: adapters.lora({ rank: 32 }),
      loss: losses.dpo({ beta: 0.1 }),
      optimizer: optim.adamW({ lr: 5e-5 }),
    }),
  })
  .wait();

console.log(dpo.artifact.id, dpo.evalReport);
```

### When to use SFT vs. DPO vs. RL

- **Start with [SFT](/docs/training/recipes/sft/)** when the model doesn't follow your format, schema, or style yet and you have examples of good answers.
- **Follow with DPO (`DPORecipe`)** when the model mostly works but keeps repeating specific mistakes you can show as `(chosen, rejected)` pairs.
- **Move to [RL (`GRPORecipe`)](/docs/training/recipes/rl-agents/)** when you can grade answers automatically with tests, validators, or a judge and want the model to discover better solutions on its own.

### Key parameters

- **`losses.DPO(beta=...)`:** higher `beta` (`0.2`–`0.5`) stays closer to your starting model; lower (`0.05`–`0.1`) pushes harder away from rejected patterns.
- **`optim.AdamW(lr=...)`:** use a smaller learning rate than SFT (`2e-5`–`5e-5`) so you don't break formatting you already taught it.
- **`adapters.LoRA(rank=32)`:** exports a lightweight adapter by default so multiple adapters share one base model in production. Pass `merge_on_export=True` only if you want a standalone merged checkpoint.

## Deploy

Roll out the updated [`Artifact`](/docs/training/artifacts/) to your [`Endpoint`](/docs/training/endpoints/) on 10% of traffic first so you can compare it directly against your SFT version:

```python
endpoint = dpo.deploy(canary=0.10)
```

## Want more control?

You can swap `losses.DPO()` for your own PyTorch `losses.CustomLoss` (like SimPO, ORPO, or KTO) right inside `DPORecipe` — see [Custom loops](/docs/training/custom-loops/) and [Advanced objectives](/docs/training/advanced-objectives/).
