# Embeddings

<DocsLead>Fine-tune an embedding model on your own docs and codebase for better search.</DocsLead>

General-purpose embedding models often miss internal acronyms, product names, and custom schemas. Fine-tuning a small encoder with **`EmbeddingRecipe`** on your own query/document pairs usually boosts top-10 search hit rate by 10–25 points while staying under 10 ms per request.

## What data you need

Each training example is a `Triplet` with three parts:

- **`query`:** what a user (or agent) searched for.
- **`positive`:** the doc or code snippet that actually answers the query.
- **`negatives`:** one or more wrong docs that look similar to the right one, so the model learns to rank the right doc above them.

Aim for **1,000–5,000 triplets** in a [`Dataset`](/docs/training/trajectories/). Push them directly with `Triplet`:

```python
from grad import Grad, Triplet

client = Grad()
dataset = client.datasets.create("docs-retrieval-triplets")

dataset.push([
    Triplet(
        query="how do I rotate my api key?",
        positive="To rotate an existing API key, open Settings > API Keys and click Regenerate.",
        negatives=[
            "To create your first API key, open Settings > API Keys and click New Key.",
            "API keys are scoped to a single workspace and can be revoked at any time.",
        ],
    ),
])
```

**Why wrong docs should be close misses:** if the query is *"rotate my api key"* and the negative is *"Pricing FAQ"*, any base model already knows those are unrelated and learns almost nothing. Pulling close-but-wrong results from your current search or RAG pipeline (like *"create an API key"* when the user asked to *rotate* one) teaches the model the exact distinctions it currently gets wrong. If you only have `(query, positive)` pairs to start, you can omit `negatives` and `EmbeddingRecipe` will use other docs in the same batch as negatives, though adding real close-miss negatives improves ranking quality further.

## Train with `EmbeddingRecipe`

<DocsCodeTabs action={<DocsApiKeyAction />}>
  <DocsCodeTab label="Python">

```python
from grad import Grad, adapters, losses, optim, pooling
from grad.recipes import EmbeddingRecipe

client = Grad()
dataset = client.datasets.get("docs-retrieval-triplets")

recipe = EmbeddingRecipe(
    model="baai/bge-small-en-v1.5",
    adapter=adapters.Full(),
    pool=pooling.Mean(),
    loss=losses.InfoNCE(temp=0.05),
    optimizer=optim.AdamW(lr=2e-5),
)

run = client.runs.create(dataset=dataset, name="docs-embedder", recipe=recipe).wait()

print(run.artifact.id, run.eval_report)
```

import { Grad, adapters, losses, optim, pooling, recipes } from "@gradiated/grad";

const grad = new Grad();

const run = await grad.runs

### When to use embeddings vs. decision models vs. Cartridges

- **Use `EmbeddingRecipe`** when you search or retrieve across thousands or millions of documents (RAG, code search, semantic deduplication) and general-purpose embeddings miss your domain terms.
- **Use a [Decision model](/docs/training/recipes/decision-model/)** when you want a direct answer (a category, yes/no probability, or score) rather than nearest-neighbor search.
- **Use [Context Cartridges](/docs/training/recipes/cartridges/)** when your docs fit in ~10k–100k tokens and are mostly static, so you can skip retrieval and bake them straight into a small KV prefix.

### Key parameters

- **`model`:** start with a compact encoder like `"baai/bge-small-en-v1.5"` (sub-10 ms inference). Move to a larger encoder only if retrieval quality plateaus on long code or technical text.
- **`adapter=adapters.Full()`:** because embedding encoders are small (~33M–300M parameters), training all weights is fast and usually beats LoRA.
- **`pool=pooling.Mean()`:** averages token vectors into one vector per document (the standard choice for dense search).
- **`losses.InfoNCE(temp=0.05)`:** pulls matching `(query, positive)` pairs together and pushes `negatives` apart; lower `temp` (`0.03`–`0.05`) sharpens rankings when wrong docs are very similar to the right one.
- **`optim.AdamW(lr=...)`:** keep the learning rate low (`1e-5`–`3e-5`) for full encoder fine-tuning.

## Embed offline or deploy

Extract normalized embeddings directly from the exported [`Artifact`](/docs/training/artifacts/), [deploy](/docs/training/deploying/) it on Gradiated Cloud (callable via `openai.embeddings.create(model="your-org/docs-embedder", ...)`), or download the weights for your own serving stack:

```python
from grad import Record, pooling

vectors = run.artifact.embed(
    [Record(text="rotate api keys")],
    pool=pooling.Mean(),
).embeddings

run.deploy()
```
