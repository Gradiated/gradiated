# Embeddings

<DocsLead>
  Fine-tune an embedding model on your own docs and codebase for better search.
</DocsLead>

General-purpose embedding models often miss internal acronyms, product names, and custom schemas. Fine-tuning a small encoder with **`EmbeddingRecipe`** on your own query/document pairs usually boosts top-10 search hit rate by 10–25 points while staying under 10 ms per request.

## What data you need

Each training example is a triplet with three parts:

- **`query`:** what a user (or agent) searched for.
- **`positive`:** the doc or code snippet that actually answers the query.
- **`negatives`:** one or more wrong docs that look similar to the right one, so the model learns to rank the right doc above them.

Aim for **1,000–5,000 triplets** in a [`Dataset`](/docs/training/trajectories/). Push them as plain records (a `.jsonl` path with the same keys works too, and `grad.Triplet(...)` is available if you want type checking):

```python
from grad import Grad

client = Grad()
dataset = client.datasets.push("docs-retrieval-triplets", [
    {
        "query": "how do I rotate my api key?",
        "positive": "To rotate an existing API key, open Settings > API Keys and click Regenerate.",
        "negatives": [
            "To create your first API key, open Settings > API Keys and click New Key.",
            "API keys are scoped to a single workspace and can be revoked at any time.",
        ],
    },
])
```

**Why wrong docs should be close misses:** if the query is _"rotate my api key"_ and the negative is _"Pricing FAQ"_, any base model already knows those are unrelated and learns almost nothing. Pulling close-but-wrong results from your current search or RAG pipeline (like _"create an API key"_ when the user asked to _rotate_ one) teaches the model the exact distinctions it currently gets wrong. If you only have `(query, positive)` pairs to start, you can omit `negatives` and `EmbeddingRecipe` will use other docs in the same batch as negatives, though adding real close-miss negatives improves ranking quality further.

## Train with `EmbeddingRecipe`

<DocsCodeTabs action={<DocsApiKeyAction />}>
  <DocsCodeTab label="Python">

```python
from grad import Grad
from grad.recipes import EmbeddingRecipe

client = Grad()
dataset = client.datasets.get("docs-retrieval-triplets")

run = client.runs.create(
    dataset=dataset,
    name="docs-embedder",
    recipe=EmbeddingRecipe(),  # manages its own encoder, baai/bge-small-en-v1.5
).wait()

print(run.artifact.id, run.eval_report)
```

### When to use embeddings vs. decision models vs. Cartridges

- **Use `EmbeddingRecipe`** when you search or retrieve across thousands or millions of documents (RAG, code search, semantic deduplication) and general-purpose embeddings miss your domain terms.
- **Use a [Decision model](/docs/training/recipes/decision-model/)** when you want a direct answer (a category, yes/no probability, or score) rather than nearest-neighbor search.
- **Use [Context Cartridges](/docs/training/recipes/cartridges/)** when your docs fit in the model's context window and are mostly static, so you can skip retrieval and bake them straight into a small KV prefix.

### Parameters you might change

- **`loss=losses.InfoNCE(temp=...)`:** pulls matching `(query, positive)` pairs together and pushes `negatives` apart. `temp` is `0.05` by default; lower it (to `0.03`) to sharpen rankings when wrong docs are very similar to the right one.
- **`pool`:** `pooling.Mean()` (the default) averages the token vectors; `pooling.CLS()` uses the first token's vector.
- **`model`:** leave it out to use the recipe-managed encoder, `baai/bge-small-en-v1.5` (sub-10 ms inference). `grad models list --recipe embedding` shows any other encoders your server offers.

The recipe trains every weight of the encoder (they're small enough that this beats LoRA), and `run.artifact` is the checkpoint with the best held-out top-10 hit rate. Every other setting has a default; see the [training parameters reference](/docs/reference/training-parameters/#embeddingrecipe).

## Deploy or download

[Deploy](/docs/training/deploying/) the trained [`Artifact`](/docs/training/artifacts/) on Gradiated Cloud and embed with `client.embeddings.create(...)` (or `openai.embeddings.create(model="your-org/docs-embedder", ...)`). Vectors are L2-normalized and use the trained pooling:

```python
from grad import Grad

client = Grad()
client.deploy("docs-embedder@latest")

vectors = client.embeddings.create(model="docs-embedder", input=["rotate api keys"]).embeddings
```

To serve it yourself, download it. The artifact is a standard transformers model directory with sentence-transformers pooling files, so `SentenceTransformer("./docs-embedder")` loads it:

```python
from grad import Grad

client = Grad()
client.artifacts.download("docs-embedder@latest", "./docs-embedder", format="files")
```
