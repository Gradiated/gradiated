# Reward models and verifiers

<DocsLead>Train pairwise Bradley-Terry reward models, step-level process verifiers, and generative judges to grade RL rollouts and gate production cascades.</DocsLead>

When unit tests or exact-match rules cannot grade an output on their own, train a dedicated verifier artifact. The same artifact works in two places: inside a [Rubric](/docs/training/environments/) during RL, and as the `verifier` stage inside a production `strategies.Cascade` or `strategies.MajorityVote` [Endpoint](/docs/training/endpoints/).

## Choose a verifier type

| Type | Output | Best for |
| --- | --- | --- |
| **Pairwise reward model (Bradley-Terry)** | Scalar score per response | Ranking candidates, best-of-N reranking, or scoring open-ended quality from `(chosen, rejected)` pairs. |
| **Process reward model (PRM)** | Score per reasoning step or tool call | Dense credit assignment in multi-turn agents and catching bad steps early. |
| **Generative verifier (GenRM)** | Short critique + `yes` / `no` verdict | Complex rubric grading where chain-of-thought reasoning beats a single linear head. |

## 1. Pairwise Bradley-Terry reward model

Use `(chosen, rejected)` [trajectories](/docs/training/trajectories/) sharing a `group_id` and train a single scalar head (`heads.Linear(dim=1)`) with a shuffle-safe `BradleyTerryLoss` using `grad.by_group()`:

```python
import torch
import torch.nn.functional as F
import grad
from grad import Grad, Model, adapters, heads, losses, optim

class BradleyTerryLoss(losses.CustomLoss):
    outputs = ("heads",)

    def compute(self, datums, out) -> torch.Tensor:
        terms = [
            -F.logsigmoid(g["chosen"].heads["rm"][0] - g["rejected"].heads["rm"][0])
            for g in grad.by_group(datums, out)
        ]
        return torch.stack(terms).mean()

client = Grad()

with client.trainers.create(
    model=Model("Qwen/Qwen3-8B"),
    adapter=adapters.LoRA(rank=32, merge_on_export=True),
    heads={"rm": heads.Linear(dim=1)},
) as trainer:
    for batch in pair_batches:
        fb = trainer.forward_backward(batch, loss=BradleyTerryLoss())
        trainer.optim_step(optim.AdamW(lr=1e-4)).result()
        print(f"bt_loss={fb.result().loss:.4f}")

    rm_artifact = trainer.export(name="sql-verifier")
```

Score candidate rollouts (passing `Trajectory` or `ModelInput` lists directly) offline or inside a rubric using batched inference:

```python
scores = [
    torch.sigmoid(res.logits[0]).item()
    for res in rm_artifact.infer_batch(candidate_trajectories)
]
```

## 2. Step-level process reward model (PRM)

Attach a `token_level=True` head and label only the end-of-step token positions using the built-in `losses.BCESparsePositions` loss:

```python
from grad import Datum, DatumTargets, Grad, Model, ModelInput, adapters, heads, losses, optim

client = Grad()

datums = [
    Datum(
        ModelInput(tokens=step_traj_tokens),
        DatumTargets(
            positions=[42, 98, 151],     # token indices ending steps 1, 2, 3
            labels=[1.0, 1.0, 0.0],      # step 3 introduced an error
        ),
    ),
]

with client.trainers.create(
    model=Model("Qwen/Qwen3-8B"),
    adapter=adapters.LoRA(rank=32),
    heads={"prm": heads.Linear(dim=1, token_level=True)},
) as trainer:
    m = trainer.forward_backward(datums, loss=losses.BCESparsePositions(head="prm")).result()
    trainer.optim_step(optim.AdamW(lr=1e-4)).result()
    prm_artifact = trainer.export(name="reasoning-prm")
```

At inference time, `prm_artifact.infer(inp).heads["prm"]` returns a `(L, 1)` tensor with a calibrated correctness logit at every step boundary.

## 3. Generative verifier (GenRM)

When grading requires reasoning (checking subtle policy violations or comparing code diffs against requirements), train a small 4B–8B model with [`SFTRecipe`](/docs/training/recipes/sft-dpo/) on `(prompt, candidate, critique + verdict)` trajectories, optionally followed by [`GRPORecipe`](/docs/training/recipes/rl-agents/) where the reward is exact agreement with human labels.

Deploy the trained verifier with `strategies.MajorityVote` for higher accuracy at test time:

```python
from grad import strategies

judge = client.artifacts.get("policy-judge@2026-11-25-1")

client.endpoints.create(
    slug="policy-judge",
    artifact=judge,
    strategy=strategies.MajorityVote(n_samples=5),
)
```

## Use a verifier in production cascades

Pass any trained reward model or verifier artifact into a `strategies.Cascade` [endpoint](/docs/training/endpoints/) so easy requests stay on a fast 8B model while low-scoring outputs escalate automatically:

```python
from grad import Model, strategies

agent = client.artifacts.get("sql-agent@2026-11-25-2")
verifier = client.artifacts.get("sql-verifier@2026-11-25-1")
capture = client.datasets.get("sql-agent-prod")

client.endpoints.create(
    slug="sql-agent",
    artifact=agent,
    capture_dataset=capture,
    strategy=strategies.Cascade(
        verifier=verifier,
        frontier=Model("Qwen/Qwen3-32B"),
        threshold=0.75,
    ),
)
```
