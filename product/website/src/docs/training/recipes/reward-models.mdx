# Reward models

<DocsLead>Train a small model to score how good another model's answers are.</DocsLead>

When unit tests or syntax checks aren't enough to grade an answer — or calling a frontier `Judge` on every request is too slow or expensive — train your own verifier [`Artifact`](/docs/training/artifacts/) with **`RewardModelRecipe`**. You can use the same verifier in three places:

- Inside a [`Judge`](/docs/training/rubrics/) to score a [`Dataset`](/docs/training/trajectories/) or grade [`GRPORecipe`](/docs/training/recipes/rl-agents/) runs.
- Inside a `strategies.Cascade` [`Endpoint`](/docs/training/endpoints/) so easy requests stay on a fast 8B model and low-scoring answers automatically fall back to a frontier model.
- With `strategies.BestOfN` or `strategies.MajorityVote` to pick the best of several candidate answers.

## What data you need

- **Minimum volume:** 500–2,000 `(chosen, rejected)` pairs in a [`Dataset`](/docs/training/trajectories/) (same format as [Preference tuning (DPO)](/docs/training/recipes/dpo/), sharing a `group_id` with `role: "chosen"` and `role: "rejected"`).

## Train with `RewardModelRecipe`

<DocsCodeTabs action={<DocsApiKeyAction />}>
  <DocsCodeTab label="Python">

```python
from grad import Grad, Model, adapters, optim, splits
from grad.recipes import RewardModelRecipe

client = Grad()
pairs_ds = client.datasets.get("sql-preferences")

recipe = RewardModelRecipe(
    model=Model("Qwen/Qwen3-8B"),
    adapter=adapters.LoRA(rank=32),
    optimizer=optim.AdamW(lr=1e-4),
    split=splits.BySession(eval_fraction=0.10),
)

run = client.runs.create(dataset=pairs_ds, name="sql-verifier", recipe=recipe).wait()

print(run.artifact.id, run.eval_report)
```

```ts
import { Grad, Model, adapters, optim, recipes, splits } from "@gradiated/grad";

const grad = new Grad();
const pairsDs = await grad.datasets.get("sql-preferences");

const run = await grad.runs
  .create({
    dataset: pairsDs,
    name: "sql-verifier",
    recipe: recipes.rewardModel({
      model: new Model("Qwen/Qwen3-8B"),
      adapter: adapters.lora({ rank: 32 }),
      optimizer: optim.adamW({ lr: 1e-4 }),
      split: splits.bySession({ evalFraction: 0.1 }),
    }),
  })
  .wait();

console.log(run.artifact.id, run.evalReport);
```

### Key parameters

- **`model`:** start with a fast 4B–8B model (`Model("Qwen/Qwen3-8B")`) — reward models only score an output in a single forward pass, so an 8B verifier runs in milliseconds.
- **`adapter`:** `adapters.LoRA(rank=32)` works well for 500–5,000 preference pairs.
- **`optim.AdamW(lr=...)`:** start around `1e-4` for LoRA reward models.
- **`split`:** `splits.BySession(eval_fraction=0.10)` keeps paired examples and multi-turn conversations together so eval accuracy isn't inflated.

## Use your verifier in `Judge` or production cascades

### 1. Plug straight into a `Judge` (for datasets or RL)

Because `Artifact` subclasses `Model`, pass `run.artifact` directly to [`Judge`](/docs/training/rubrics/) with no prompt required:

```python
from grad import Judge

sql_judge = Judge(name="sql_quality", model=run.artifact)
scored = client.datasets.get("sql-prod").score(sql_judge).wait()
```

### 2. Gate a production `Cascade` endpoint

Pair a fast fine-tuned specialist with your verifier so only uncertain outputs escalate to a frontier model:

```python
from grad import Model, strategies

agent = client.artifacts.get("sql-agent@2026-11-25-2")
verifier = run.artifact
capture = client.datasets.get("sql-agent-prod")

client.endpoints.create(
    slug="sql-agent",
    artifact=agent,
    capture_dataset=capture,
    strategy=strategies.Cascade(
        verifier=verifier,
        frontier=Model("Qwen/Qwen3-32B"),
        threshold=0.75,
    ),
)
```

## When to train a reward model vs. other graders

- **Use a [`Scorer`](/docs/training/rubrics/) (code check)** first whenever correctness can be checked in Python (JSON schema, SQL parser, unit tests). It's instant and free.
- **Use a frontier [`Judge`](/docs/training/rubrics/)** (`Model("claude-sonnet-4-6")`) while prototyping — no training data needed, just a prompt.
- **Train a reward model (`RewardModelRecipe`)** once you have 500–2,000 graded pairs and want fast, cheap scoring at scale (for RL training or live `Cascade` fallback checks).
