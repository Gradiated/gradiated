# Reward models

<DocsLead>Train a small model to score how good another model's answers are.</DocsLead>

## When to train a reward model

Most teams do not need to train a reward model. Pick the simplest grader that fits your task:

- **Use a [`Scorer`](/docs/training/rubrics/) (code check)** first whenever correctness can be checked deterministically in code (JSON schema, SQL parser, unit tests). It's instant and free.
- **Use a [`Judge`](/docs/training/rubrics/) with a frontier or open model and a rubric** as your default for everything else. For most tasks, a prompted judge with clear criteria is the best route: it needs no training data and is easy to update as your requirements change.
- **Train a reward model (`RewardModelRecipe`)** when you want to strongly encode specific taste or domain-specific reward behavior from preference pairs, or when you need millisecond scoring inside your app or evaluation loop.

Before training a reward model, try a prompted [`Judge`](/docs/training/rubrics/) with a [`Rubric`](/docs/training/rubrics/) first:

```python
from grad import Judge, Rubric, Scorer, validators

rubric = Rubric([
    Scorer("valid_sql", weight=0.3, fn=validators.SQL()),
    Judge(
        name="accurate_query",
        model="{{SONNET_MODEL}}",
        prompt="Verify the SQL answers the user's question accurately without hallucinated columns.",
        weight=0.7,
    ),
])
```

If a prompted judge is still missing subtle preferences you can demonstrate with examples, train a dedicated reward model with **`RewardModelRecipe`**. You can use the trained [`Artifact`](/docs/training/artifacts/) to:

- Plug into a [`Judge`](/docs/training/rubrics/) to score a [`Dataset`](/docs/training/trajectories/) or grade [`GRPORecipe`](/docs/training/recipes/rl-agents/) runs.
- Score draft answers from a fast 8B model in your app so low-scoring answers fall back to a larger model.
- Rank multiple candidate answers (best-of-N) and return the highest-scoring one.

## What data you need

- **Minimum volume:** 500 to 2,000 `(chosen, rejected)` pairs in a [`Dataset`](/docs/training/trajectories/), in the same format as [Preference tuning (DPO)](/docs/training/recipes/dpo/): one `{"prompt", "chosen", "rejected"}` record per pair, or two trajectories sharing a `group_id`.
- **To try it first on public data:** `client.datasets.from_hf("trl-lib/ultrafeedback_binarized", split="train", chosen="chosen", rejected="rejected", limit=2000)` gives you a ready-made preference dataset.

## Train with `RewardModelRecipe`

<DocsCodeTabs action={<DocsApiKeyAction />}>
  <DocsCodeTab label="Python">

```python
from grad import Grad, splits
from grad.recipes import RewardModelRecipe

client = Grad()
pairs_ds = client.datasets.get("sql-preferences")  # pushed or imported earlier

recipe = RewardModelRecipe(
    model="qwen/qwen3-8b",
    split=splits.BySession(eval_fraction=0.10),
    # Defaults: LoRA(rank=32), lr="auto" (about 1e-4 here), batch_size=128, epochs=1
)
print(client.runs.plan(dataset=pairs_ds, recipe=recipe))

run = client.runs.create(
    dataset=pairs_ds,
    name="sql-verifier",
    recipe=recipe,
    max_cost_usd=25,
).wait()

print(run.artifact.id, run.eval_report)
```

const grad = new Grad();

const run = await grad.runs

### Key parameters

- **`model`:** start with a fast 4B to 8B model (`"qwen/qwen3-8b"`). Reward models only score an output in a single forward pass, so an 8B model runs in milliseconds.
- **`adapter`:** defaults to `adapters.LoRA(rank=32)` with `alpha=32` fixed, so changing the rank doesn't change the right learning rate. Rank `8`–`16` is enough for a few thousand pairs.
- **`lr="auto"`** *(default)*: typically resolves to about `1e-4` for `qwen/qwen3-8b` at batch 128. The dry run prints the exact value; pass a float to override it.
- **Checkpoints:** saved every 10% of steps; `run.artifact` is the checkpoint with the best held-out pair accuracy.
- **`split`:** `splits.BySession(eval_fraction=0.10)` keeps paired examples and multi-turn conversations together so eval accuracy isn't inflated.

## Use your reward model

### 1. Plug straight into a `Judge` (for datasets or RL)

Pass `run.artifact` straight into [`Judge`](/docs/training/rubrics/) with no prompt required:

```python
from grad import Judge

sql_judge = Judge(name="sql_quality", model=run.artifact)
scored = client.datasets.get("sql-prod").score(sql_judge).wait()
```

### 2. Gate a fast model in your app code

You can also [deploy](/docs/training/deploying/) your reward model (or download it to your own server) and use it to check answers from a fast 8B model before returning them, falling back to a larger model only when the score is low:

```python
import os
from openai import OpenAI
from grad import Record

oai = OpenAI(base_url="https://api.gradiated.com/v1", api_key=os.environ["GRADIATED_API_KEY"])
messages = [{"role": "user", "content": "How many orders shipped to Canada last month?"}]

draft = oai.chat.completions.create(model="your-org/sql-agent", messages=messages).choices[0].message.content
score = run.artifact.infer(Record(messages=[*messages, {"role": "assistant", "content": draft}])).score

if score < 0.75:
    draft = oai.chat.completions.create(model="qwen/qwen3-32b", messages=messages).choices[0].message.content
```
