# RL for agents (GRPO)

<DocsLead>Train models to pass tests, call tools, and recover from errors using verifiable reinforcement learning against a rubric or live Docker Compose environment.</DocsLead>

Use `GRPORecipe` (or a custom `Trainer` + `Environment` loop) when you can **grade an outcome** (unit tests pass, SQL returns the right rows, an API state matches expectations) even if you do not have a single gold answer. For best stability, warm-start with [SFT](/docs/training/recipes/sft-dpo/) first so the model already emits valid tool calls, then pass that SFT `Artifact` as `model=` (or chain both in a [`Pipeline`](/docs/training/recipes/)).

## Managed recipe vs. custom loop for RL

| Setup | Use | Why |
| --- | --- | --- |
| **Single-turn tasks + HTTP grader** | **`GRPORecipe` + `WebhookRubric`** | Pass a dataset of prompts and a grading webhook; Gradiated handles sampling, advantage normalization, and updates. |
| **Multi-turn apps, Docker Compose, seeded DBs, custom curricula** | **Custom loop (`Environment` + `Trainer`)** | Your environment stays on your own CPU/Kubernetes infrastructure and talks to `Artifact` and `Trainer` over HTTP. |

## Option A: Managed `GRPORecipe`

Provide a dataset of task prompts (see [Trajectories and data](/docs/training/trajectories/)) and a `WebhookRubric` backed by a named workspace secret (`grad secrets set eval-webhook-token`). Gradiated sends `Authorization: Bearer <secret>` with each rollout and expects `scores` plus a scalar `reward`:

```json
// POST https://eval.internal.example/grade-sql
{ "task": { "id": "q_42", "expected_rows": 12 }, "trajectory": { "output": { "turns": [...] } } }

// 200 OK
{ "scores": { "sql_valid": 1.0, "exact_rows": 1.0 }, "reward": 1.0 }
```

```python
from grad import Grad, WebhookRubric, adapters, losses, optim
from grad.recipes import GRPORecipe

client = Grad()
dataset = client.datasets.get("sql-benchmark-tasks")
sft_art = client.artifacts.get("sql-agent@sft-v1")
webhook_secret = client.secrets.get("eval-webhook-token")

recipe = GRPORecipe(
    model=sft_art,
    adapter=adapters.LoRA(rank=32),
    rubric=WebhookRubric(
        url="https://eval.internal.example/grade-sql",
        secret=webhook_secret,
    ),
    group_size=8,
    max_new_tokens=512,
    loss=losses.GRPO(clip_low=0.2, clip_high=0.28, kl_beta=0.01),
    optimizer=optim.AdamW(lr=2e-5),
)

run = client.runs.create(dataset=dataset, name="sql-agent", recipe=recipe).wait(
    on_metric=lambda m: print(f"step={m.step} reward={m.eval_metrics.get('mean_reward', 0):.3f}"),
)

print(run.artifact.id)
```

## Option B: Stateful multi-turn agents (custom loop)

When the agent must call tools against a real backend stack (Postgres, Redis, internal APIs), subclass `Environment` and drive `Trainer` directly. See [Environments and rubrics](/docs/training/environments/) for the full `AppComposeEnv` implementation.

```python
import grad
from grad import Grad, adapters, losses, optim

client = Grad()
sft_art = client.artifacts.get("support-agent@sft-v1")

with client.trainers.create(
    model=sft_art,
    adapter=adapters.LoRA(rank=32),
) as trainer:
    for step, task_batch in enumerate(task_batches):
        groups = env.rollout_groups(
            artifact=trainer.snapshot(),
            tasks=task_batch,
            group_size=8,
            max_turns=6,
            max_new_tokens=512,
            max_concurrency=8,
            timeout_s=60,
        )

        # Group-normalize rewards and automatically skip zero-variance prompt groups
        datums = grad.group_datums(groups, norm="std", skip_zero_var=True)

        fb = trainer.forward_backward(datums, loss=losses.GRPO(clip_low=0.2, clip_high=0.28))
        opt = trainer.optim_step(optim.AdamW(lr=2e-5, grad_clip=1.0))
        m = fb.result()
        opt.result()

        print(f"step={step} datums={len(datums)} loss={m.loss:.4f} kl_st={m.metrics['kl_sample_train']:.5f}")

    artifact = trainer.export(name="support-agent", merge_adapter=True)
```

## Practical checks that prevent wasted training tokens

1. **Verify observation masking:** Tool responses, retrieved docs, and error tracebacks must have `loss_mask = 0.0`. Using `Environment.step()` returning `Observation(text=...)` or `traj.append_env_tokens()` enforces this automatically.
2. **Watch zero-variance group rate:** If >70% of prompt groups get all `0.0` (too hard) or all `1.0` (too easy), add partial-credit rubric scorers or filter your task pool to medium-difficulty prompts.
3. **Warm-start with SFT:** If the base model emits malformed tool JSON on >30% of rollouts, run a short [SFT](/docs/training/recipes/sft-dpo/) stage on 200–500 valid trajectories first, then pass `model=sft.artifact`.
4. **Monitor `kl_sample_train`:** Every RL `forward_backward` step logs `kl_sample_train` and `sample_train_max_diff` comparing the sampler's logprobs against the trainer's recomputed logprobs. Sudden spikes on on-policy steps immediately flag a chat-template or tokenization mismatch.

<DocsCallout label="Already have an OpenAI-SDK or LangGraph agent?" tone="tip">
You do not need to rewrite your agent loop to call `artifact.sample()`. Wrap `trainer.snapshot()` with `snap.openai_client()` (see [Environments and rubrics](/docs/training/environments/)) to run your existing agent unchanged while recording exact 1:1 token-aligned trajectories for GRPO.
</DocsCallout>

## Choosing an RL method for your environment

All modern policy-gradient methods share the same rollout loop and `trainer.forward_backward(datums, loss=...)` call — only the advantage normalization or `Loss` class changes.

| Method | When to use it | How to run it |
| --- | --- | --- |
| **GRPO** | Default synchronous RL against verifiable rubrics. | `grad.group_datums(groups, norm="std")` + `losses.GRPO(clip_low=0.2, clip_high=0.2)` |
| **Dr. GRPO** | Remove std-division and length bias in reasoning RL. | `grad.group_datums(groups, norm="mean")` + constant-denominator `CustomLoss` |
| **DAPO** | Long reasoning or multi-turn coding where standard clipping collapses entropy. | `losses.GRPO(clip_low=0.2, clip_high=0.28)` + `skip_zero_var=True` + length penalty in `Rubric` |
| **CISPO** | Async rollout pools where Docker Compose workers finish 1–4 weight versions behind the trainer. | `losses.CISPO(clip_low=0.2, clip_high=0.28)` — stable under off-policy lag |
| **PPO + Critic** | Dense per-token value baselines with GAE when group sampling is too expensive. | Attach `heads={"v": heads.Linear(dim=1, token_level=True)}` + `PPOGAELoss(CustomLoss)` |
| **RLOO** | Small group sizes (`group_size=4`) where std-normalization is noisy. | `grad.group_datums(groups, norm="rloo")` + `losses.ImportanceSampling(kl_beta=0.02)` |
| **REINFORCE++** | Global batch stability with per-token KL shaping against a frozen reference. | Score `ref.score_logprobs(trajs).aligned_logprobs`, whiten active tokens, pass `advantages=[...]` to `to_datum()` |
| **GSPO** | MoE models or long multi-turn agent trajectories where token-level importance ratios diverge. | Sequence-level geometric mean ratio in 7 lines via `GSPOLoss(CustomLoss)` |

### Example: swapping RL algorithms or running async rollouts

```python
from concurrent.futures import ThreadPoolExecutor
import grad
from grad import losses, optim

# Overlap slow Docker Compose rollouts with training steps; refresh snapshot every step.
with ThreadPoolExecutor(max_workers=1) as pool:
    next_rollouts = pool.submit(env.rollout_groups, trainer.snapshot(), batches[0], group_size=8, max_turns=6)

    for step in range(len(batches)):
        groups = next_rollouts.result()
        if step + 1 < len(batches):
            next_rollouts = pool.submit(env.rollout_groups, trainer.snapshot(), batches[step + 1], group_size=8, max_turns=6)

        datums = grad.group_datums(groups, norm="std")
        trainer.forward_backward(datums, loss=losses.CISPO(clip_low=0.2, clip_high=0.28)).result()
        trainer.optim_step(optim.AdamW(lr=2e-5, grad_clip=1.0)).result()
```

```python
import torch
import grad
from grad import losses, optim

# Trainer created with heads={"v": heads.Linear(dim=1, token_level=True)}
class PPOGAELoss(losses.CustomLoss):
    outputs = ("logprobs", "heads")

    def __init__(self, eps: float = 0.2, vf_coef: float = 0.5):
        self.eps, self.vf_coef = eps, vf_coef

    def compute(self, datums, out) -> torch.Tensor:
        terms = []
        for lp, old_lp, v, mask, d in zip(out.logprobs, out.sampling_logprobs, out.heads["v"], out.masks, datums):
            ret = torch.full_like(v[:, 0], float(d.targets.scalar))
            adv = ret - v[:, 0].detach()
            r = torch.exp(lp - old_lp)
            pg = -torch.minimum(r * adv, r.clamp(1.0 - self.eps, 1.0 + self.eps) * adv)
            vf = 0.5 * (v[:, 0] - ret) ** 2
            terms.append(grad.masked_mean(pg + self.vf_coef * vf, mask))
        return torch.stack(terms).mean()

trainer.forward_backward(datums, loss=PPOGAELoss()).result()
trainer.optim_step(optim.AdamW(lr=2e-5, grad_clip=1.0)).result()
```

```python
import torch
import grad
from grad import losses, optim

class GSPOLoss(losses.CustomLoss):
    outputs = ("logprobs",)

    def __init__(self, eps_low: float = 3e-4, eps_high: float = 4e-4):
        self.eps_low, self.eps_high = eps_low, eps_high

    def compute(self, datums, out) -> torch.Tensor:
        terms = []
        for lp, old_lp, adv, mask in zip(out.logprobs, out.sampling_logprobs, out.advantages, out.masks):
            # Geometric-mean importance ratio over generated tokens only (env tokens masked out)
            s = torch.exp(grad.masked_mean(lp - old_lp, mask))
            a_seq = grad.masked_mean(adv, mask)
            terms.append(-torch.minimum(s * a_seq, s.clamp(1.0 - self.eps_low, 1.0 + self.eps_high) * a_seq))
        return torch.stack(terms).mean()

fb = trainer.forward_backward(datums, loss=GSPOLoss())
trainer.optim_step(optim.AdamW(lr=2e-5, grad_clip=1.0)).result()
```

  <DocsCodeTab label="Multi-turn per-turn KL (SCoRe)">

```python
import torch
import grad
from grad import losses, optim

# `turn_ids` on each Datum identifies which turn generated each token.
ref_lps = ref_artifact.score_logprobs(trajectories).aligned_logprobs
datums = grad.group_datums(groups, norm="mean", ref_logprobs=ref_lps)

class PerTurnKLLoss(losses.CustomLoss):
    outputs = ("logprobs",)

    def compute(self, datums, out) -> torch.Tensor:
        terms = []
        for lp, old_lp, rlp, adv, mask, tids in zip(
            out.logprobs, out.sampling_logprobs, out.ref_logprobs, out.advantages, out.masks, out.turn_ids,
        ):
            kl_beta = torch.where(tids == 0, 0.20, 0.01)
            kl = torch.exp(rlp - lp) - (rlp - lp) - 1.0
            w = torch.exp(lp - old_lp).clamp(0.8, 1.2).detach()
            terms.append(grad.masked_mean(-w * adv * lp + kl_beta * kl, mask))
        return torch.stack(terms).mean()

fb = trainer.forward_backward(datums, loss=PerTurnKLLoss())
trainer.optim_step(optim.AdamW(lr=2e-5)).result()
```

## Sampling controls and structured tool calls

`artifact.sample()` and `env.rollout_groups()` support stop delimiters, nucleus sampling, deterministic seeds, and grammar-constrained JSON while preserving exact 1:1 `sampling_logprobs` for policy-gradient updates:

```python
from grad import ResponseFormat

rollouts = snap.sample(
    prompt_inputs,
    n=8,
    temperature=0.8,
    top_p=0.95,
    max_new_tokens=512,
    stop=["</tool_call>", "\nObservation:"],
    seed=42,
    response_format=ResponseFormat.json_schema(tool_call_schema),
)
```

Use `stop` (strings or token IDs) to halt generation cleanly at tool-call boundaries so the environment can execute the tool and append its output before the next turn.

## Deploy with test-time scaling or cascade

RL-tuned 4B–8B agents often match a frontier model on 80–90% of requests. Pair the trained artifact with a [trained verifier](/docs/training/recipes/reward-models/) in a `strategies.Cascade` [endpoint](/docs/training/endpoints/) so hard tasks still escalate cleanly:

```python
from grad import Model, strategies

agent = client.artifacts.get("sql-agent@2026-11-25-2")
verifier = client.artifacts.get("sql-verifier@v1")
capture = client.datasets.get("sql-agent-prod")

client.endpoints.create(
    slug="sql-agent",
    artifact=agent,
    capture_dataset=capture,
    strategy=strategies.Cascade(
        verifier=verifier,
        frontier=Model("Qwen/Qwen3-32B"),
        threshold=0.75,
    ),
)
```
