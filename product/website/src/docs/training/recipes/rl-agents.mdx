# RL for agents

<DocsLead>Train models to pass checks, write accurate queries, and use tools reliably with verifiable reinforcement learning using `GRPORecipe`.</DocsLead>

Use **`GRPORecipe`** when you can **grade an outcome** (SQL returns valid syntax and the right answer, unit tests pass, an API state matches expectations) even if there is no single gold response. For best stability, warm-start with [Supervised fine-tuning (SFT)](/docs/training/recipes/sft/) first so the model already follows your format and tool schemas, then pass that SFT [`Artifact`](/docs/training/artifacts/) as `model=` (or chain directly with [`.then(...)`](/docs/training/recipes/)).

## Managed `GRPORecipe` vs. stateful `Environment`

| Setup | Use | Why |
| --- | --- | --- |
| **Single-turn tasks + [`Rubric`](/docs/training/rubrics/) (`Judge` / `validators.*`)** | **`GRPORecipe` + `Rubric`** | Pass a [`Dataset`](/docs/training/trajectories/) of prompts and a declarative `Rubric`; Gradiated handles sampling, grading, and updates server-side. |
| **Multi-turn apps, Harbor, Docker Compose, seeded DBs** | **[`Environment`](/docs/training/environments/) + [`Trainer`](/docs/training/custom-loops/)** | Your containers and tools stay on your own infrastructure and talk to `Artifact` and `Trainer` over HTTP. |

## Train with `GRPORecipe`

Provide a `Dataset` of task prompts and a [`Rubric`](/docs/training/rubrics/) combining deterministic checks (`validators.SQL()`, `validators.TypeScriptAST()`, `validators.JSONSchema(...)`) and/or a `Judge` (either a catalog `Model` or a fine-tuned [reward model](/docs/training/recipes/reward-models/) `Artifact`):

<DocsCodeTabs action={<DocsApiKeyAction />}>
  <DocsCodeTab label="Python">

```python
from grad import Grad, Judge, Model, Rubric, Scorer, adapters, losses, optim, validators
from grad.recipes import GRPORecipe

client = Grad()
dataset = client.datasets.get("sql-benchmark-tasks")
sft_art = client.artifacts.get("sql-agent@sft-v1")

recipe = GRPORecipe(
    model=sft_art,
    adapter=adapters.LoRA(rank=32, merge_on_export=True),
    rubric=Rubric([
        Scorer("valid_sql", weight=0.3, fn=validators.SQL()),
        Judge(
            name="correct_query",
            model=Model("claude-sonnet-4-6"),
            prompt="Verify the SQL answers the question accurately without hallucinated columns.",
            weight=0.7,
        ),
    ]),
    group_size=8,
    max_new_tokens=512,
    loss=losses.GRPO(clip_low=0.2, clip_high=0.28, kl_beta=0.01),
    optimizer=optim.AdamW(lr=2e-5),
)

run = client.runs.create(dataset=dataset, name="sql-agent", recipe=recipe).wait(
    on_metric=lambda m: print(f"step={m.step} reward={m.eval_metrics.get('mean_reward', 0):.3f}"),
)

print(run.artifact.id)
```

```ts
import { Grad, Judge, Model, Rubric, Scorer, adapters, losses, optim, recipes, validators } from "@gradiated/grad";

const grad = new Grad();
const dataset = await grad.datasets.get("sql-benchmark-tasks");
const sftArt = await grad.artifacts.get("sql-agent@sft-v1");

const run = await grad.runs
  .create({
    dataset,
    name: "sql-agent",
    recipe: recipes.grpo({
      model: sftArt,
      adapter: adapters.lora({ rank: 32, mergeOnExport: true }),
      rubric: new Rubric([
        new Scorer("valid_sql", { weight: 0.3, fn: validators.sql() }),
        new Judge({
          name: "correct_query",
          model: new Model("claude-sonnet-4-6"),
          prompt: "Verify the SQL answers the question accurately without hallucinated columns.",
          weight: 0.7,
        }),
      ]),
      groupSize: 8,
      maxNewTokens: 512,
      loss: losses.grpo({ clipLow: 0.2, clipHigh: 0.28, klBeta: 0.01 }),
      optimizer: optim.adamW({ lr: 2e-5 }),
    }),
  })
  .wait();

console.log(run.artifact.id);
```

## Practical tips before scaling up

1. **Warm-start with SFT:** If the base model emits malformed JSON or tool calls on >30% of rollouts, run a short [SFT](/docs/training/recipes/sft/) stage on 200–500 valid trajectories first, then pass `model=sft.artifact`.
2. **Watch zero-variance groups:** If >70% of prompts score all `0.0` (too hard) or all `1.0` (too easy), add partial-credit scorers to your [`Rubric`](/docs/training/rubrics/) or filter your task dataset to medium-difficulty prompts.
3. **Need multi-turn containers or production trace replay?** See [Environments](/docs/training/environments/) (including `environments.Harbor` and `environments.MCP`) and [Traces to environments](/docs/training/traces-to-environments/).

## Deploy with a cascade

RL-tuned 4B–8B agents often match a frontier model on 80–90% of requests. Pair the trained [`Artifact`](/docs/training/artifacts/) with a fine-tuned [reward model](/docs/training/recipes/reward-models/) in a `strategies.Cascade` [`Endpoint`](/docs/training/endpoints/) so hard tasks escalate automatically:

```python
from grad import Model, strategies

agent = client.artifacts.get("sql-agent@2026-11-25-2")
verifier = client.artifacts.get("sql-verifier@v1")
capture = client.datasets.get("sql-agent-prod")

client.endpoints.create(
    slug="sql-agent",
    artifact=agent,
    capture_dataset=capture,
    strategy=strategies.Cascade(
        verifier=verifier,
        frontier=Model("Qwen/Qwen3-32B"),
        threshold=0.75,
    ),
)
```
