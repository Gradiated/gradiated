# Model router

<DocsLead>Send each request to the cheapest model that still meets your quality bar.</DocsLead>

A model router looks at each incoming prompt and predicts how likely each candidate model is to succeed. At runtime, it picks the cheapest model that still meets your quality bar.

## What data you need

All you need to start is a [`Dataset`](/docs/training/trajectories/) of real prompts (`input.messages`):

- **How the router compares models:**
  - **Already logging multiple models?** If your logs include responses from both cheap and strong models (in `metadata.model`), Gradiated trains directly on them.
  - **Only logging one model so far?** Pass `models=[...]` to `RouterRecipe` (for example, a cheap model and your current frontier model). Gradiated replays your logged prompts against the candidate models first so it can compare how each one performs — no sandbox environment needed for single-turn prompts.
- **How quality is scored:**
  - **No scores yet?** Pass a [`Judge`](/docs/training/rubrics/) with a plain-English prompt (or a `Rubric` with code checks) and Gradiated grades each response for you.
  - **Already have scores in your logs?** Pass the score name (`score="task_success"`) or a function (`score=lambda t: t.scores["task_success"]`) to reuse them directly.
- **Request cost (optional):**
  - You don't need to log costs. Gradiated calculates request cost automatically from the model name and token counts using built-in model pricing.
  - If you have custom or self-hosted pricing, include `metrics.cost_usd` on your logs to override it.

Plan for ~500 examples per candidate model to get started (2,000+ if your prompts cover many different tasks).

## Train the router

By default, `RouterRecipe` fine-tunes `qwen/qwen3-0.6b` on your prompts and scores, holds out 15% of conversations for evaluation, and tunes routing to stay within your allowed quality drop:

<DocsCodeTabs action={<DocsApiKeyAction />}>
  <DocsCodeTab label="Python">

```python
from grad import Grad, Judge
from grad.recipes import RouterRecipe

client = Grad()
dataset = client.datasets.get("support-traces")

recipe = RouterRecipe(
    models=["qwen/qwen3-8b", "{{OPUS_MODEL}}"],
    score=Judge(
        name="resolved",
        model="{{SONNET_MODEL}}",
        prompt="Did the assistant solve the user's issue accurately?",
    ),
    max_quality_drop=0.02,
)

run = client.runs.create(dataset=dataset, name="support-router", recipe=recipe).wait()

print(run.artifact.id)
print(run.eval_report["pareto_summary"])
```

### When to use a router vs. fine-tuning vs. distillation

- **Start with a router (`RouterRecipe`)** when a cheap model already handles most of your requests well and you only need a frontier model for the hard ones. It's the fastest way to cut LLM spend without training a new generator.
- **Use [Supervised fine-tuning (SFT)](/docs/training/recipes/sft/) or [distillation](/docs/training/recipes/distillation/)** when no cheap model is good enough on its own yet and you want to teach a small model to handle the task directly.
- **Combine them** once you have a fine-tuned 8B model by putting it alongside a frontier model in your router.

### Key parameters

- **`models`:** the list of candidate models to route between. If your dataset only contains logs from one model, Gradiated replays your prompts against the others automatically. If your logs already include multiple models in `metadata.model`, you can leave `models` out.
- **`score`:** how quality is measured — pass a [`Judge`](/docs/training/rubrics/) with a prompt if your logs don't have scores yet, or pass an existing score name (`"task_success"`) or function (`lambda t: ...`).
- **`max_quality_drop`:** how much quality drop vs. your best model you're willing to trade for cost savings (default `0.02`, or 2%).
- **`model`:** the router backbone (`"qwen/qwen3-0.6b"` by default). Swap in a different model or a lightweight frozen-encoder fit in [Custom loops](/docs/training/custom-loops/) if you have strict CPU latency limits.
- **`split`:** defaults to `splits.BySession(eval_fraction=0.15)` so turns from the same conversation never leak between training and evaluation.
- **Custom pricing:** Gradiated uses built-in model pricing automatically; include `metrics.cost_usd` in your dataset (or pass `pricing=`) only if you have negotiated or self-hosted rates.

## Read the evaluation report

Before deploying, check `run.eval_report`:

```json
{
  "eval_examples": 480,
  "fallback_model": "{{OPUS_MODEL}}",
  "fallback_quality": 0.912,
  "pareto_summary": {
    "target_max_drop": 0.02,
    "routed_quality": 0.904,
    "quality_drop": 0.008,
    "quality_drop_ci95": [-0.004, 0.019],
    "offload_rate": 0.64,
    "cost_savings_pct": 0.57,
    "ece": 0.018
  }
}
```

- **`cost_savings_pct`:** how much less you'll spend compared to sending every request to your fallback model while staying within `max_quality_drop`.
- **`quality_drop` and `quality_drop_ci95`:** the estimated quality difference vs. your fallback model, plus a low-to-high range showing how sure we are. Look at the high end of that range — if it's larger than the drop you're okay with, add more examples to your dataset before shipping.
- **`ece`:** how closely the router's predicted success rates match what actually happened on held-out examples (aim for under `0.05`).

## Deploy the router

Deploy your trained [`Artifact`](/docs/training/artifacts/) to an [`Endpoint`](/docs/training/endpoints/) in one line (`run.deploy(canary=0.10)`), or configure your fallback model and safety threshold explicitly:

<DocsCodeTabs>
  <DocsCodeTab label="Python">

```python
from grad import Grad, strategies

client = Grad()
capture = client.datasets.get("support-traces")

router = client.endpoints.create(
    slug="support-router",
    artifact=run.artifact,
    capture_dataset=capture,
    strategy=strategies.SLALagrangian(
        fallback="{{OPUS_MODEL}}",
        max_quality_drop=0.02,
        hard_stop_drop=0.05,
    ),
)

decision = router.route(messages=messages, tools=tools)
reply = call_your_llm(decision.model, messages, tools)

decision.record_feedback(
    score=1.0 if ticket_resolved else 0.0,
)
```

  </DocsCodeTab>
  <DocsCodeTab label="TypeScript">

```ts
import { Grad, strategies } from "@gradiated/grad";

const grad = new Grad();
const capture = await grad.datasets.get("support-traces");

const router = await grad.endpoints.create({
  slug: "support-router",
  artifact: run.artifact,
  captureDataset: capture,
  strategy: strategies.slaLagrangian({
    fallback: "{{OPUS_MODEL}}",
    maxQualityDrop: 0.02,
    hardStopDrop: 0.05,
  }),
});

const decision = await router.route({ messages, tools });
const reply = await callYourLLM(decision.model, messages, tools);

await decision.recordFeedback({
  score: ticketResolved ? 1.0 : 0.0,
});
```

As feedback comes in, the endpoint keeps live quality within `max_quality_drop` and automatically routes all traffic back to your `fallback` model if quality ever drops past `hard_stop_drop`.

If you already call models through Gradiated with the [OpenAI SDK](/docs/openai-sdk/) or [Anthropic SDK](/docs/anthropic-sdk/), you can skip `router.route(...)` and pass `"model": "<org>/support-router"` directly to your chat completion call.
