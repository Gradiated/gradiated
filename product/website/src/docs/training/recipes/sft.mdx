# Supervised fine-tuning (SFT)

<DocsLead>Fine-tune an open model on examples of the exact outputs you want.</DocsLead>

Use **`SFTRecipe`** when you have good examples of what the model should produce (code edits, structured JSON, SQL queries, or a specific style). Once it reliably follows your format, you can run [Preference tuning (DPO)](/docs/training/recipes/dpo/) or [RL for agents](/docs/training/recipes/rl-agents/) on top of the saved [`Artifact`](/docs/training/artifacts/) to improve it further.

## What data you need

- **Minimum volume:** 300–1,000 clean examples for focused tasks; 2,000+ for broader ones.
- **Quality beats volume:** don't train on raw, unfiltered logs. Score your dataset with a [`Judge`](/docs/training/rubrics/) and keep only high-scoring answers (or filter on an existing score like `tests_passed` if you already log one).
- **Format:** plain chat records, the same JSONL you'd send to OpenAI fine-tuning. The final assistant turn is what the model learns to write. `session_id` is optional; add it when several records come from one conversation so they stay in the same split. Imported production logs work too (see [Trajectories](/docs/training/trajectories/)).

```json
{
  "messages": [
    { "role": "system", "content": "Apply the edit snippet to the original file. Return only the merged file." },
    { "role": "user", "content": "<original>...</original>\n<edit>...</edit>" },
    { "role": "assistant", "content": "export const retry = ..." }
  ]
}
```

## Try it on a public dataset

This runs as pasted. It imports 2,000 conversations from Hugging Face and trains with the defaults:

<DocsCodeTabs action={<DocsApiKeyAction />}>
  <DocsCodeTab label="Python">

```python
from grad import Grad
from grad.recipes import SFTRecipe

client = Grad()
chats = client.datasets.from_hf(
    "HuggingFaceH4/ultrachat_200k",
    split="train_sft",
    messages="messages",
    limit=2000,
)

run = client.runs.create(
    dataset=chats,
    name="ultrachat-sft",
    recipe=SFTRecipe(model="qwen/qwen3-8b"),
).wait()
print(run.artifact.id)
```

## Train on your production logs

Score your `Dataset` once with a [`Judge`](/docs/training/rubrics/) to keep only good examples, then train a LoRA adapter. The held-out eval split is grouped by `session_id` by default, so multi-turn conversations never leak into eval:

<DocsCodeTabs action={<DocsApiKeyAction />}>
  <DocsCodeTab label="Python">

```python
from grad import Grad, Judge
from grad.recipes import SFTRecipe

client = Grad()
dataset = client.datasets.get("diff-merge-prod")  # pushed or imported earlier

# Score logs once with a Judge and keep only high-quality examples
judge = Judge(
    name="clean_merge",
    model="{{SONNET_MODEL}}",
    prompt="Did the assistant apply the edit accurately without breaking surrounding code?",
)
# Field filters run server-side, with no download
clean_dataset = dataset.score(judge).wait().filter(scores={"clean_merge": ">=0.8"})

sft = client.runs.create(
    dataset=clean_dataset,
    name="fast-diff-merge",
    recipe=SFTRecipe(model="qwen/qwen3-8b"),
).wait(
    on_metric=lambda m: print(f"step={m.step} loss={m.loss:.4f}"),
)

print(sft.artifact.id)
```

  </DocsCodeTab>
  <DocsCodeTab label="TypeScript">

```ts
import { Grad, Judge, recipes } from "@gradiated/grad";

const grad = new Grad();
const dataset = await grad.datasets.get("diff-merge-prod");

const judge = new Judge({
  name: "clean_merge",
  model: "{{SONNET_MODEL}}",
  prompt: "Did the assistant apply the edit accurately without breaking surrounding code?",
});
const cleanDataset = (await dataset.score(judge).wait()).filter({
  scores: { clean_merge: ">=0.8" },
});

const sft = await grad.runs
  .create({
    dataset: cleanDataset,
    name: "fast-diff-merge",
    recipe: recipes.sft({ model: "qwen/qwen3-8b" }),
  })
  .wait();

console.log(sft.artifact.id);
```

If your logs already include a deterministic score (like `tests_passed` from CI), skip `dataset.score(judge)` and filter directly: `dataset.filter(scores={"tests_passed": "==1.0"})`. A Python function works too (`dataset.filter(lambda t: ...)`); it runs on your machine once and saves the matching IDs as a view (see [where your code runs](/docs/training/recipes/#where-your-code-runs)).

### When to use SFT vs. DPO vs. distillation

- **Use SFT (`SFTRecipe`)** when you have verified examples of the exact outputs you want (or high-scoring production answers filtered with a `Judge`).
- **Follow with [DPO (`DPORecipe`)](/docs/training/recipes/dpo/)** when the model already follows your format but keeps making specific mistakes you can contrast as `(chosen, rejected)` pairs.
- **Use [Distillation (`DistillRecipe`)](/docs/training/recipes/distillation/)** when you don't have gold answers yet, just prompts and a larger teacher model you want a small model to imitate.

### Parameters you might change

- **`adapter`:** LoRA (`rank=32`) by default. For large datasets (50,000+ records), `adapters.LoRA(rank=64)` or `128` can help.
- **`train_on`:** trains only the final assistant turn by default. Use `train_on="all_assistant"` for multi-turn agent traces.
- **`epochs`:** one pass by default. The dry run suggests a second epoch when a small dataset gives too few training steps.

Every other setting has a default; see the [training parameters reference](/docs/reference/training-parameters/#sftrecipe). To see the exact tokens that get trained, run `grad render <dataset> --model qwen/qwen3-8b` (see [chat templates](/docs/training/tuning-troubleshooting/#chat-templates-and-loss-masks)).

## Deploy and call your model

Host the trained [`Artifact`](/docs/training/artifacts/) on Gradiated Cloud with `sft.deploy()` (or download the LoRA weights to run on your own vLLM / SGLang server; see [Deploying](/docs/training/deploying/)).

Call it through the standard [OpenAI SDK](/docs/openai-sdk/) or [Anthropic SDK](/docs/anthropic-sdk/). For structured JSON, SQL, or code edits, you can validate the output in a few lines of app code and retry on a larger model if syntax fails:

<DocsCodeTabs>
  <DocsCodeTab label="Python">

```python
import os
from openai import OpenAI
from grad import Grad, validators

sft.deploy()

messages = [
    {"role": "system", "content": "Apply the edit snippet to the original file. Return only the merged file."},
    {"role": "user", "content": "<original>export const retry = 1</original>\n<edit>export const retry = 3</edit>"},
]

oai = OpenAI(
    base_url="https://api.gradiated.com/v1",
    api_key=os.environ["GRADIATED_API_KEY"],
)
check_ts = validators.TypeScriptAST()

res = oai.chat.completions.create(
    model="your-org/fast-diff-merge",
    messages=messages,
)
code = res.choices[0].message.content

# Fall back in your own code if the fine-tuned model produces invalid syntax
if not check_ts(code):
    res = oai.chat.completions.create(model="qwen/qwen3-32b", messages=messages)
    code = res.choices[0].message.content

# Later, once you know the outcome, log it (and any human fix) for your next run
tests_passed = check_ts(code)  # or your CI result
human_fix = None               # or the corrected file a developer committed
Grad().feedback.record(
    inference_id=res.id,
    score=1.0 if tests_passed else 0.0,
    expected_output={"content": human_fix} if human_fix else None,
)
```

  </DocsCodeTab>
  <DocsCodeTab label="TypeScript">

```ts
import OpenAI from "openai";
import { Grad, validators } from "@gradiated/grad";

await sft.deploy();

const messages = [
  { role: "system" as const, content: "Apply the edit snippet to the original file. Return only the merged file." },
  { role: "user" as const, content: "<original>export const retry = 1</original>\n<edit>export const retry = 3</edit>" },
];

const oai = new OpenAI({
  baseURL: "https://api.gradiated.com/v1",
  apiKey: process.env.GRADIATED_API_KEY,
});
const checkTs = validators.typeScriptAST();

let res = await oai.chat.completions.create({
  model: "your-org/fast-diff-merge",
  messages,
});
let code = res.choices[0].message.content ?? "";

// Fall back in your own code if the fine-tuned model produces invalid syntax
if (!checkTs(code)) {
  res = await oai.chat.completions.create({ model: "qwen/qwen3-32b", messages });
  code = res.choices[0].message.content ?? "";
}

const testsPassed = checkTs(code); // or your CI result
const humanFix: string | null = null; // or the corrected file a developer committed
await new Grad().feedback.record({
  inferenceId: res.id,
  score: testsPassed ? 1.0 : 0.0,
  expectedOutput: humanFix ? { content: humanFix } : undefined,
});
```

<DocsCallout label="Turn production misses into your next dataset" tone="tip">
When a developer fixes a bad answer or your syntax check catches invalid JSON or code, calling `feedback.record(..., expected_output=...)` saves both the failed attempt and the fix on the same trajectory, giving you ready-to-use data for your next SFT or [DPO](/docs/training/recipes/dpo/) run.
</DocsCallout>
