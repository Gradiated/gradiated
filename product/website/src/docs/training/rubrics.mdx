# Rubrics

<DocsLead>
  Score model outputs with Python checks, built-in validators, or an LLM judge.
</DocsLead>

A **`Rubric`** combines one or more weighted checks (a `Judge`, a `Scorer` or a built-in validator) into an overall score, the weighted mean of its items, and keeps each check's score by name. You can use it in two places:

- **Evals:** pass it as `rubric=` to [`client.evals.create`](/docs/training/evaluations/) to score each model's answers on a dataset. A single `Judge`, `Scorer`, validator or plain function works too.
- **Router training:** pass a `Judge` or a `Rubric` of judges and validators as `rubric=` to [`RouterRecipe`](/docs/training/recipes/router/), or the name of a score already on your records (`rubric="task_success"`).

## Building a `Rubric`

Mix fast code checks (validators, exact matches, length checks) with a **`Judge`** so obvious errors are caught cheaply and the judge only grades nuance:

```python
from grad import Judge, Rubric, Scorer, validators

rubric = Rubric([
    Scorer("valid_json", weight=0.3, fn=validators.JSON()),
    Judge(
        name="accurate_extraction",
        model="{{SONNET_MODEL}}",
        prompt="Does the JSON capture every field the user asked for, without invented values?",
        weight=0.7,
    ),
])
```

## Types of scorers

Pick the class that matches how you grade an answer:

| Class                | Signature                                | When to use it                                                                                                                                                                                                                                                                                                    |
| -------------------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`Scorer`**         | `Scorer(name, fn=..., weight=1.0)`       | A built-in validator (`fn=validators.JSON()`), which runs on the server, or your own Python function `fn(traj) -> float`, which runs in your process. Return a score in `[0, 1]` (a bool counts as `1.0`/`0.0`).                                                                                                  |
| **`Judge`**          | `Judge(model, prompt=..., name="judge")` | Grade with a model id (such as `"{{SONNET_MODEL}}"`) or a trained `Artifact`. The judge sees the conversation, the answer and any reference answer, and replies with a score in `[0, 1]`. `model` is required, with no default that could change under you, and each eval result records the judge model it used. |
| **`StatefulScorer`** | `(traj: Trajectory, handle: H) -> float` | Checks live state inside an [`Environment`](/docs/training/environments/), which is coming soon.                                                                                                                                                                                                               |

The built-in validators run on the server and score the trimmed output `1.0` or `0.0`:

- **`validators.JSON()`:** the output parses as JSON.
- **`validators.NonEmpty()`:** the output isn't empty.
- **`validators.ExactMatch()`:** the output equals the record's `expected_output`.
- **`validators.Regex(pattern, flags="")`:** the pattern matches the output. Patterns use JavaScript syntax, up to 256 characters, with flags from `imsu`.

Put one in a `Rubric` directly (`Rubric([validators.JSON()])`) or call it locally to test it: `validators.JSON()('{"ok": true}')` returns `1.0`. There are no built-in SQL, TypeScript, numeric or JSON Schema validators; write those checks as a Python `Scorer`.

## Scoring a `Dataset` with a `Judge`

Scoring stored logs in place (`dataset.score(...)`) is not available yet. To grade a model's answers on a dataset, run an eval with the judge:

```python
from grad import Grad, Judge

client = Grad()

judge = Judge(
    name="resolved",
    model="{{SONNET_MODEL}}",
    prompt="Did the assistant resolve the user's request accurately without policy errors?",
)
ev = client.evals.create(models=["qwen/qwen3-8b"], dataset="support-prod", rubric=judge).wait()

print(ev.summary_table())
```

## Where Python scorers run

Built-in validators and every `Judge` run on Gradiated's servers. Your own Python functions run in your Python process (`runtime="local"`, the default). The eval waits in `awaiting_scores` while `ev.wait()` pulls the model outputs, calls your function and posts the scores, so keep the process running until the eval completes. If no SDK posts scores for 24 hours, the eval fails with an error naming the missing scorers. `traj.text` is the answer; `traj.metadata` and `traj.expected_output` come from the record:

```python
from grad import Scorer

def math_answer(traj) -> float:
    import sympy
    expected = sympy.sympify(traj.metadata["answer"])
    got = sympy.sympify(traj.text.strip())
    return 1.0 if sympy.simplify(got - expected) == 0 else 0.0

answer_check = Scorer("answer", fn=math_answer, requirements=["sympy==1.14.0"])
```

Before any model is called, `evals.create` checks that the declared `requirements` are installed and runs each function once on a sample record, so a broken scorer fails before you spend anything.

Python scorers in training recipes (`RouterRecipe(rubric=Scorer(...))`) run in a managed sandbox, which is coming soon; today the recipe rejects them. Compute the score yourself, store it in each record's `scores`, and pass its name instead. See [Where your code runs](/docs/training/recipes/#where-your-code-runs).

## Grading live state inside an `Environment`

`StatefulScorer(name, fn=f(traj, handle))` checks what an agent actually changed, such as a row inserted in Postgres or a test suite passing in a container. It runs inside an [`Environment`](/docs/training/environments/) rubric, which is coming soon; eval and training rubrics can't carry one.
