# Rubrics

<DocsLead>Score model outputs and datasets with Python checks, validators, or an LLM judge.</DocsLead>

A **`Rubric`** combines one or more weighted **`Scorer`**s into an overall score while saving each individual check in [`trajectory.scores`](/docs/training/trajectories/). You can reuse the same `Rubric` or `Judge` in three places:

- **Cleaning datasets:** score old logs once with [`dataset.score(rubric)`](/docs/training/trajectories/), then filter on the scores.
- **Managed RL:** pass `rubric=` directly to [`GRPORecipe`](/docs/training/recipes/rl-agents/).
- **Stateful environments:** attach a `Rubric` to an [`Environment`](/docs/training/environments/) so checks can inspect your database, API, or container before it shuts down.

## Building a `Rubric`

Mix fast code checks (syntax validators, unit tests, length checks) with a **`Judge`** so obvious errors are caught immediately and the model judge only grades nuance:

```python
from grad import Judge, Rubric, Scorer, validators

rubric = Rubric([
    Scorer("valid_sql", weight=0.3, fn=validators.SQL()),
    Judge(
        name="accurate_query",
        model="{{SONNET_MODEL}}",
        prompt="Verify the SQL answers the user's question accurately without hallucinated columns.",
        weight=0.7,
    ),
])
```

## Types of scorers

Pick the scorer class that matches how you grade an answer:

| Class | Signature | When to use it |
| --- | --- | --- |
| **`Scorer`** | `(traj: Trajectory) -> float` | Fast code checks (`validators.SQL()`, `validators.TypeScriptAST()`, `validators.JSONSchema(...)`), exact matches, or your own Python function. |
| **`Judge(Scorer)`** | `Judge(name, model, prompt=...)` | Grade with a frontier `Model` (`"{{SONNET_MODEL}}"`) **or** a fine-tuned [reward model](/docs/training/recipes/reward-models/) `Artifact` (no prompt needed for a reward model). |
| **`StatefulScorer(Scorer)`** | `(traj: Trajectory, handle: H) -> float` | Checks that query live Postgres rows, Redis keys, HTTP endpoints, or container files inside an [`Environment`](/docs/training/environments/) before cleanup. |
| **`GroupScorer`** | `(group: list[Trajectory]) -> list[float]` | Compare multiple candidate answers for the same prompt side by side (for example, **`PairwiseJudge(GroupScorer)`**). |

To reuse a score already stored on your imported logs, pass `Scorer.from_score("task_success", weight=1.0)`.

## Scoring a `Dataset` with a `Judge`

`dataset.score(judge)` grades logs in parallel on the server and saves the results to `trajectory.scores`. Already-scored rows are skipped automatically, so you can change filter thresholds or reuse scores across [recipes](/docs/training/recipes/) without paying again:

```python
from grad import Grad, Judge

client = Grad()
dataset = client.datasets.get("support-prod")

judge = Judge(
    name="resolved",
    model="{{SONNET_MODEL}}",
    prompt="Did the assistant resolve the user's request accurately without policy errors?",
)
scored = dataset.score(judge).wait()
good = scored.filter(lambda t: t.scores["resolved"] >= 0.8)
```

<DocsCallout label="When to train a reward model instead" tone="tip">
A frontier or open model `Judge` with a clear rubric is the right default for most teams. If you need to strongly encode custom preferences from examples or score outputs in milliseconds, train a dedicated verifier with [`RewardModelRecipe`](/docs/training/recipes/reward-models/) and pass that [`Artifact`](/docs/training/artifacts/) straight into `Judge(name="resolved", model=verifier_artifact)`.
</DocsCallout>

## Grading live state inside an `Environment`

When you need to check what the agent actually changed (for example, whether a row was inserted in Postgres or a test suite passes in a container), use `StatefulScorer`:

```python
from grad import Rubric, Scorer, StatefulScorer

def passes_unit_tests(traj, handle) -> float:
    res = handle.exec("pytest -q tests/target_test.py")
    return 1.0 if res.returncode == 0 else 0.0

def concise_patch(traj) -> float:
    return 1.0 if len(traj.token_ids) < 1024 else 0.5

rubric = Rubric([
    StatefulScorer("tests", weight=0.8, fn=passes_unit_tests),
    Scorer("concise", weight=0.2, fn=concise_patch),
])
```

See [Environments](/docs/training/environments/) for how `evaluate(handle, trajectory)` runs `StatefulScorer` terms before `teardown()`.
