# Building an environment from traces

<DocsLead>Turn production traces into a verifiable RL environment — starting from simple prompt-and-rubric tasks, upgrading to mock tool-replay sandboxes, or synthesizing Harbor container benchmarks with automated fail-to-pass verification.</DocsLead>

Most teams start with thousands of logged production traces in a [`Dataset`](/docs/training/trajectories/), not a hand-built RL simulator. You do not need to build a full container benchmark on day one: progress through three levels of fidelity using the same [`Task`, `Environment`, and `Rubric`](/docs/training/environments/) primitives.

| Level | Best for | Setup effort | What runs during rollouts |
| --- | --- | --- | --- |
| **1. Trace → `Task` + `Rubric`** | SQL, diff-merge, JSON extraction, support replies, single-turn tool selection | Minutes | Prompt + tools from the trace; graded by `validators.*`, unit tests, or a `Judge`. |
| **2. Trace → Mock / Replay Tool Env** | Multi-turn tool-calling agents (`get_order`, `search_kb`, `issue_refund`) | Hours | Local in-memory / SQLite state seeded from trace tool outputs; write tools mutate local state safely with zero prod side effects. |
| **3. Trace → Harbor Sandbox** | Coding agents, CLI/DevOps debugging, full-stack web apps | 1–2 days | Standard Harbor container tasks (`Dockerfile` + `tests/test.sh` + `solution/solve.sh`) validated with fail-to-pass oracle checks. |

## Step 0: Mine high-signal traces first

Training RL on traces that the base model already solves 100% of the time (or can never solve) wastes tokens on zero-variance groups. Before constructing tasks, score your dataset with a `Judge` or existing outcome scores and focus on **borderline failures, escalations, and human-corrected sessions**:

```python
from grad import Grad, Judge, Model

client = Grad()
dataset = client.datasets.get("support-prod")

judge = Judge(
    name="resolved",
    model=Model("claude-sonnet-4-6"),
    prompt="Did the assistant resolve the user's request accurately without policy errors?",
)
scored = dataset.score(judge).wait()

# Focus on failures or sessions where a human stepped in to fix the output
hard_traces = scored.filter(
    lambda t: t.scores["resolved"] < 0.8 or t.expected_output is not None
)
print(f"Selected {hard_traces.count()} candidate traces for environment tasks")
```

## Level 1: Trace to `Task` + `Rubric` (single-turn)

When the agent does not need multi-turn external state, convert curated traces directly into typed `Task`s with `Task.from_trajectory(t)`. Each `Task` preserves `input.messages`, `input.tools`, `expected_output`, and `metadata`, ready for `GRPORecipe` or a custom loop:

```python
from grad import Grad, Judge, Model, Rubric, Scorer, Task, validators

sql_valid = validators.SQL()

def valid_sql_syntax(traj) -> float:
    return 1.0 if sql_valid(traj.text) else 0.0

rubric = Rubric([
    Scorer("sql_syntax", weight=0.3, fn=valid_sql_syntax),
    Judge(
        name="matches_intent",
        model=Model("claude-sonnet-4-6"),
        prompt="Compare the generated SQL against expected_output and verify it returns the exact requested result.",
        weight=0.7,
    ),
])

tasks = [Task.from_trajectory(t) for t in hard_traces]
```

If you already have a database fixture or unit tests that can execute the generated SQL or code patch, run them deterministically inside a `Scorer` and reserve `Judge` only for subjective quality checks.

## Level 2: Trace to Mock / Replay Tool Environment (multi-turn)

Multi-turn production traces already contain the tool schemas, the read-only tool calls the agent made (`get_order`, `lookup_policy`), the exact payloads returned by your backend, and the final resolution. You can turn each trace into an isolated local sandbox so RL rollouts never touch production APIs:

1. **Extract seed state from the trace:** Parse read-tool results from each trace into `task.seed` (for example, the order row, customer record, and KB snippets fetched during that session).
2. **Hydrate a local store in `setup()`:** Populate an in-memory dict or SQLite database per rollout from `task.seed`.
3. **Replay reads, execute writes locally in `step()`:** Read tools query the local store (with an optional fallback simulator `Model` if the policy explores an off-trace query); write tools (`issue_refund`, `update_ticket`) mutate the rollout's local store.
4. **Grade final state in `evaluate()`:** Assert the expected state mutations with a `StatefulScorer` and grade conversation quality with a `Judge`.

```python
import json
from dataclasses import dataclass, field
from grad import Environment, Judge, Model, Observation, Rubric, StatefulScorer, Task

@dataclass
class MockStore:
    orders: dict[str, dict]
    refunds: list[dict] = field(default_factory=list)

class TraceReplayEnv(Environment[MockStore]):
    def setup(self, task: Task, rollout_id: str) -> MockStore:
        # Deep-copy trace-extracted fixtures so parallel rollouts never share mutable state
        return MockStore(orders=dict(task.seed["orders"]))

    def step(self, handle: MockStore, action) -> Observation:
        call = parse_tool_call(action.text)
        if call is None:
            return Observation(done=True)

        if call.name == "get_order":
            order = handle.orders.get(call.args["order_id"], {"error": "not_found"})
            return Observation(text=json.dumps(order), done=False)

        if call.name == "issue_refund":
            handle.refunds.append(call.args)
            return Observation(text='{"status": "refunded"}', done=False)

        return Observation(text=f'{{"error": "unknown tool {call.name}"}}', done=False)

    def evaluate(self, handle: MockStore, trajectory) -> dict[str, float]:
        self.rubric.score(trajectory, state=handle)
        return trajectory.scores

    def teardown(self, handle: MockStore) -> None:
        handle.refunds.clear()

def correct_refund(traj, store: MockStore) -> float:
    expected = traj.metadata.get("expected_refund")
    return 1.0 if expected in store.refunds else 0.0

rubric = Rubric([
    StatefulScorer("refund_state", weight=0.7, fn=correct_refund),
    Judge(
        name="policy_compliance",
        model=Model("claude-sonnet-4-6"),
        prompt="Verify the assistant explained the refund policy clearly and accurately.",
        weight=0.3,
    ),
])

env = TraceReplayEnv(rubric=rubric)
tasks = [extract_replay_task(t) for t in hard_traces]
```

<DocsCallout label="Handling off-trace tool calls" tone="tip">
During RL exploration, the policy will inevitably call tools with arguments that did not appear in the original trace. Handle those cleanly — either return realistic `"not_found"` responses from your local SQLite seed or route unseen read queries to a small deterministic simulator `Model` — rather than crashing the rollout.
</DocsCallout>

## Level 3: Trace to Harbor Sandbox Synthesis (coding, CLI, and full-stack apps)

For coding agents, DevOps debugging, or full-stack applications where real execution matters (compilers, package managers, Postgres migrations, browser checks), synthesize standard **Harbor** task directories from your traces so every task is reproducible, portable, and runnable with `environments.Harbor`.

### Mapping trace fields to a Harbor task directory

```text
harbor-tasks/<trace_id>/
├── task.toml               # timeouts, CPU/memory limits, trace_id metadata
├── instruction.md          # initial user prompt / issue description from input.messages
├── environment/
│   └── Dockerfile          # pinned pre-fix repo commit SHA / base image from metadata
├── solution/
│   └── solve.sh            # gold fix diff from expected_output (or merged PR)
└── tests/
    └── test.sh             # regression test from the PR or synthesized state check
```

### The Fail-to-Pass quality gate

Synthetic tasks built from traces often have hidden flaws (the test already passes before any fix, the pinned image fails to build, or the oracle patch does not pass the test). Always run a two-step **fail-to-pass gate** before letting a synthesized task into RL training:

1. **Initial state must fail (`reward == 0.0`):** Run `tests/test.sh` immediately after `setup()` with no agent actions. Drop any task that already passes.
2. **Oracle solution must pass (`reward == 1.0`):** Run `solution/solve.sh` and then `tests/test.sh` via `env.verify_oracles(...)`. Drop any task that fails or times out.

```python
import grad
from grad import Grad, Model, adapters, advantages, environments, losses, optim

# 1. Load synthesized Harbor tasks and keep only verified fail-to-pass tasks
env = environments.Harbor()
raw_tasks = environments.Harbor.load_tasks("./harbor-tasks/")
verified_tasks = env.verify_oracles(raw_tasks, require_initial_fail=True)
print(f"Kept {len(verified_tasks)}/{len(raw_tasks)} verified tasks")

# 2. Train directly with GRPO on the verified Harbor suite
client = Grad()
with client.trainers.create(
    model=Model("Qwen/Qwen3-8B"),
    adapter=adapters.LoRA(rank=32, merge_on_export=True),
) as trainer:
    for batch in chunked(verified_tasks, size=8):
        groups = env.rollout_groups(
            artifact=trainer.snapshot(),
            tasks=batch,
            group_size=8,
            max_turns=12,
            max_concurrency=8,
            timeout_s=180,
        )
        batch = grad.with_advantages(groups, advantage=advantages.GroupStd(), skip_zero_var=True)
        fb = trainer.forward_backward(batch, loss=losses.GRPO(clip_low=0.2, clip_high=0.28))
        opt = trainer.optim_step(optim.AdamW(lr=2e-5, grad_clip=1.0))
        fb.result()
        opt.result()

    artifact = trainer.export(name="code-agent-harbor")
```

## Pre-training checklist before launching RL

Run a quick 8–16 task smoke pass against your starting model before scaling up:

- **Check zero-variance rate:** If >70% of prompt groups get all `0.0` or all `1.0`, add partial-credit rubric terms or adjust your trace difficulty filter in Step 0.
- **Keep test suites isolated:** Never bake `tests/` into the agent's container image; `environments.Harbor` copies `tests/` in only during `evaluate()`.
- **Verify `loss_mask`:** Confirm tool and shell observations have `loss_mask = 0.0` (automatic when returning `Observation(text=...)` or using `snap.openai_client()`).
- **Use a warm pool once the loop works:** Cold container startup is fine for validating 20 tasks, then switch to pre-warmed containers or template DB resets before scaling to thousands of rollouts.
