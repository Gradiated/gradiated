# Trajectories and data

<DocsLead>Every training run reads from a dataset of trajectories: production traces, labeled examples, or multi-turn rollouts stored in one model-agnostic schema.</DocsLead>

Populate a dataset in any of four ways:

1. **Automatic capture** from Gradiated inference or any deployed [Endpoint](/docs/training/endpoints/).
2. **Direct SDK push** from your own database or evaluation scripts.
3. **File import** from Parquet or JSONL exports.
4. **Scheduled pull sync** from your LLM observability provider.

## Push trajectories from code

If your labeled examples or production logs already live in your own database, push them directly into a dataset with `trajectories.push`.

<DocsCodeTabs>
  <DocsCodeTab label="Python">

```python
from grad import Grad

client = Grad()

client.trajectories.push(
    dataset="diff-merge-gold",
    trajectories=[
        {
            "session_id": "pr_481",
            "input": {"messages": [{"role": "user", "content": prompt}]},
            "expected_output": {"content": gold_merged_code},
            "scores": {"tests_passed": 1.0},
        },
    ],
)
```

  </DocsCodeTab>
  <DocsCodeTab label="TypeScript">

```ts
import { Grad } from "@gradiated/grad";

const grad = new Grad();

await grad.trajectories.push({
  dataset: "diff-merge-gold",
  trajectories: [
    {
      sessionId: "pr_481",
      input: { messages: [{ role: "user", content: prompt }] },
      expectedOutput: { content: goldMergedCode },
      scores: { tests_passed: 1.0 },
    },
  ],
});
```

  </DocsCodeTab>
  <DocsCodeTab label="Go">

```go
_ = client.Trajectories.Push(ctx, "diff-merge-gold", []grad.Trajectory{{
	SessionID:      "pr_481",
	Input:          grad.TrajectoryInput{Messages: []grad.Message{{Role: "user", Content: prompt}}},
	ExpectedOutput: map[string]any{"content": goldMergedCode},
	Scores:         map[string]float64{"tests_passed": 1.0},
}})
```

  </DocsCodeTab>
  <DocsCodeTab label="cURL">

```bash
curl https://api.gradiated.com/v1/trajectories \
  -H "Authorization: Bearer $GRADIATED_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "dataset": "diff-merge-gold",
    "trajectories": [{
      "session_id": "pr_481",
      "input": {"messages": [{"role": "user", "content": "..."}]},
      "expected_output": {"content": "..."},
      "scores": {"tests_passed": 1.0}
    }]
  }'
```

</DocsCodeTabs>

## Import from files

Stream Parquet or JSONL exports into a named dataset. Gradiated auto-detects the source schema (`grad.trajectory/1`, OTLP, Langfuse, Braintrust, etc.) and normalizes messages, tool calls, token counts, costs, and evaluation scores — pass `--format` only when you want to override auto-detection.

<DocsCodeTabs>
  <DocsCodeTab label="Python">

```python
from grad import Grad

client = Grad()

job = client.trajectories.import_file(
    "./traces.parquet",
    dataset="support-prod",
).wait()

print(job.imported_count, job.dropped_count, job.detected_scores)
```

  </DocsCodeTab>
  <DocsCodeTab label="TypeScript">

```ts
import { Grad } from "@gradiated/grad";

const grad = new Grad();

const job = await grad.trajectories
  .importFile("./traces.parquet", {
    dataset: "support-prod",
  })
  .wait();

console.log(job.importedCount, job.droppedCount, job.detectedScores);
```

  </DocsCodeTab>
  <DocsCodeTab label="Go">

```go
job, _ := client.Trajectories.ImportFile(ctx, "./traces.parquet", grad.ImportOpts{
	Dataset: "support-prod",
}).Wait(ctx)
fmt.Println(job.ImportedCount, job.DetectedScores)
```

  </DocsCodeTab>
  <DocsCodeTab label="CLI">

```bash
grad import ./traces.parquet --dataset support-prod

# Or pin a specific parser explicitly:
grad import ./traces.parquet --format otel --dataset support-prod --json
```

  </DocsCodeTab>
  <DocsCodeTab label="cURL">

```bash
curl https://api.gradiated.com/v1/trajectories/imports \
  -H "Authorization: Bearer $GRADIATED_API_KEY" \
  -F "dataset=support-prod" \
  -F "file=@./traces.parquet"
```

  </DocsCodeTab>
</DocsCodeTabs>

The import result lists how many trajectories were parsed, how many were dropped, and every `scores` key detected in the file so you can check target coverage before training.

## Sync from observability providers

Register a source to pull new traces and feedback scores incrementally on a cron schedule. Provider credentials stay behind a secret reference and are never written into dataset records or `.grad` artifacts.

<DocsCodeTabs>
  <DocsCodeTab label="Python">

```python
from grad import Grad

client = Grad()

source = client.sources.create(
    provider="langfuse",
    dataset="support-prod",
    config={"host": "https://cloud.langfuse.com"},
    secret_ref="env:LANGFUSE_API_KEY",
    schedule="*/15 * * * *",
)

client.sources.sync(source.id)
```

  </DocsCodeTab>
  <DocsCodeTab label="TypeScript">

```ts
import { Grad } from "@gradiated/grad";

const grad = new Grad();

const source = await grad.sources.create({
  provider: "langfuse",
  dataset: "support-prod",
  config: { host: "https://cloud.langfuse.com" },
  secretRef: "env:LANGFUSE_API_KEY",
  schedule: "*/15 * * * *",
});

await grad.sources.sync(source.id);
```

  </DocsCodeTab>
  <DocsCodeTab label="Go">

```go
source, _ := client.Sources.Create(ctx, grad.SourceParams{
	Provider:  "langfuse",
	Dataset:   "support-prod",
	Config:    map[string]any{"host": "https://cloud.langfuse.com"},
	SecretRef: "env:LANGFUSE_API_KEY",
	Schedule:  "*/15 * * * *",
})
_ = client.Sources.Sync(ctx, source.ID)
```

  </DocsCodeTab>
  <DocsCodeTab label="CLI">

```bash
grad sources add langfuse \
  --dataset support-prod \
  --host https://cloud.langfuse.com \
  --secret-ref env:LANGFUSE_API_KEY \
  --schedule "*/15 * * * *"

grad sources sync src_01J9X
```

  </DocsCodeTab>
</DocsCodeTabs>

### Supported providers

| Provider | `--format` / `provider` | File imports | Incremental sync |
| --- | --- | --- | --- |
| Gradiated Native | `gradiated` | JSONL, `.jsonl.zst` | Automatic / S3 cursor |
| Native schema | `grad_trajectories` | JSONL, Parquet | `trajectories.push()` |
| OpenTelemetry / OpenInference | `otel` | OTLP JSONL, Parquet | OTLP collector |
| PostHog | `posthog` | Batch Parquet, CSV, JSON | HogQL API |
| Langfuse | `langfuse` | S3 Parquet, JSONL, CSV | Traces + Scores API |
| Braintrust | `braintrust` | BTQL JSONL, CSV | BTQL cursor |
| LangSmith | `langsmith` | Bulk Parquet | Runs + Feedback API |
| Arize Phoenix | `phoenix` | Parquet, JSONL | Spans + Annotations API |
| Datadog LLMObs | `datadog` | Span archive | Events Search API |
| W&B Weave | `weave` | Parquet, JSONL | Calls + Feedback API |
| Comet Opik | `opik` | JSON, CSV | Traces API |
| Pydantic Logfire | `logfire` | Arrow, Parquet | SQL Query API |
| Laminar | `laminar` | SQL export | Query API |
| Helicone | `helicone` | JSONL, CSV | Query API |

## Fields recipes use

Managed recipes operate directly on `grad.trajectory/1` records — you do not pre-tokenize datasets or reshape columns per model family. The main fields recipes look for:

- `input.messages`, `input.tools`, `input.media`, and `input.features` hold text, tool schemas, image or audio refs, and tabular features.
- `expected_output` holds gold corrections (a human-edited diff or label) for `sft` and `classifier` runs.
- `scores` and `metrics.cost_usd` provide quality and cost signals for `router` runs, data filters, and rubrics.
- `group_id` and `role` (`chosen`, `rejected`, `anchor`, `positive`, `negative`, `rollout`) keep pairs and rollout groups atomic across splits and microbatches.
- `session_id` splits multi-turn conversations by session so turns never leak into held-out evaluation.

See the [Primitives reference](/docs/reference/primitives/) for the full `grad.trajectory/1` JSON schema and custom-loop helpers (`append_env_tokens()` and `to_datum()`).
