# Adaptive MoE architecture cost proxy

## Question

Can a small, recoverable change to GLM-4.7 Flash's MoE execution materially reduce c16 dollars per output token on the L40S or unlock a cheaper chip?

## Why this is the first architecture lane

The exact model has 47 transformer layers: one dense layer followed by 46 MoE layers. Each MoE layer has 64 routed experts, activates four experts per token, and always executes one shared expert; routed and shared expert width is 1,536 over a 2,048-wide hidden state. The measured current-AWQ c16 endpoint is already 98.36% GPU-utilized, so reducing real per-token expert work may transfer more directly than adding concurrency. Modest post-training or distillation is assumed possible later; full quality certification is deliberately deferred.

## Research scope

Use the official architecture/config, current AWQ checkpoint, retained c16 telemetry, and exact vLLM fused-MoE path. Derive and compare executable cost proxies such as fewer routed experts per token, confidence-adaptive top-k, conditional shared-expert execution, selected layer/expert width reduction, or another closely related mechanism the evidence supports. Preserve request geometry and report when a proxy changes semantics. Measure routing distributions, expert load balance, kernel and serving wall time, memory, power, throughput, and committed-price dollars per token. Relate each candidate to L40S tensor-core, memory-bandwidth, and kernel behavior and state whether it would map differently to A40, H100, or an AMD high-memory part.

Prefer a cheap exact-shape or runtime proxy that can falsify the mechanism quickly. If one candidate has a clear material endpoint path, run it against a contemporaneous c16 control on the proven L40S launcher; do not spend the project on a training pipeline or quality harness. Leave training/recovery and quality as the next-stage decision.

Start by discriminating the two highest-leverage minimal changes—conditional removal of the always-on shared expert and top-3/top-2 routed execution—before widening the search. Treat full-layer removal, MLA-rank changes, and output-head changes as separate portfolio lanes rather than absorbing them here.
