# Research log

## 2026-07-15 — exact residency/PCIe falsifier

- Question: does quality-preserving expert residency/offload unlock a 24–32 GiB low-cost GPU for the fixed GLM-4.7-Flash workload?
- Action: parsed every safetensors header in the cached immutable AWQ revision `ab31d120`; classified exact tensor bytes; ran deterministic c1/c8 capacity and uniform/hot-set PCIe calculations. No provider, checkpoint mutation, routing change, or GPU code was used. The raw machine-readable result is [`RESULT.json`](RESULT.json), generated by [`offload_bound.py`](offload_bound.py).
- Evidence: total 20,166,726,064 bytes = 18.781727 GiB; non-routed state 3.910499 GiB; 47 routed layers × 64 experts = 3,008 experts; each expert 5,308,464 bytes; routed experts 14.871228 GiB. With 4 GiB runtime reserve and 2 KiB/token KV, 24 GiB holds 3,251 experts at c1 / 3,229 at c8 and 32 GiB holds 4,869 / 4,847, so all experts fit. The exact index total matches the parsed headers. Two runs are byte-identical (SHA-256 `78bab8e7...88990fe2`).
- Bound: 188 expert invocations/token × 5,308,464 bytes = 997,991,232 bytes/token on a full miss. At conservative PCIe4x16 24 GB/s, no-overlap decode is 24.05 tok/s; achieving the $0.6365/M rate gates needs 87.48% hit on A40 $0.44/h and 88.75% on RTX A6000 $0.49/h; $0.60/M needs 89.69%. Uniform reuse is one request per expert every 16 tokens on average. An 8,192-token prefill touches all 64 experts/layer and transfers 14.871 GiB from an empty cache.
- Interpretation: offload is not an economic unlock here because exact AWQ residency already fits both target devices under conservative reserves; adding PCIe movement can only reduce attainable throughput. A 90% hot set is borderline, while 95% uses 14.130 GiB and clears the analytical traffic bound, but this is an unmeasured locality assumption and does not create a >=5% cost margin.
- Runtime evidence: current vLLM source exposes generic `cpu_offload_gb`; expert-cache/offload is described in current vLLM RFC/PR issue paths ([#33869](https://github.com/vllm-project/vllm/issues/33869), [#38256](https://github.com/vllm-project/vllm/issues/38256)), not as a GLM-4.7 validated production path. No implementation prototype is admitted.
- Decision/next move: close this mechanism for the campaign. Reopen only after measured target-device peak allocation falsifies the exact fit, then require a matched baseline, measured cache hit above the rate-specific bound, and quality/SLO/cost evidence.

## 2026-07-15 — director-corrected MLA capacity amendment

- Question: does the result survive the pinned vLLM MLA accounting of 54,144 BF16 bytes/token across 47 layers?
- Action: amended, rather than replacing, `RESULT.json` with [`CORRECTED_RESULT.json`](CORRECTED_RESULT.json), using the A40 study's exact source-derived equation: 16-token blocks, 90% allocation ceiling, 150 MiB redundancy, 5.799453 GiB expected non-KV overhead, and 10 GiB conservative non-KV overhead. The deterministic implementation is [`capacity_correction.py`](capacity_correction.py).
- Evidence: c1/c8/c16 KV is 0.465/3.718/7.436 GiB. At 24 GiB, conservative expert cache capacity is 1,431/773/21 slots (47.6%/25.7%/0.7% uniform hit); at 32 GiB it is 2,888/2,230/1,478 slots (96.0%/74.1%/49.1%). Minimum expert bytes absent at 24 GiB/c8 are 1.048 GiB under the hard band and 11.050 GiB under the conservative band; at 32 GiB/c8 the conservative absent set is 3.846 GiB.
- Economic falsifier: full-miss decode traffic remains 997,991,232 bytes/token. Conservative PCIe4x16 24 GB/s no-overlap ceilings are 32.4 tok/s (24 GiB/c8), 93.0 tok/s (32 GiB/c8), and 47.3 tok/s (32 GiB/c16), below the $0.60/M target rates of 203.7 tok/s for A40 $0.44/h, 226.9 for RTX A6000 $0.49/h, and 356.5 for RTX 6000 Ada $0.77/h. Source-expected c8 bands also fail except 32 GiB/c8, where all experts fit; that is not a conservative promotion.
- Interpretation: the first result's 2,048-byte KV envelope was materially wrong and is superseded for capacity decisions. With the corrected MLA geometry, expert offload is required on 24 GiB/c8 and 32 GiB/c8 under conservative runtime overhead, but PCIe traffic rules out the needed economic rates. 32 GiB/c8 only works if the full model fits inside the source-expected band; it does not need offload and offers no offload-specific economic margin.
- Decision/next move: close the branch for this campaign. No prototype is admitted: generic vLLM CPU offload/RFC support is not a validated GLM-4.7 expert-cache implementation, and no conservative >=5% end-to-end economic margin exists. Reopen only if a measured target-device memory band materially undercuts the pinned 10 GiB conservative overhead or a GLM-specific cache implementation is validated.
